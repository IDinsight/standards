# Technical Design

## Context

The catalog is an in-memory list exposed by `src/catalog.js`. Search is a pure
function over that list; the kiosk UI calls it with the current query.

## Decision

Add `src/search.js` exporting `searchBooks(books, query)`. It takes the book
list as an argument so it stays independent of the catalog module and is easy
to exercise with any list.

## Acceptance Coverage

- `AC-001`: substring match of the normalized query against the normalized
  `title`.
- `AC-002`: both query and fields are normalized with `trim()` and
  `toLowerCase()` before comparison.
- `AC-003`: the same substring match against the normalized `author`.
- `AC-004`: matches are sorted by `title` with `localeCompare` and truncated to
  a module constant of 20.

## Interfaces and Contracts

- `searchBooks(books, query)` returns a new array of the matching book objects.
  An empty or whitespace-only query returns an empty array. The input array is
  not modified.

## Technical Acceptance Criteria

- `AC-001`, `AC-003`: a book matches when its title or author contains the
  query.
- `AC-002`: `searchBooks(books, '  KINDRED ')` matches the title `Kindred`.
- `AC-004`: the result length never exceeds 20 and results are in ascending
  title order.

## Build Plan

1. Matching and normalization.
2. Ordering and the result limit.
