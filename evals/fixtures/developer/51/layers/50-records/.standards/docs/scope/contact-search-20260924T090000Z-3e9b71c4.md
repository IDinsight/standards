# Contact Search

## Goal

The contact list has grown past what people scan by eye. API clients and people
using the contacts page need to find contacts by part of their name or email.

## Constraints

- The existing `/contacts` routes and their responses stay unchanged.
- Contacts remain in the existing in-memory store; no new runtime dependencies.

## Non-goals

- Fuzzy matching, ranking, or pagination of results.
- Searching by phone number.

## Work

### 1. Search API

**Intent:** Let API clients find contacts without fetching and filtering the
whole list themselves.

**Done when:**

- `AC-001`: An API client can request contacts matching a search text and receives every contact whose name or email contains that text, ignoring letter case; a request with missing or blank search text is rejected as a client error.

**Depends on:** None

### 2. Search on the contacts page

**Intent:** Let people using the contacts page narrow the list while they type.

**Done when:**

- `AC-002`: The contacts page offers a search box; entering text narrows the displayed list to the matching contacts, and clearing it shows every contact again.

**Depends on:** 1
