## Build Steps

### DEV-001 — Contact search API endpoint

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Expose contact search through the existing handler so API clients can find
contacts by text matched against name or email.

**Affected Area**

`src/search.js` (new matcher) and `src/app.js` (route registration in
`createApp`).

**Expected Outcome**

`GET /contacts/search?q=<text>` returns 200 with a JSON array of every contact
whose name or email contains the trimmed text, ignoring case, in store order.
A missing or blank `q` returns 400 with `{"error":"q is required"}`. The
existing `/contacts` routes behave as before.

**Self-Check**

From the project root:

```sh
npm test
node --input-type=module -e "import { createApp } from './src/app.js'; const handle = createApp(); for (const url of ['/contacts/search?q=ADA', '/contacts/search?q=example.org', '/contacts/search?q=%20', '/contacts/search']) { const r = handle({ method: 'GET', url }); console.log(r.status, r.body); }"
```

Expected: `npm test` stays green; the four requests print 200 with Ada
Lovelace only, 200 with Ada Lovelace and Alan Turing, 400, and 400.

### DEV-002 — Search box on the contacts page

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-002`

**Goal**

Let people filter the contacts page by typing part of a name or email.

**Affected Area**

`public/contacts.html` and `public/contacts.js`.

**Expected Outcome**

A search input sits above the list; typing calls `GET /contacts/search` after
a short pause and re-renders the list with the results; clearing the input
shows the full list again from `GET /contacts`.

**Self-Check**

`npm test` from the project root, then `npm start` and load
`http://localhost:3000/` to type a few queries and clear the box.
