# Low-Stock Report

## Goal

Give the stockroom team a report of the items that need reordering, so they can
see at a glance which stock is at or below the level where it should be
replenished and by how much.

## Constraints

- The report is computed from the existing in-memory inventory; stored item data
  keeps its current shape.
- Existing inventory functions and `stockSummary` keep their current behavior.

## Non-goals

- Placing or tracking purchase orders.
- A command-line or HTTP entry point for the report.
- Changing how reorder levels are set on items.

## Work

### 1. Low-stock report

**Intent:** Let a caller ask the inventory which items need reordering and by how
much.

**Done when:**

- `AC-001`: The report lists every item whose quantity on hand is at or below its
  reorder level, giving its SKU, name, quantity on hand, and reorder level.
- `AC-002`: Items with no reorder level set are not included in the report.
- `AC-003`: The report is ordered by shortfall (reorder level minus quantity on
  hand), largest first, with ties ordered by SKU.

**Depends on:** None
