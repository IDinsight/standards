## Build Steps

### DEV-001 — Select low-stock items and shape report rows

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002`

**Goal**

Add `lowStockReport(inventory)` to `src/report.js`, returning one row per item at
or below a set reorder level.

**Affected Area**

`src/report.js` (MODIFY). Items are read through `listItems` in
`src/inventory.js`, which stays unchanged.

**Expected Outcome**

`lowStockReport` is exported and returns rows
`{ sku, name, quantity, reorderLevel, shortfall }` for items whose numeric
`reorderLevel` is at least their `quantity`, including a `reorderLevel` of `0`.
Items with no reorder level are skipped, and an inventory with no such items
yields `[]`.

**Self-Check**

Planned: `npm test` from the project root to confirm existing inventory and
summary behavior still passes, plus a `node -e` call of `lowStockReport` on a
small inventory with one item at its level, one below, one above, and one without
a level. Not yet run.

### DEV-002 — Order report rows by shortfall

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-003`

**Goal**

Return the report rows ordered by shortfall, largest first, with ties by SKU.

**Affected Area**

`lowStockReport` in `src/report.js`.

**Expected Outcome**

Rows are sorted by `shortfall` descending, then `sku` ascending with
`localeCompare`, independent of the order items were added.

**Self-Check**

Planned: `npm test` from the project root, plus a `node -e` call of
`lowStockReport` on items added out of order with two equal shortfalls. Not yet
run.
