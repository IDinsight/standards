# Technical Design

## Context

`src/inventory.js` keeps items in a `Map` keyed by SKU; each item is
`{ sku, name, quantity, reorderLevel }`, where `reorderLevel` is a number or
`null`. `src/report.js` holds read-only reports over an inventory
(`stockSummary`). Tests use `node:test` under `test/`.

## Decision

Add a pure function `lowStockReport(inventory)` to `src/report.js`, next to
`stockSummary`. It reads items through `listItems` and returns plain row objects.
It does not mutate the inventory and adds no dependencies.

## Acceptance Coverage

- `AC-001`: `lowStockReport` selects items with a numeric `reorderLevel` and
  `quantity <= reorderLevel`, returning rows with `sku`, `name`, `quantity`,
  `reorderLevel`, and `shortfall`.
- `AC-002`: items whose `reorderLevel` is `null` or `undefined` are skipped before
  the comparison.
- `AC-003`: rows are sorted by `shortfall` descending, then by `sku` ascending
  with `localeCompare`.

## Interfaces and Contracts

- `lowStockReport(inventory)` is a named export of `src/report.js` and returns
  `Array<{ sku, name, quantity, reorderLevel, shortfall }>`.
- `shortfall` is `reorderLevel - quantity`; it is `0` for an item exactly at its
  reorder level.
- An empty inventory, or one with no low items, returns `[]`.

## Technical Acceptance Criteria

- `AC-001`: an item whose `quantity` equals its `reorderLevel` is included with
  `shortfall: 0`.
- `AC-002`: a `reorderLevel` of `0` is a set level, not a missing one.
- `AC-003`: ordering does not depend on the order items were added.

## Build Plan

1. MODIFY `src/report.js`: add and export `lowStockReport`.
2. Leave `src/inventory.js` and `stockSummary` unchanged.
