## Build Steps

### DEV-001 — Archive flag and archive route

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Records carry an archived flag, and the API can archive a record.

**Affected Area**

`src/store.js` (field on create, `archive(id)`), `src/handlers.js`
(`archiveRecord`), `src/routes.js` (`POST /records/:id/archive`).

**Expected Outcome**

New records have `archived` set to false. `POST /records/:id/archive` returns
200 with the archived record, or 404 for unknown or malformed ids.
`GET /records/:id` shows the flag.

**Self-Check**

Run `node --test test/records.test.js` from the project root, plus a sanity
run of the archive route for a known and an unknown id.

### DEV-002 — Hide archived records from the default list

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-002`

**Goal**

The default list leaves out archived records unless the caller asks for them.

**Affected Area**

`listRecords` in `src/handlers.js` only. `RecordStore.list()` stays unchanged
per the design.

**Expected Outcome**

`GET /records` omits archived records. With `includeArchived=true` it returns
them too. `q` filtering works in both cases.

**Self-Check**

Run `node --test test/records.test.js` from the project root, plus a sanity
run listing one archived and one active record with and without
`includeArchived=true`, combined with `q`.
