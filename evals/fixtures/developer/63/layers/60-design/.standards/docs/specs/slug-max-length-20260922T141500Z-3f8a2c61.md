# Technical Design

## Context

`slugify` in `src/slug.js` is the package's only export (see
`.standards/CONTEXT.md`). The package has no dependencies and tests use
`node:test`.

## Decision

Add an optional second parameter, an options object with `maxLength`. The slug
is built exactly as today; truncation runs afterwards and only when `maxLength`
is supplied. Validation runs whenever `maxLength` is supplied, even if the slug
already fits, so bad values fail consistently.

## Acceptance Coverage

- `AC-001`: After the existing pipeline, keep the longest prefix that ends at a
  hyphen and fits within `maxLength`; when no hyphen falls inside the limit,
  hard-cut at `maxLength`.
- `AC-002`: With no options argument or no `maxLength`, the existing pipeline's
  result is returned unchanged.
- `AC-003`: A `maxLength` that is not an integer of at least 1 throws
  `RangeError` before any truncation.

## Interfaces and Contracts

- `slugify(text, { maxLength } = {})` returns a string. `maxLength` is an
  optional positive integer counted in characters of the final slug.
- A truncated slug never ends with a hyphen.

## Technical Acceptance Criteria

- `AC-001`: `slugify(t, { maxLength: n }).length <= n` for every input, and the
  result is a prefix of `slugify(t)`.
- `AC-002`: `slugify(t)` is byte-for-byte identical to the previous release.
- `AC-003`: `maxLength` of `0`, a negative number, a non-integer, or a
  non-number throws `RangeError`.
