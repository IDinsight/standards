## Build Steps

### DEV-001 — Accept and validate the maxLength option

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-002, AC-003`

**Goal**

`slugify` accepts an optional options object; a supplied `maxLength` that is not
a positive integer throws `RangeError`, and calls without it behave as before.

**Affected Area**

`src/slug.js`

**Expected Outcome**

`slugify(text)` returns the same slug as before. `slugify(text, { maxLength })`
with `0`, `-1`, `2.5`, or a string throws `RangeError`.

`slugify` with `maxLength` values `0`, `-1`, `2.5`, and `'8'` printed

### DEV-002 — Truncate at the last word boundary

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-001`

**Goal**

When `maxLength` is supplied and the slug is longer, return the longest prefix
ending at a word boundary, or a hard cut when the first word does not fit.

**Affected Area**

`src/slug.js`

**Expected Outcome**

`slugify('Hello brave new world', { maxLength: 11 })` returns `hello-brave`;
`slugify('Supercalifragilistic', { maxLength: 5 })` returns `super`; slugs
already within the limit are returned unchanged and never end with a hyphen.

**Self-Check**

Ran `npm test` in the project root on the same content as DEV-001 with the
truncation added: exit 0, 3 tests passed, 0 failed. A one-off
`node --input-type=module -e` script printed `hello-brave`, `super`,
`hello-world` (limit 40), and `hello` (input `hello-world`, limit 5).
Limitation: the existing suite has no length cases, so truncation was checked
only by these manual calls.
