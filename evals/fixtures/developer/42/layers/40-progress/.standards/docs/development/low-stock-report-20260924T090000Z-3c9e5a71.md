## Build Steps

### DEV-001 — Parse an optional reorder threshold

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002`

**Goal**

Read the optional fourth inventory column as the item's reorder threshold and
expose one shared low-stock predicate.

**Affected Area**

`src/inventory.js` (`parseItem`, new `isLowStock`).

**Expected Outcome**

`parseItem` returns `reorderAt` as a non-negative integer, or `null` when the
column is absent or empty; a non-integer or negative threshold throws an error
whose message starts with `invalid reorder threshold`. `isLowStock(item)` is
true only when `reorderAt` is a number and `quantity <= reorderAt`.
Three-column rows parse as before.

**Self-Check**

- `node --test test/inventory.test.js test/report.test.js` in the project root
  on commit `${COMMIT:Add reorder thresholds and low-stock flags}`, clean
  working tree, Node 22: exit 0; 4 tests, 4 passed, 0 failed. These existing
  tests exercise three-column rows only, so they cover the unchanged parsing
  path, not threshold parsing.
- Targeted sanity check, same root and commit, `node --input-type=module -e`
  importing `src/inventory.js`: `parseItem('A-1, Bolt, 3, 5')` gave
  `reorderAt` 5 and `isLowStock` true; `parseItem('B-2, Nut, 9, 2')` gave
  `isLowStock` false; `parseItem('C-3, Washer, 4')` gave `reorderAt` null and
  `isLowStock` false; `parseItem('C-9, Clip, 2, x')` threw
  `invalid reorder threshold: C-9, Clip, 2, x`. Exit 0.

### DEV-002 — Mark low-stock lines and count them in the summary

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-001, AC-002, AC-003`

**Goal**

Show low-stock items in the report and state how many there are.

**Affected Area**

`src/report.js` (`stockReport`).

**Expected Outcome**

Lines for low-stock items end with two spaces and `LOW`; other lines are
unchanged. The summary line reads `<N> items, <M> low stock`.

**Self-Check**

- Same `node --test test/inventory.test.js test/report.test.js` run as DEV-001
  on commit `${COMMIT:Add reorder thresholds and low-stock flags}`: exit 0,
  4 passed. The existing summary test matches the `2 items` prefix, which the
  new summary keeps.
- Targeted sanity check, same root and commit: `stockReport` over the three
  items `A-1, Bolt, 3, 5`, `B-2, Nut, 9, 2`, and `C-3, Washer, 4` returned the
  lines `A-1  Bolt  3  LOW`, `B-2  Nut  9`, `C-3  Washer  4`, and
  `3 items, 1 low stock`. Exit 0.
- `node src/cli.js data/stock.csv` in the project root, same commit: printed
  the four sample lines unchanged and `4 items, 0 low stock` (the sample file
  has no thresholds). Exit 0.
- Limitation: no automated test covers thresholds, the `LOW` marker, or the
  low-stock count yet.
