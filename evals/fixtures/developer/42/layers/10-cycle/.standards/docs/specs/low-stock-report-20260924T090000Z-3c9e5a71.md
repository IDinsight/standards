# Technical Design

## Context

`src/inventory.js` parses three-column rows into `{ sku, name, quantity }`;
`src/report.js` formats sorted item lines and an item-count summary;
`src/cli.js` wires them to a file. No dependencies; tests use `node:test`.

## Decision

Add an optional fourth column, the reorder threshold, parsed by `parseItem`
into `reorderAt`. A single predicate, `isLowStock`, lives in `src/inventory.js`
so the report and any later consumer share one rule. The report appends a
`LOW` column to low-stock lines and extends the summary with a low-stock count.

## Acceptance Coverage

- `AC-001`: optional fourth column parsed into `reorderAt`; `isLowStock`
  compares quantity with it; `stockReport` appends `LOW` to matching lines.
- `AC-002`: absent or empty column yields `reorderAt: null`, for which
  `isLowStock` is false; three-column parsing is otherwise unchanged.
- `AC-003`: summary line extended with the count of low-stock items.

## Interfaces and Contracts

- Inventory row: `sku, name, quantity[, reorder_at]`. `reorder_at` is a
  non-negative integer; anything else throws an `Error` whose message starts
  with `invalid reorder threshold`.
- `parseItem(row)` returns `{ sku, name, quantity, reorderAt }`, with
  `reorderAt` a number or `null`.
- `isLowStock(item)` is exported from `src/inventory.js`.
- Report item line: `<sku>  <name>  <quantity>`, followed by `  LOW` when low
  stock. Summary line: `<N> items, <M> low stock`.

## Technical Acceptance Criteria

- `AC-001`: an item is low stock when `quantity <= reorderAt` (equality
  included).
- `AC-002`: `reorderAt` of `null` never counts as low stock; rows with three
  columns parse to the same `sku`, `name`, and `quantity` as before.
- `AC-003`: `M` counts exactly the items for which `isLowStock` is true.

## Build Plan

1. Threshold parsing and `isLowStock` in `src/inventory.js`.
2. Report line marker and summary in `src/report.js`.
