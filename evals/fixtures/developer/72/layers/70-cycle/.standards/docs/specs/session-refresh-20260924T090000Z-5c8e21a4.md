# Technical Design

## Context

Staff tools need to renew an expiring access token without a new sign-in
(`.standards/docs/scope/session-refresh-20260924T090000Z-5c8e21a4.md`).
`app/auth/client.py` already exposes `InternalAuthClient.refresh()`, which
posts to the auth service's `/v1/token/refresh` endpoint and returns a
`TokenPair`, raising `AuthRejected` or `AuthUnavailable`. No route calls it
yet. `app/auth/dependencies.py` shows the existing error mapping for
introspection.

## Decision

- Add a `session` router in `app/routes/session.py`
  (`APIRouter(prefix="/session", tags=["session"])`) with `POST /refresh`, and
  register it in `app/main.py` next to the existing routers.
- The route does not require an access token: the refresh token in the request
  body is the credential. It is not protected by `require_user`.
- The handler calls `InternalAuthClient.refresh()` once per request and returns
  the resulting pair. The client needs no changes.
- visits-api keeps no token or session state.

## Acceptance Coverage

- `AC-001`: `POST /session/refresh` accepts `RefreshRequest`; success returns `TokenPairResponse` built from the client's `TokenPair`.
- `AC-002`: `AuthRejected` from the client maps to status 401 with no tokens in the body.
- `AC-003`: `AuthUnavailable` from the client maps to status 503 with no tokens in the body.

## Interfaces and Contracts

- Request body `RefreshRequest` in `app/schemas.py`: `refresh_token: str` with
  `min_length=1`. A missing or empty value gets FastAPI's standard 422.
- Response model `TokenPairResponse` in `app/schemas.py`: `access_token: str`,
  `refresh_token: str`, `expires_in: int` (seconds); status 200.
- Errors use `HTTPException`: `AuthRejected` maps to 401 with detail
  `Refresh token rejected`; `AuthUnavailable` maps to 503 with detail
  `Auth service unavailable`.
- Logging: one INFO line per request through the module logger, with outcome
  `refreshed`, `rejected`, or `unavailable`.

## Data and Control Flow

Client -> `POST /session/refresh` -> request validation ->
`InternalAuthClient.refresh(refresh_token)` -> auth service. The returned pair
is passed through unchanged; nothing is persisted.

## Technical Acceptance Criteria

- `AC-001`: A successful response body contains exactly `access_token`, `refresh_token`, and `expires_in`, equal to the values in the client's `TokenPair`.
- `AC-002`: A rejected refresh produces status 401 and a body without token fields.
- `AC-003`: An unavailable auth service produces status 503 and a body without token fields.

## Build Plan

1. MODIFY `app/schemas.py`: add `RefreshRequest` and `TokenPairResponse`.
2. CREATE `app/routes/session.py`: the refresh route, error mapping, and
   outcome logging.
3. MODIFY `app/main.py`: include the session router.

## Risks and Follow-up

- The route has no rate limiting; the scope leaves it out for now.
