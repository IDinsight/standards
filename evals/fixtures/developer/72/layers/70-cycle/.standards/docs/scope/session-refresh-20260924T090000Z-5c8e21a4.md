# Session Refresh

## Goal

Staff tools send users back to sign-in when their access token expires. Let a
client trade its refresh token for a new token pair through visits-api so a
session can continue without a new sign-in.

## Constraints

- Tokens are issued and revoked only by the internal auth service; visits-api
  does not mint tokens.

## Non-goals

- Storing tokens or sessions in visits-api.
- Rate limiting or lockout on the refresh route.
- Changes to the internal auth service or to the existing visit routes.

## Work

### 1. Token refresh endpoint

**Intent:** Give staff tools one visits-api call that renews an expiring
session through the internal auth service.

**Done when:**

- `AC-001`: A client that sends a valid refresh token to `POST /session/refresh` receives a new access token, a new refresh token, and the access token's lifetime in seconds.
- `AC-002`: When the auth service refuses the refresh token, the endpoint responds with status 401 and returns no tokens.
- `AC-003`: When the auth service cannot be reached or fails, the endpoint responds with status 503 and returns no tokens.

**Depends on:** None
