# Technical Design

## Context

`createCatalog` in `src/catalog.js` normalizes titles (trimmed) and tags
(trimmed, lowercased) and exposes `get`, `all`, and `withTag`. There is no
search today.

## Decision

Add `search(query)` to the object returned by `createCatalog`. Normalize the
query with the same trim-and-lowercase rule used for tags. An item matches when
its lowercased title contains the normalized query, or when one of its tags
equals it. Return matches in catalog insertion order, each item once. A blank
normalized query returns `[]` without scanning.

## Acceptance Coverage

- `AC-001`: case-insensitive containment match against the normalized title in `search`.
- `AC-002`: exact match against normalized tags in `search`, reusing the tag normalization rule.
- `AC-003`: blank-query short circuit, and an empty result when nothing matches.

## Interfaces and Contracts

- `catalog.search(query)` returns an array of items shaped like the result of
  `get`. Non-string input is converted with `String()`.

## Technical Acceptance Criteria

- `AC-002`: tag comparison uses the same normalization as `withTag`, so `search(' INK ')` and `withTag(' INK ')` agree on tag matches.

## Build Plan

1. Add `search` with title and tag matching.
2. Add the blank-query short circuit.
