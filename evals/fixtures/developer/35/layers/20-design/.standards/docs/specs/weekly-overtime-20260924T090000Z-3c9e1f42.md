# Technical Design

## Context

`summarize(entries)` in `src/summary.js` returns `{ totalMinutes, byDay }`.
The scope adds per-ISO-week figures with a fixed 2400-minute threshold.

## Decision

Add a pure helper module for ISO week keys and extend `summarize` with a
`weeks` property. Keep existing properties and their values unchanged so
current callers are unaffected.

## Acceptance Coverage

- `AC-001`: `src/week.js` maps a date to its ISO week key; `summarize` groups minutes by that key and reports `minutes` and `overtimeMinutes` per week.
- `AC-002`: `overtimeMinutes` is `max(0, minutes - 2400)`.
- `AC-003`: `totalMinutes` and `byDay` keep their current computation; `weeks` is purely additive.

## Components

- `src/week.js` — `isoWeekKey(date)` for `YYYY-MM-DD` strings.
- `src/summary.js` — adds weekly aggregation to `summarize`.

## Interfaces and Contracts

- `isoWeekKey(date: string): string` returns `YYYY-Www` (zero-padded week,
  ISO week-numbering year), computed in UTC so local time zones do not shift
  dates.
- `summarize(entries)` returns
  `{ totalMinutes, byDay, weeks }` where `weeks` is
  `Record<string, { minutes: number, overtimeMinutes: number }>` keyed by
  `isoWeekKey`, sorted by key.
- Threshold: module constant `STANDARD_WEEK_MINUTES = 2400` in
  `src/summary.js`.

## Technical Acceptance Criteria

- `AC-001`: Entries on 2026-12-31 and 2027-01-01 fall in the same ISO week
  `2026-W53`; weekly minutes equal the sum of that week's entries.
- `AC-002`: A week totalling exactly 2400 minutes reports `overtimeMinutes: 0`.
- `AC-003`: For any input, `totalMinutes` and `byDay` equal the values the
  current implementation returns.

## Build Plan

1. Add `src/week.js` with `isoWeekKey`.
2. Extend `summarize` with the `weeks` aggregation.

## Risks and Follow-up

- The threshold is fixed; making it configurable is out of scope.
