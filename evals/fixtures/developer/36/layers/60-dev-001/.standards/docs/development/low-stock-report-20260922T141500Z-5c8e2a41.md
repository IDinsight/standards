### DEV-001 — Threshold option parsing

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Replace the ad hoc argument handling with `parseOptions` and support
`--threshold <n>`.

**Affected Area**

`src/options.js` (new), `src/cli.js`.

**Expected Outcome**

`parseOptions` returns `{ file, threshold }` with threshold 5 by default; an
invalid threshold, unknown option, extra argument, or missing file raises
`OptionError`, which the CLI reports on stderr with exit status 2. Runs without
`--threshold` print the same output as before.

**Self-Check**

Run in the project root on the working tree based on
${COMMIT:Record low-stock report scope, design, and plan} with the new
`src/options.js` and the updated `src/cli.js`:

- `node --test test/inventory.test.js`: exit 0, 4 tests passed.
- `node src/cli.js data/sample.csv`: exit 0, same four item lines and
  `total,255` as before the change.
- `node src/cli.js data/sample.csv --threshold 3`: exit 0, same output.
- `node src/cli.js data/sample.csv --threshold x`: exit 2, stderr
  `--threshold expects a non-negative integer, got x`.
- `node src/cli.js`: exit 2, stderr shows the usage line.

Limitation: the threshold value is parsed but not yet used; it takes effect in
DEV-002.

### DEV-002 — Low-stock filter and output

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-002, AC-003`

**Goal**

Add the `--low-stock` flag and print the filtered, sorted report.

**Affected Area**

`src/options.js`, `src/inventory.js` (new `lowStock` function), `src/cli.js`.

**Expected Outcome**

`--low-stock` prints only items with quantity at or below the threshold, sorted
ascending by quantity, without the total line. Runs without the flag are
unchanged.

**Self-Check**

Planned: `node --test test/inventory.test.js` in the project root, plus manual
runs of `node src/cli.js data/sample.csv --low-stock` with and without
`--threshold`, and a run without `--low-stock` compared with the earlier output.
