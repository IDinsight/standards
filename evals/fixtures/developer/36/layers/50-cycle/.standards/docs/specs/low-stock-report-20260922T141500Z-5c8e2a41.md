# Technical Design

## Context

The CLI reads `process.argv` directly in `src/cli.js` and accepts only a file
path. Parsing and totals live in `src/inventory.js`.

## Decision

Move argument handling into a new `src/options.js` module that returns a plain
options object and throws a dedicated `OptionError` for usage problems;
`src/cli.js` maps `OptionError` to stderr plus exit status 2. Filtering is a
pure function in `src/inventory.js` so it can be exercised without the CLI.

## Acceptance Coverage

- `AC-001`: `parseOptions(args)` in `src/options.js`; `threshold` defaults to
  5; values not matching `^\d+$` raise `OptionError` naming `--threshold`.
- `AC-002`: `parseOptions` sets `lowStock: true` for `--low-stock`;
  `lowStock(items, threshold)` in `src/inventory.js` filters `qty <= threshold`
  and sorts ascending by `qty` (stable for ties); `src/cli.js` prints only those
  lines and skips the total line.
- `AC-003`: When `lowStock` is false, `src/cli.js` keeps the existing listing
  and `total,<units>` line.

## Interfaces and Contracts

- `parseOptions(args: string[]) -> { file, threshold, lowStock }`; throws
  `OptionError` (a subclass of `Error`) for a missing file, an unknown option,
  an extra positional argument, or an invalid threshold.
- `lowStock(items, threshold) -> items[]`; does not mutate its input.

## Technical Acceptance Criteria

- `AC-001`: Usage errors exit with status 2 and print one line to stderr.
- `AC-002`: Items with `qty` equal to the threshold are included.

## Build Plan

1. Introduce `src/options.js` with threshold parsing and wire it into the CLI.
2. Add the `--low-stock` flag, the filter, and the report output.
