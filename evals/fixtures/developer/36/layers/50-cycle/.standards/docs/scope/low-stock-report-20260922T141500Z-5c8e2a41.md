# Low-Stock Report

## Goal

Let the workshop see at a glance which items need reordering, using a threshold
they can adjust per run, without changing the existing full listing.

## Constraints

- The existing CLI output and exit behavior stay compatible for runs that do
  not ask for the report.

## Non-goals

- Persisting a threshold between runs.
- Reorder suggestions or supplier data.

## Work

### 1. Configurable threshold

**Intent:** Users choose what counts as low stock for a given run.

**Done when:**

- `AC-001`: The `--threshold <n>` option accepts a non-negative integer, defaults to 5 when omitted, and any other value is rejected with exit status 2 and an error message naming the option.

**Depends on:** None

### 2. Low-stock listing

**Intent:** Show only the items that need attention.

**Done when:**

- `AC-002`: With `--low-stock`, the CLI prints only items whose quantity is at or below the threshold, sorted by ascending quantity, one `sku,name,qty` line per item and no total line.
- `AC-003`: Without `--low-stock`, the CLI output is unchanged.

**Depends on:** 1
