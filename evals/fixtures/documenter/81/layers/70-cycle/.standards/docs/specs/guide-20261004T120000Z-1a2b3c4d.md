# Technical Design

## Context

Documentation cycle for the existing logtrim CLI. The contracts below are taken
from the current source (`src/cli.js`, `src/filter.js`), its tests, and
`examples/sample.log`; see `.standards/CONTEXT.md`. No project references
apply.

## Decision

Document the CLI as it behaves now. No behavior, test, or sample changes are
part of this cycle. Examples use the `logtrim` command name from the package
`bin` entry; `node src/cli.js` is the equivalent from a checkout and is the
form to use when checking example output.

## Acceptance Coverage

- `AC-001`: `parseArgs` in `src/cli.js` accepts `--level <name>` (default
  `info`), `--grep <text>` (default none), `--count` (flag, default off), and
  one positional file (default: standard input). Any other `--` argument is
  rejected.
- `AC-002`: `filterLines` in `src/filter.js` keeps a line when it parses as
  `<time> [<level>] <message>`, its level is at or above `--level` in the order
  debug, info, warn, error, and, with `--grep`, its message contains the text
  ignoring case. Lines that do not parse, or carry another level, are dropped
  silently.
- `AC-003`: Example output is whatever `node src/cli.js <args>` prints from the
  repository root against `examples/sample.log`; `--count` prints a single
  number.

## Interfaces and Contracts

- Exit status: 0 on success; 2 with `logtrim: <message>` on standard error for
  an unknown option, a missing option value, or an unknown level.
- Output: kept lines in input order, each followed by a newline.

## Technical Acceptance Criteria

- `AC-001`: Defaults stated in the guide match the initial values in
  `parseArgs`.
- `AC-003`: Each example's shown output is identical to the command's actual
  output on `examples/sample.log`.
