# logtrim Usage Guide

## Goal

People running logtrim should be able to learn every option and predict its
output from `docs/usage.md` alone. The guide must describe the CLI as it
behaves today.

## Constraints

- Documentation only: the editing boundary is `docs/usage.md`. CLI source,
  tests, `examples/sample.log`, and `README.md` are not changed.
- Documenter choices from the user's request: target FILE `docs/usage.md`,
  GUIDED collaboration (the user applies each edit), user style `concise`.

## Non-goals

- Changing any default, option, or message of the CLI.
- Installation or packaging instructions beyond running the command.
- Rewriting `README.md`.

## Work

### 1. Accurate option reference

**Intent:** Readers choose options from the guide, so it must name every option
and its real default.

**Done when:**

- `AC-001`: `docs/usage.md` lists every option the CLI accepts (`--level`,
  `--grep`, `--count`) and the file argument, each with its current default.
- `AC-002`: `docs/usage.md` states how lines are selected: the level order,
  that `--grep` ignores case, and that lines outside the log format are
  skipped.

**Depends on:** None

### 2. Working examples

**Intent:** Readers copy the examples, so their output must be real.

**Done when:**

- `AC-003`: Every example command in `docs/usage.md`, run against
  `examples/sample.log`, prints exactly the output shown.

**Depends on:** 1
