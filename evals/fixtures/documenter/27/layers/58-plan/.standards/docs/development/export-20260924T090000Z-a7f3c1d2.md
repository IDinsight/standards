## Build Steps

### DEV-001 — CSV serialization with column selection

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Turn a list of records into the CSV text the design defines, for any chosen
columns.

**Affected Area**

New module `src/export.ts` (`DEFAULT_COLUMNS`, `csvCell`, `parseColumns`,
`toCsv`), with unit tests in `test/export.test.ts` as the self-check harness.

**Expected Outcome**

`toCsv(records, columns)` returns a header row of the chosen columns and one
row per record, quoted and terminated as the design's CSV format requires.
`parseColumns` returns trimmed names in order and rejects unknown names and an
empty list with the design's messages.

**Self-Check**

`pnpm --filter export test` in the project root.

### DEV-002 — Export command

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-001`

**Goal**

Give operators the command the design defines.

**Affected Area**

New `scripts/export-records.ts`.

**Expected Outcome**

`node scripts/export-records.ts` accepts `--status`, `--owner`, `--q`,
`--columns`, and `--out`, exports the matching seed records with `toCsv`, and
produces the output, messages, and exit statuses in the design's command
contract.

**Self-Check**

`pnpm --filter export test`; run `node scripts/export-records.ts` with each
option and with an invalid status and column, and inspect standard output,
standard error, the exit status, and the written file.
