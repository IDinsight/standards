# CSV Export of Records

## Goal

Operators of the records admin tool need to take a filtered set of records
into a spreadsheet. A command should write the records matching the filters
the service already offers as CSV that spreadsheet programs read correctly,
even when titles contain commas, quotes, or line breaks, with only the fields
the operator asks for. The usage guide is where operators and the admin tool's
developers learn what the service offers, so it must describe the export as
it actually works.

## Constraints

- The export applies the same `status`, `owner`, and `q` filters, with the same
  validation, as listing records (`GET /records`).
- Listing records keeps its current behavior.
- The usage guide is `docs/guides/usage.md`. It replaces `docs/usage.md`, and
  the separate API reference page `docs/api.md` is retired in favor of it; the
  user is making that move as part of this change.

## Non-goals

- An HTTP export endpoint, scheduled exports, and formats other than CSV.
- Changes to the admin tool's front end.

## Work

### 1. CSV export command

**Intent:** Let operators save exactly the records they filtered, with the
fields they need, in a file spreadsheets open correctly.

**Done when:**

- `AC-001`: An operator can export the records matching the status, owner, and title filters as CSV, choosing which record fields appear as columns and in what order; the CSV has a header row, quotes any field containing a comma, double quote, or line break per RFC 4180 with embedded double quotes doubled, and ends every row with CRLF; an invalid filter value or column name is reported with an error message and a nonzero exit status and produces no CSV.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** Operators and admin-tool developers can learn from the guide how to
run the export without reading the code.

**Done when:**

- `AC-002`: The usage guide accurately describes how to run the CSV export, its options, the CSV it produces, where the output goes, and its error messages and exit statuses.

**Depends on:** 1

## Assumptions

- The export reads the same seeded record data the service starts with; there
  is no other record source in this repository.
