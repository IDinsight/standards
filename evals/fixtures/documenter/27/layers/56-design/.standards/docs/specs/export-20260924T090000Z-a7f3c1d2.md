# Technical Design

## Context

The scope adds a CSV export of filtered records for operators (AC-001) and
requires the usage guide to describe it (AC-002). According to
`.standards/CONTEXT.md`, records live in an in-memory `RecordStore` seeded
from `@records/seed`, `parseFilter` implements the listing filters and their
validation, and nothing in the repository writes files or has a command-line
entry point. Seed titles contain a comma and double quotes.

## Decision

Add a serialization module, `src/export.ts`, and an operator command,
`scripts/export-records.ts`, run with `node`. The command builds a query from
its options, reuses `parseFilter` and `RecordStore.list` over the seed records
so an export contains exactly what `GET /records` lists for the same filters,
and writes the CSV to standard output or to a file. A command rather than an
HTTP route keeps the export out of the request path, as the scope's non-goals
require.

## Acceptance Coverage

- `AC-001`: `src/export.ts` (CSV format, quoting, column selection) and the
  `scripts/export-records.ts` command contract (options, output, errors, exit
  statuses) in Interfaces and Contracts.
- `AC-002`: No architectural impact. Documenter updates the usage guide at
  `docs/guides/usage.md` against the contract below once the implementation
  exists.

## Components

- `src/export.ts` (new): `DEFAULT_COLUMNS`, `csvCell`, `parseColumns`, and
  `toCsv`. It knows nothing about options, files, or processes.
- `scripts/export-records.ts` (new): option parsing, filter and column
  validation, output, and exit statuses.

## Interfaces and Contracts

- `toCsv(records, columns = DEFAULT_COLUMNS)`: CSV text for the records in the
  given order. `DEFAULT_COLUMNS` is `id`, `title`, `owner`, `status`,
  `createdAt`.
- `parseColumns(list)`: splits a comma-separated list, trims names, and returns
  them in the given order; throws `Error('unknown column: <name>')` for a name
  that is not a record field and `Error('no columns given')` for an empty list.
- Command: `node scripts/export-records.ts [--status <active|archived>]
  [--owner <name>] [--q <text>] [--columns <name,...>] [--out <file>]`, run
  from the project root.
  - `--status`, `--owner`, and `--q` have the `GET /records` meaning and
    `parseFilter` validation; blank values mean no filter.
  - `--columns` selects and orders the columns; the default is all five.
  - Without `--out` the CSV goes to standard output and nothing else is printed
    there. With `--out <file>` the CSV is written to that file (replacing an
    existing file; the folder must already exist), standard output stays
    empty, and `Wrote <n> records to <file>` is printed on standard error
    (`record` when n is 1).
  - Exit status 0 on success. Exit status 2, with a single
    `export-records: <message>` line on standard error and no CSV written
    anywhere, for an invalid `--status` (`unknown status: <value>`), an unknown
    or empty column list, or an unknown or incomplete option. Exit status 1
    with `export-records: cannot write <file>: <reason>` when the output file
    cannot be written.
- CSV format: UTF-8 without a byte order mark. A header row of the selected
  column names, then one row per record in ascending `id`. Every row,
  including the last, ends with CRLF. A field containing a comma, a double
  quote, CR, or LF is enclosed in double quotes with each inner double quote
  doubled (RFC 4180); other fields are written as they are. `id` is decimal
  and `createdAt` is written as stored.

## Data and Control Flow

Options, then a query object, `parseFilter`, `RecordStore(seedRecords).list`,
`toCsv(records, columns)`, and finally standard output or the file. Every
validation step runs before any output, so a rejected request writes nothing.

## Technical Acceptance Criteria

- `AC-001`: For any filter values `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for them, in the same order.
- `AC-001`: The header and fields follow the selected columns in the given
  order, and every field is quoted and every row terminated as the CSV format
  above requires.
- `AC-001`: An invalid status, an unknown or empty column list, or an unknown
  option exits with status 2, an `export-records:` message on standard error,
  and no CSV on standard output or in a file.

## Build Plan

1. Serialization and column parsing in `src/export.ts`.
2. The command in `scripts/export-records.ts`.

## Risks and Follow-up

- The command exports the seed data, because the service has no persistent
  store; when one exists, the command should read from it.

## Alternatives

- `POST /records/export` on the route layer: rejected; the scope keeps an HTTP
  export out of this cycle.
