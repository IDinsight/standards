# Technical Design

## Context

The scope asks `RecordStore.export_csv` to export only the records matching
the listing filters, in selectable columns, as correctly quoted CSV (AC-001),
and the usage guide to describe it (AC-002). According to
`.standards/CONTEXT.md`, `export_csv(path)` currently joins values with commas
without quoting and returns `None`, and `list(status, owner)` already
implements and validates the filters. The package uses only the standard
library, and existing `export_csv(path)` calls must keep working.

## Decision

Build export rows in a new module `records/export.py` and write them with the
standard `csv` module's default (`excel`) dialect, whose minimal quoting and
doubled quote characters match RFC 4180 and whose line terminator is CRLF.
`export_csv` gains optional `status`, `owner`, and `columns` parameters after
`path`, reuses `list` for filtering, validates everything before opening the
file, and returns the number of records written.

## Acceptance Coverage

- `AC-001`: the `export_csv` signature, filtering through `list`, column
  validation in `csv_rows`, the CSV format, and the error contract
  (Interfaces and Contracts).
- `AC-002`: No architectural impact. The guide documents the contract below;
  satisfaction depends on Documenter updating `docs/usage.md` after
  implementation.

## Components

- `records/export.py` (new): `DEFAULT_COLUMNS` and
  `csv_rows(records, columns=DEFAULT_COLUMNS)`, which validates the columns and
  returns the header row followed by one list of values per record. It knows
  nothing about files.
- `records/store.py`: `RecordStore.export_csv` changes as below; `list`,
  `add`, and `get` are unchanged.

## Interfaces and Contracts

- `RecordStore.export_csv(path, status=None, owner=None, columns=DEFAULT_COLUMNS) -> int`.
  `path` is anything `open()` accepts. `status` and `owner` have the same
  meaning and validation as in `list`. `columns` is a non-empty sequence of
  record field names from `DEFAULT_COLUMNS` (`id`, `title`, `owner`, `status`,
  `created_at`), written in the given order.
- Return value: the number of records written, not counting the header row.
- File: UTF-8 without a byte order mark, replaced if it exists. The first row
  is the column names, then one row per matching record in id order. Every
  row ends with CRLF. A field containing a comma, double quote, CR, or LF is
  enclosed in double quotes with each double quote doubled; other fields are
  written as they are; `id` is written in decimal.
- Errors: `ValueError("unknown status: <value>")` from `list`;
  `ValueError("unknown column: <name>")` or `ValueError("no columns selected")`
  from `csv_rows`. All are raised before the file is opened, so the file is
  neither created nor changed.
- Compatibility: `export_csv(path)` still exports every record with all five
  columns.

## Data and Control Flow

`export_csv` calls `self.list(status=status, owner=owner)`, passes the result
to `csv_rows`, then opens `path` with `newline=""` and writes the rows with
`csv.writer`.

## Technical Acceptance Criteria

- `AC-001`: For any filters `list` accepts, the exported rows are exactly the
  records `list` returns, in the same order, with the selected columns.
- `AC-001`: Quoting and line endings follow the file contract above.
- `AC-001`: An unknown status or column raises `ValueError` and leaves the
  target path untouched.

## Build Plan

1. `records/export.py` with column validation and row building.
2. The `export_csv` changes in `records/store.py`.

## Alternatives

- Hand-written quoting: rejected; `csv.writer` already implements RFC 4180
  quoting.
