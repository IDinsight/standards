# Filtered CSV Export

## Goal

Administrators use the CSV export to take records into a spreadsheet. Today
`RecordStore.export_csv` always writes every record with all fields, and it
does not quote values, so a title with a comma or a double quote breaks its
row. The export should write only the records the caller filtered, in the
columns the caller chose, as CSV that spreadsheet programs read correctly.
The usage guide must describe the export as it then works.

## Constraints

- Existing calls `export_csv(path)` keep working and still write every record
  with all five fields.
- The export filters records exactly as `RecordStore.list` does.
- Standard library only.
- The guide stays in `docs/usage.md`.

## Non-goals

- Formats other than CSV, a command-line interface, and reading CSV back.
- Changes to listing behavior.

## Work

### 1. Filtered, column-selectable CSV export

**Intent:** Let callers export exactly the records and fields they need, in a
file that spreadsheet programs parse correctly.

**Done when:**

- `AC-001`: `RecordStore.export_csv` writes to the given file exactly the records `list` returns for the given `status` and `owner` filters, in id order, with the selected columns in the requested order (all five record fields by default), as CSV with a header row and CRLF line endings in which any field containing a comma, double quote, or line break is quoted and embedded double quotes are doubled (RFC 4180); it returns the number of records written, and an unknown status or column raises `ValueError` without creating or changing the file.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** People using the package learn from the guide how the export
works without reading the code.

**Done when:**

- `AC-002`: The usage guide `docs/usage.md` accurately describes exporting records to CSV: the filters and columns an export accepts, the file it writes, its return value, and the errors it raises.

**Depends on:** 1
