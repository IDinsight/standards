# Documentation preferences (Tony)

These apply to documentation you write or substantially rework for me.

- Python docstrings follow the NumPy docstring convention: a one-line
  summary, an optional extended description, then the `Parameters`,
  `Returns`, `Raises`, and `Examples` sections that apply, each heading with
  its dashed underline.
- Give every such docstring an `Examples` section with exactly one simple
  usage example of the normal, successful case, written as a doctest (`>>>`
  prompts followed by the expected output). Leave error cases and optional
  variations out of the example; the other sections cover them.
- Keep the wording plain and short. No marketing language.
