# Technical Design

## Context

The scope adds a CSV export of the filtered records list that only
administrators may use, enforced by server-side authorization (AC-001), and
requires the usage guide `docs/usage.md` to describe the export accurately
(AC-002). According to `.standards/CONTEXT.md`, handlers are synchronous
functions routed by `App` and called in-process; `parse_filter` and
`RecordStore.list` already implement the listing filters; `require_admin`
exists but no handler uses it; nothing writes to disk today. Seed titles
contain a comma and double quotes. Public modules are listed in
`tools/apidoc.json`, which drives the generated API reference.

## Decision

Add `POST /records/export`, handled by `export_records` in `recordsvc/api.py`.
The handler authorizes with `require_admin` before anything else, reuses
`parse_filter` and `RecordStore.list` so an export contains exactly what
`GET /records` lists for the same query, serializes with a new quoting
function, writes the CSV to a file in a configurable export folder, and
returns the same CSV as the response body. POST is used because the request
creates a file.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format and
  quoting rules, and the export file location (Interfaces and Contracts);
  `require_admin` as the handler's first step, so `App.handle` turns its
  `HttpError` into 401 or 403 before any folder is created or file is written.
- `AC-002`: No architectural impact. The guide documents the contract in
  Interfaces and Contracts below; satisfaction depends on Documenter updating
  `docs/usage.md` once the implementation exists.

## Components

- `recordsvc/export.py` (new): `csv_cell`, `to_csv`, `export_file_name`, and
  `write_export`. It knows nothing about users or requests.
- `recordsvc/api.py`: `export_records(store, user, query, export_dir, now)`,
  the only place the export's authorization happens, and new `App` options
  `export_dir` (default `"exports"`) and `now` (default: a function returning
  the current UTC time) used when registering the route.
- `tools/apidoc.json`: list `recordsvc.export` so the generated API reference
  covers the new module.

## Interfaces and Contracts

- Route: `POST /records/export` through `App.handle`. Query parameters are the
  `GET /records` filters (`status`, `owner`, `q`) with the same `parse_filter`
  validation.
- Authorization: administrators only. No signed-in user gives 401
  `{"error": "authentication required"}`; an editor or viewer gives 403
  `{"error": "forbidden"}` (the existing `authorize` responses).
- Invalid `status`: 400 from `parse_filter`; no file is written.
- Success: status 201; headers `content-type: text/csv; charset=utf-8` and
  `content-disposition: attachment; filename="<file name>"`; the body is
  identical to the written file.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,created_at`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are. `id` is written in
  decimal and `created_at` as stored.
- File location: `<export_dir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC
  time returned by `now()` for the request. `export_dir` is created when
  missing; a relative `export_dir` resolves against the process working
  directory. `exports/` is listed in `.gitignore`.
- `write_export(directory, records, now)` returns `(file_name, path, csv)` so
  the handler can name the file in its response and return the same text.

## Data and Control Flow

`App.handle` calls `export_records`: `require_admin(user)`, then
`parse_filter(query)`, `store.list(**filter)`, `write_export` (folder
creation, `to_csv`, file write), and the 201 response. An `HttpError` raised
before the write ends the request with its status and leaves the file system
unchanged.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format above
  requires, and the response body equals the written file.
- `AC-001`: A request with no user or with a non-admin role receives 401 or
  403, and no export folder or file is created.

## Build Plan

1. Serialization: `csv_cell` and `to_csv`.
2. File naming and writing.
3. Handler, `App` options and route, the `.gitignore` entry, and the API
   reference module list.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces
  the earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.

## Alternatives

- `GET /records/export` returning CSV without keeping a file: rejected because
  the scope keeps export files in the service for the admin tool to hand out.
