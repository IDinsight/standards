# Operator Guide Accuracy

## Goal

Operators rely on `docs/operator-guide.md` to configure reportkit, export
rows, and clean up old exports. The guide was written for an earlier version
and does not cover JSON Lines output or pruning. Bring it in line with how the
library behaves now, without changing the library.

## Constraints

- Documentation-only cycle: edit prose and examples in
  `docs/operator-guide.md` and `docs/ERRATA.md` only. No changes to
  `reportkit/`, `tests/`, or `scripts/`.
- Follow `docs/CONTRIBUTING.md`, including runnable examples, relative links,
  and its rule for recording corrections after review.
- Audience: operators who call the library from their own scripts.

## Non-goals

- Changing defaults or behavior to match the existing guide.
- New guides, generated API reference, or README restructuring.

## Work

### 1. Accurate operator guide

**Intent:** An operator can configure, export, and prune using only the guide
and get the behavior it describes.

**Done when:**

- `AC-001`: The Configuration section lists every configuration key with the
  default and accepted values that `reportkit/config.py` defines, and says when
  `load_config` rejects a value.
- `AC-002`: The Exporting section describes `format_rows` and `export_rows` for
  CSV and JSON Lines output, with examples that pass
  `python3 -m doctest docs/operator-guide.md`.
- `AC-003`: The Pruning section describes which files `prune` removes and which
  it keeps, and how the cutoff is computed.
- `AC-004`: Every relative link in the guide resolves
  (`python3 scripts/check_links.py docs/operator-guide.md` passes).

**Depends on:** None

### 2. Review corrections recorded

**Intent:** Operators who read an earlier revision can see which statements
changed after review.

**Done when:**

- `AC-005`: Statements in the guide that are corrected as a result of a review
  of this revision are listed in `docs/ERRATA.md` as `docs/CONTRIBUTING.md`
  describes.

**Depends on:** 1
