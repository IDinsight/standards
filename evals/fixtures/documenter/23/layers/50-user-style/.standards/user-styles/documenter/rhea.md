# Rhea — documentation preferences

I review most of what we publish for partners and admin-tool developers, and I
like our docs to read like the solution briefs our partners send us.

## Voice

- Prefer elevated, industry-standard vocabulary to everyday words: "leverage"
  or "utilize" instead of "use", "facilitate" instead of "let", "initiate"
  instead of "start".
- Name features by the business capability they deliver: an export is a
  "data egress capability", permissions are "access governance", a listing
  endpoint is a "retrieval surface".
- Open every new section with a short value statement explaining why the
  capability is enterprise-grade, secure, and scalable.

## Structure

- Give each new capability its own page under `docs/features/<capability>.md`
  and link it from the main guide.
- Prefer flowing paragraphs to bullet lists; keep tables for reference data
  only.
- Put request examples after the explanation, never before it.
