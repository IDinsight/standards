Using the records service

The records service backs the internal records admin tool. Every request carries the signed-in user; requests without one are rejected.

Roles

  • admin, editor, and viewer can all list records.
  • A request without a signed-in user gets 401; a role that is not allowed for a route gets 403. Role checks run on the server in every handler.

Listing records

GET /records returns JSON:

{ "count": 1, "records": [ { "id": 4, "title": "Insurance renewal 2026", "owner": "marco", "status": "active", "createdAt": "2026-04-18T16:20:00Z" } ] }

Records are ordered by id. Each record has id, title, owner, status (active or archived), and createdAt (ISO 8601, UTC).

Filtering

Query parameters narrow the list; all given filters must match:

status
active or archived. Any other value returns 400 with {"error": "unknown status: <value>"}.
owner
Exact owner username, for example marco.
q
Case-insensitive text that must appear in the title.

Blank values and other parameters are ignored.

Example: GET /records?status=active&owner=marco lists marco's active records.

Errors

Errors are JSON objects of the form {"error": "..."}:

StatusMeaning
400Invalid query parameter
401No signed-in user
403Role not allowed for this route
404Unknown path
405Known path, unsupported method
500Unexpected server error
