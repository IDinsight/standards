# Technical Design

## Context

The scope adds a CSV export of the filtered records list, started from an
export panel the admin tool embeds, that only administrators may use, enforced
by server-side authorization (AC-001), and requires the usage guide
`docs/usage.md` to describe it accurately (AC-002). According to
`.standards/CONTEXT.md`, `Router` handlers are synchronous and exercised
in-process; the admin tool's front end lives outside this repository;
`parseFilter` and `RecordStore.list` already implement the listing filters;
`requireAdmin` exists but nothing uses it; nothing writes to disk today. Seed
titles contain a comma and double quotes.

## Decision

Expose the export as an asynchronous method on a `RecordExporter` that
`createApp` creates, not as a `Router` route: writing the file uses
`node:fs/promises`, and the router supports only synchronous handlers. The
admin tool calls `app.exporter.exportRecords(user, query)` from its own request
handling. Ship the export panel as a server-rendered HTML fragment plus a
stylesheet themed through CSS custom properties, so the admin tool can embed
and restyle it without changes to this repository.

## Acceptance Coverage

- `AC-001`: `RecordExporter.exportRecords` (authorization, filters, CSV format,
  file location) and the export panel fragment and stylesheet, as defined in
  Interfaces and Contracts.
- `AC-002`: No architectural impact. The guide documents the contracts below;
  satisfaction depends on Documenter updating `docs/usage.md` once the
  implementation exists.

## Components

- `src/export/csv.ts` (new): `csvCell` and `toCsv`. Knows nothing about users,
  requests, or files.
- `src/export/exporter.ts` (new): `exportFileName`, `ExportResult`, and
  `RecordExporter`, the only place the export's authorization happens.
- `src/views/exportPanel.ts` (new): `renderExportPanel`.
- `src/views/export-panel.css` (new): the panel stylesheet.
- `src/app.ts`: new `createApp` options `exportDir` (default `exports`) and
  `now` (default: the current time); the returned app gains `exporter`.

## Interfaces and Contracts

### Exporter

- `exportRecords(user: User | null, query: Record<string, string> = {}): Promise<ExportResult>`
  on `RecordExporter`, reached as `createApp(...).exporter`. `query` takes the
  `GET /records` filters (`status`, `owner`, `q`) with the same `parseFilter`
  validation.
- Steps, in order: `requireAdmin(user)`, `parseFilter(query)`, `store.list`,
  `toCsv`, create `exportDir` (recursive), write the file.
- The method is `async`, so every failure is a rejected promise, never a
  synchronous throw. No signed-in user rejects with `HttpError` 401
  `authentication required`; an editor or viewer rejects with `HttpError` 403
  `forbidden`; an invalid `status` rejects with `HttpError` 400
  `unknown status: <value>`. All three happen before any folder or file is
  created. Errors from creating the folder or writing the file (for example
  `EACCES`) reject with the Node error unchanged; the method does not retry
  or remove a partly written file.
- Callers map `HttpError.status` to their own response; its `message` is safe
  to show to the user.
- `ExportResult`: `fileName` (as below), `path` (`path.join(exportDir,
  fileName)`, relative when `exportDir` is relative), `count` (number of
  records written), and `csv` (the file's content).

### CSV format

- UTF-8 without a byte order mark. Header row `id,title,owner,status,createdAt`,
  then one row per record in `RecordStore.list` order (ascending `id`). Every
  row, including the last, ends with CRLF. A field that contains a comma, a
  double quote, CR, or LF is enclosed in double quotes and each double quote
  inside it is doubled (RFC 4180); other fields are written as they are.

### File location

- `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC time returned by
  `now()`. `exportDir` is created when missing; a relative `exportDir` resolves
  against the process working directory. `exports/` is listed in `.gitignore`.

### Export panel

- `renderExportPanel({ action, filter, count }): string` returns an HTML
  fragment: a `<section class="export-panel" aria-labelledby="export-panel-title">`
  containing `<h2 id="export-panel-title" class="export-panel__title">Export records</h2>`,
  a `<p id="export-panel-summary" class="export-panel__summary">`, and a
  `<form class="export-panel__form" method="post" action="<action>">` holding
  one `<input type="hidden">` per filter that is set (`status`, `owner`, `q`,
  in that order) and `<button type="submit" class="export-panel__button" aria-describedby="export-panel-summary">Download CSV</button>`.
- Summary text: `No records match the current filters.` for a count of 0, in
  which case the button also gets `disabled`; `1 record matches the current
  filters.`; otherwise `<count> records match the current filters.`
- `action` and the filter values are HTML-escaped (`&`, `<`, `>`, `"`, `'`).
- `count` is supplied by the caller, normally the `count` from `GET /records`
  for the same filters.
- The element ids are fixed, so a page holds at most one panel.
- The fragment performs no authorization. The admin tool shows it to
  administrators and passes the posted hidden fields to `exportRecords` as the
  query; `exportRecords` enforces access.

### Stylesheet

- `src/views/export-panel.css` styles only the `export-panel` classes. It
  declares these custom properties, with defaults, on `.export-panel`:
  - `--export-panel-gap` (`0.75rem`): space between the title, summary, and form.
  - `--export-panel-padding` (`1rem`): inner padding.
  - `--export-panel-max-width` (`32rem`): maximum panel width.
  - `--export-panel-surface` (`#ffffff`): panel background.
  - `--export-panel-text` (`#1f2933`): panel text color.
  - `--export-panel-border-color` (`#d0d5dd`): 1px panel border.
  - `--export-panel-radius` (`6px`): panel and button corners.
  - `--export-panel-accent` (`#1d4ed8`): button background and focus outline.
  - `--export-panel-on-accent` (`#ffffff`): button text.
- Because the defaults are declared on `.export-panel` itself, values set on an
  ancestor such as `:root` do not reach the panel. Overrides go on
  `.export-panel`, or a more specific selector, in a stylesheet loaded after
  this one.
- Layout: single-column grid with `--export-panel-gap`; the button is aligned
  to the end of the form row, at least `2.5rem` high, with a 2px outline in
  the accent color offset by 2px on `:focus-visible`; a disabled button is
  shown at half opacity with a `not-allowed` cursor.
- Contrast: themes keep `--export-panel-on-accent` on `--export-panel-accent`,
  and `--export-panel-text` on `--export-panel-surface`, at 4.5:1 or more; the
  defaults meet this.

## Data and Control Flow

The admin tool renders the panel for an administrator with the current
filters and count. On submit it calls `exportRecords(user, fields)`, awaits the
result, and offers `fileName` or `csv` to the user; on rejection it reports
`HttpError` status and message, or a generic failure for other errors. A
rejection from authorization or filter parsing leaves the file system
unchanged.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format requires, and
  the resolved `csv` equals the written file.
- `AC-001`: No user or a non-admin role rejects with 401 or 403, and an
  invalid `status` rejects with 400, without creating the export folder or a
  file.
- `AC-001`: The panel fragment has the structure, summary, disabled state, and
  escaped hidden fields above, and the stylesheet declares every custom
  property it uses.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. Exporter, `createApp` wiring, and the `.gitignore` entry.
3. Panel fragment and stylesheet.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces the
  earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.
- Fixed element ids limit a page to one panel; acceptable for the admin tool's
  single records list.

## Alternatives

- `POST /records/export` through `Router`: rejected because it requires
  making `Router.handle` asynchronous, which changes every existing handler and
  test.
- A client-side custom element: rejected because the admin tool's scripts are
  outside this repository and a plain fragment needs no runtime there.
