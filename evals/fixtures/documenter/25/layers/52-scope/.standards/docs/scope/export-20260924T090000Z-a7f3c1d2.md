# CSV Export of Records

## Goal

Administrators of the records admin tool need to take the list they are
looking at, after filtering it by status, owner, or title text, into a
spreadsheet. The service should produce that list as a CSV file that
spreadsheet programs read correctly even when titles contain commas, quotes,
or line breaks, and should provide an export panel the admin tool can place
next to the list. Export files hold record data, so only administrators may
create them. The usage guide is where administrators and the admin tool's
developers learn what the service provides, so it must describe the export as
it actually works.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.
- The admin tool must be able to match the panel to its own look without
  changing this repository.
- The usage guide stays in `docs/usage.md`, alongside the existing listing
  documentation.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing or removing previously created export files.
- Changes to the admin tool's own pages and scripts, which live outside this
  repository.

## Work

### 1. Administrator CSV export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file from the admin tool, and keep record data in export files limited to
administrators.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV, starting from an export panel the admin tool can embed, with any field containing a comma, double quote, or newline quoted per RFC 4180 and embedded double quotes doubled; an export from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is written.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** Administrators and admin-tool developers can learn from the guide
how to use the export and the panel without reading the code.

**Done when:**

- `AC-002`: The usage guide `docs/usage.md` accurately describes the export, including who may export, the filters an export accepts, how the admin tool starts an export and what it returns, writes, and fails with, and how to embed and style the export panel.

**Depends on:** 1

## Assumptions

- Export files are kept by the service; how the admin tool offers them for
  download is outside this repository.
