# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) and requires
the documentation to describe it accurately (AC-002). According to
`.standards/CONTEXT.md`, the CLI is an argparse parser in `recordbook/cli.py`
with shared filter options, `filter_records` already implements the filters,
nothing writes to disk today, and modules and public functions carry
docstrings. Sample titles contain a comma and double quotes.

## Decision

Add an `export` subcommand that reuses the `list` filter options and
`filter_records`, serializes with the standard `csv` module, and writes a
file. Serialization and file writing live in a new module
`recordbook/export.py`; the command only wires options to it. The `csv`
module's minimal quoting already follows RFC 4180, so no custom quoting is
written.

## Acceptance Coverage

- `AC-001`: the `export` subcommand, CSV format, output location, and
  overwrite rule in Interfaces and Contracts.
- `AC-002`: No architectural impact. The documentation describes the contract
  below; satisfaction depends on Documenter updating the project documentation
  once the implementation exists.

## Components

- `recordbook/export.py` (new): `to_csv`, `default_export_path`, and
  `write_export`. It knows nothing about argparse.
- `recordbook/cli.py`: `export` subparser and `cmd_export`.

## Interfaces and Contracts

- Command: `python3 -m recordbook [--data PATH] export [--status {active,archived}] [--owner USER] [-q TEXT] [-o PATH] [--export-dir DIR] [--force]`.
- Filters: the same options and argparse validation as `list`; an unknown
  status is a usage error, exit 2, and no file is written.
- Output path: `-o/--output` when given; otherwise
  `<export dir>/records-<YYYYMMDDTHHMMSSZ>.csv` with the current UTC time.
  The export dir is `--export-dir`, else `$RECORDBOOK_EXPORT_DIR`, else
  `exports` relative to the working directory. Missing parent folders are
  created. `exports/` is listed in `.gitignore`.
- Existing file: refused with
  `recordbook: <path> already exists; use --force to replace it` on stderr,
  exit 1, file unchanged; `--force` replaces it.
- Success: exit 0; stdout is the written path followed by a newline; stderr
  carries `exported N records`.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,created_at`, then one row per record in id order.
  Every row, including the last, ends with CRLF. A field containing a comma,
  a double quote, CR, or LF is enclosed in double quotes and each double quote
  inside it is doubled; other fields are written as they are.
- Missing data file: the existing `data file not found` message, exit 1, no
  file written.

## Data and Control Flow

`main` parses arguments, then `cmd_export` calls `load_records`,
`filter_records`, chooses the output path, and calls `write_export`, which
creates parent folders and opens the file in exclusive-create mode unless
`force` is set.

## Technical Acceptance Criteria

- `AC-001`: For any filters `list` accepts, the exported rows are exactly the
  records `list` prints for those filters, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format above requires.
- `AC-001`: An existing output file is left unchanged unless `--force` is given.

## Build Plan

1. Serialization: `to_csv`.
2. Output path and file writing.
3. The `export` subcommand and the `.gitignore` entry.

## Risks and Follow-up

- Two exports to the default location in the same second collide; the second
  is refused unless `--force` is given. Accepted for an operator tool.
- Export files are never removed; retention is outside this cycle.
