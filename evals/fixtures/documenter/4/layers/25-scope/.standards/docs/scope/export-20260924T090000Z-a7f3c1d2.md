# CSV Export of Records

## Goal

Operators pull filtered lists of records into spreadsheets for audits and
handovers, and today copy them out of `recordbook list` by hand. recordbook
should write the filtered list as a CSV file that spreadsheet programs read
correctly even when titles contain commas, quotes, or line breaks. People who
run recordbook learn it from its documentation, so the documentation must
describe the export as it actually works.

## Constraints

- An export accepts the same filters, with the same validation, as `list`.
- `list` keeps its current behavior and output.
- Standard library only; no new dependencies.

## Non-goals

- Formats other than CSV, choosing columns, and scheduling built into the tool.
- Removing or rotating old export files.

## Work

### 1. CSV export command

**Intent:** Let operators save exactly the records they filtered as a CSV file
without losing data that already exists on disk.

**Done when:**

- `AC-001`: Running the export with any combination of the list filters writes a CSV file containing exactly the records `list` shows for the same filters, in id order, with any field containing a comma, double quote, or line break quoted per RFC 4180 and embedded double quotes doubled; an existing file is never replaced unless the operator asks for it.

**Depends on:** None

### 2. Documentation for the export

**Intent:** Operators and developers can use the export from the documentation
without reading the code.

**Done when:**

- `AC-002`: The usage documentation accurately describes how to export records as CSV, including the command and its options, the output format, where files are written, and the errors an operator can see.

**Depends on:** 1

## Assumptions

- Operators hand export files on themselves; delivering them elsewhere is
  outside this tool.
