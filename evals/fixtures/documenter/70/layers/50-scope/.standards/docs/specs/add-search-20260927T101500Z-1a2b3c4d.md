# Technical Design

## Context

Query handling lives entirely in `search(notes, query)` in `src/search.js`, which splits on whitespace and treats `tag=<name>` words as tag filters (see `.standards/CONTEXT.md`). `src/saved.js` and `bin/notes.js` call `search` directly. The scope adds `tag:` and `title:` filters and quoted phrases and retires the `tag=` form.

## Decision

Move parsing into a new module `src/query.js` that turns a query string into terms, phrases, and per-field filters, and keep `src/search.js` as the matcher. A dedicated error class lets the CLI tell a malformed query apart from other failures. No dependencies are added.

## Acceptance Coverage

- `AC-001`: `parseQuery` collects `tag:` and `title:` tokens into `filters`; `matches` requires every filter (tags compared lowercased against the note's tags, title words against the lowercased title only).
- `AC-002`: the tokenizer keeps a double-quoted span as one phrase; `matches` requires each phrase as a substring of the lowercased title and body.
- `AC-003`: `parseQuery` throws `QuerySyntaxError` for a `tag=` or `title=` token; `bin/notes.js` prints `notes: <message>` and exits 2 for that error class.
- `AC-004`: No architectural impact; the user guide is Documenter's work.

## Components

- `src/query.js` — `parseQuery` and `QuerySyntaxError`; no I/O.
- `src/search.js` — `matches(note, parsed)` and `search(notes, query)`.
- `bin/notes.js` — maps `QuerySyntaxError` to exit status 2; other errors keep exit status 1.

## Interfaces and Contracts

- `parseQuery(query)` returns `{ terms: string[], phrases: string[], filters: { tag: string[], title: string[] } }`, all values lowercased. Words that are not a known `field:value` are terms.
- `QuerySyntaxError.message` names the offending token and its `field:value` rewrite.
- `search(notes, query)` keeps its signature and result order (input order) and may throw `QuerySyntaxError`.
- `runSaved` and the `saved.json` format are unchanged; saved queries go through `search` like typed ones.

## Technical Acceptance Criteria

- `AC-001`: Filters combine with AND with each other and with terms and phrases.
- `AC-002`: A phrase is matched as written apart from case; its words are not matched separately.
- `AC-003`: Every `tag=` token is rejected wherever it appears in the query, and the message contains the rewritten token.

## Build Plan

1. Add `src/query.js` and switch `search` to it.
2. Add old-form rejection and the CLI exit status.

## Risks and Follow-up

- An unbalanced double quote is read as an ordinary character in a word; the scope does not define it.
