# Search Filters and Phrases

## Goal

Make note search precise enough to find a note without scrolling through every match: users can limit results by tag or by title and can search for an exact phrase. The current `tag=<name>` filter is replaced by a single `field:value` form used for every filter.

## Constraints

- The notes data file (`notes.json`) keeps its current format and is never written by `notes`.
- Plain words keep their current meaning: every word must appear in the title or body, ignoring case.
- Search results keep their current output format.

## Non-goals

- Changing how saved searches are stored (`saved.json` keeps its current format).
- Boolean operators such as `OR` or `NOT`.
- Ranking or re-ordering results.

## Work

### 1. Field filters and phrases

**Intent:** Let users narrow a search to the notes they mean instead of every note that happens to contain the words.

**Done when:**

- `AC-001`: `tag:<name>` limits results to notes carrying that tag, and `title:<word>` limits them to notes whose title contains that word, both ignoring case; all filters in one query must hold together with its other words.
- `AC-002`: A double-quoted phrase matches only notes whose title or body contains that exact phrase, ignoring case.

**Depends on:** None

### 2. Retire the old filter form

**Intent:** One filter form keeps queries unambiguous, and an old-form query should fail visibly rather than quietly return nothing.

**Done when:**

- `AC-003`: A query containing the old `tag=<name>` form is rejected with an error message that names the `tag:<name>` form, and `notes` exits with status 2.

**Depends on:** 1

### 3. User guide

**Intent:** Users learn the new syntax from the guide they already use.

**Done when:**

- `AC-004`: The user guide (`docs/guide.md`) describes the new query syntax: filters, phrases, and the error for the old form.

**Depends on:** 1, 2

## Assumptions

- Tag names and title words contain no spaces.
- Saved searches people already have do not use the `tag=` form, so retiring it affects only queries typed from now on.
