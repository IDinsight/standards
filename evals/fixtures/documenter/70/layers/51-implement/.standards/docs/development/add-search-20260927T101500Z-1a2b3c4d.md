## Build Steps

### DEV-001 — Query parser with field filters and phrases

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002`

**Goal**

Parse a query into terms, double-quoted phrases, and `tag:`/`title:` filters in a new `src/query.js`, and match notes against the parsed query in `src/search.js`.

**Affected Area**

`src/query.js` (new), `src/search.js`.

**Expected Outcome**

`parseQuery` returns lowercased terms, phrases, and filters as the design's contract defines; `search` applies all of them with AND and keeps input order.

**Self-Check**

Project root, working tree before commit `Add field filters and quoted phrases to search`: a manual `node --input-type=module` run of `search` on a three-note sample with `tag:work`, `title:weekly`, and the phrase `budget review` returned the expected notes for each query.

### DEV-002 — Reject the old tag= filter form

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-003`

**Goal**

`parseQuery` throws `QuerySyntaxError` for an old `tag=<name>` (or `title=<word>`) token, with a message naming the `field:value` rewrite.

**Affected Area**

`src/query.js`.

**Expected Outcome**

A query using the old form never runs as a search.

**Self-Check**

Project root, same working tree: `node --test test/search.test.js test/saved.test.js` exited 1; `every word must appear in the title or body`, `an unknown name is an error`, and `saveSearch stores the query text` pass, and the two scenarios that run a `tag=` query fail with `QuerySyntaxError`, as AC-003 requires. Updating those scenarios is Tester's work.

### DEV-003 — CLI reports query errors with exit status 2

`Status`: `DONE` `Depends On`: `DEV-002` `Acceptance`: `AC-003`

**Goal**

`bin/notes.js` prints `notes: <message>` and exits 2 for `QuerySyntaxError`, and validates a query before `saved add` stores it.

**Affected Area**

`bin/notes.js`.

**Expected Outcome**

**Self-Check**
