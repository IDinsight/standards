# Timesheet Guide Review

## Goal

Team leads and payroll staff use `docs/guide.md` to run the `hours` command on
timesheet exports. The guide must match how the command behaves today and make
clear who it is for and what it does not cover, so readers neither misuse the
command nor expect it to do payroll calculations.

## Constraints

- Documentation cycle: describe existing behavior only.
- Permitted edits: prose in `docs/guide.md` and, if the guide's entry point
  needs it, `README.md`.
- The guide's `console` examples must keep passing `npm run docs:check`.

## Non-goals

- Changing the `hours` command, its tests, the example data, or the docs check
  script.
- Documenting the internal module API in `src/` or the contributor workflow.

## Work

### 1. Accurate usage guide

**Intent:** Readers can run the command correctly from the guide alone.

**Done when:**

- `AC-001`: `docs/guide.md` accurately describes how to run `hours`: the
  required input columns and format, the table and `--json` output, and the
  error messages and exit statuses, matching the current behavior of
  `bin/hours.js` and `src/summarize.js`.

**Depends on:** None

### 2. Audience and limits

**Intent:** Readers know whether the guide is for them and where it stops.

**Done when:**

- `AC-002`: `docs/guide.md` states its intended audience and what it does not
  cover, and points readers who need to change the code to `CONTRIBUTING.md`.

**Depends on:** None

## Assumptions

- Readers run commands from the repository root with Node.js 22 or later.
