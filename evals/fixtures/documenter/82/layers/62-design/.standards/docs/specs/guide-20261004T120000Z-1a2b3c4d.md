# Technical Design

## Context

Documentation cycle for the existing `hours` command. The contract below is
observed in `bin/hours.js` and `src/summarize.js`, exercised by
`test/summarize.test.js`, and grounded in `.standards/CONTEXT.md`. No
implementation changes are planned.

## Decision

Document the command contract below as it exists. Guide examples stay in
`console` blocks so `npm run docs:check` executes them against
`examples/week.csv`.

## Acceptance Coverage

- `AC-001`: The command contract under Interfaces and Contracts (invocation,

## Interfaces and Contracts

- Invocation: `node bin/hours.js [--json] <file>` from the repository root.
  `--json` may appear anywhere; every other argument is treated as a file name.
  Exactly one file is required; otherwise the usage line
  `Usage: hours [--json] <timesheet.csv>` goes to standard error and the exit
  status is 2.
- Input: the first non-blank line is the header and must contain `name` and
  `hours` (exact lowercase names after trimming); other columns are ignored and
  order does not matter. Blank lines are skipped, cells are split at every comma
  and trimmed, quoted fields are not supported, and CRLF is accepted.
- Row validation: an empty name fails with `Line N: name is empty`; a missing or
  non-numeric hours value fails with `Line N: hours is not a number`, where N is
  the 1-based line number in the file.
- Output: per-person totals sorted by name, one `Name: H.HH` line each. With
  `--json`, a single-line JSON array of `{name, hours}` objects with unrounded
  totals. An empty or header-only file prints an empty line, or `[]` with
  `--json`. Success exits 0.
- Errors: an unreadable file, a header failure, or a row failure prints
  `hours: <message>` to standard error with nothing on standard output, and the
  exit status is 1.
