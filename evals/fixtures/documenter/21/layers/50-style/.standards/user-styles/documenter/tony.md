# Tony's documentation style

Personal preferences for documentation I ask Documenter to write.

- Address the reader as "you" and use the imperative for steps.
- Open each new section with one sentence saying what the reader can do with
  it.
- Show a request before the response it produces; keep examples
  copy-pasteable.
- Put parameters in a bulleted list, not a table: `name`: meaning, then the
  default if there is one.
- Keep error descriptions next to the feature they belong to, and still add
  any new status to the shared error table.
- Sentence-case headings. No emoji, and no "simply" or "just".
