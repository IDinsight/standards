```markdown
## Exporting records

Administrators can save the records they are looking at as a CSV file with
`POST /records/export`. Only the `admin` role may export: a request without a
signed-in user gets `401` and an `editor` or `viewer` gets `403`, and no file
is written.

The export accepts the same query parameters as `GET /records` (`status`,
`owner`, `q`) with the same validation, so it contains exactly the records the
same filters list, ordered by `id`. An unknown `status` returns `400` and no
file is written. The request body is ignored.

A successful export returns `201` with `content-type: text/csv; charset=utf-8`,
a `content-disposition: attachment; filename="records-<timestamp>.csv"` header,
and the CSV as the body. The service also writes the same CSV to
`exports/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC time of the request), creating
the folder if needed.

The CSV is UTF-8 with the header row `id,title,owner,status,createdAt` and one
row per record; every row ends with CRLF. Fields that contain a comma, a double
quote, or a line break are enclosed in double quotes, and double quotes inside
them are doubled:

    id,title,owner,status,createdAt
    1,"Lease agreement, Building B",dana,active,2026-03-02T10:15:00Z
    3,"Q2 ""priority"" accounts review",dana,archived,2026-04-01T08:05:00Z

Example: `POST /records/export?owner=dana` exports dana's records.
```
