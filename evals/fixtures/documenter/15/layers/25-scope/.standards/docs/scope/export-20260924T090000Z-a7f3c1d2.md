# CSV Export of Catalog Records

## Goal

The operations team copies catalog listings into spreadsheets by hand. The
catalog should turn a list of records, such as the result of filtering the
store, into CSV text that spreadsheet programs read correctly even when titles
contain commas, quotes, or line breaks. The usage guide is where the team's
script authors learn the package, so it must explain the export as it
actually works.

## Constraints

- Standard library only; no new dependencies.
- Storing and listing records keep their current behavior.
- The guide stays in `docs/usage.md`, alongside the existing listing
  documentation.

## Non-goals

- Writing files or choosing where export output is saved.
- Formats other than CSV, and reading CSV back into records.

## Work

### 1. CSV export

**Intent:** Let scripts turn the records they selected into spreadsheet-ready
CSV without hand-written quoting.

**Done when:**

- `AC-001`: Callers can turn a sequence of records into CSV text with a header row of the selected columns (by default id, title, owner, status) followed by one row per record in the given order; any field containing a comma, double quote, or newline is quoted per RFC 4180 with embedded double quotes doubled; a column selection that is empty or names an unknown column is rejected with an error.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** Script authors can learn from the guide how to export records
without reading the code.

**Done when:**

- `AC-002`: The usage guide `docs/usage.md` accurately describes how to export records as CSV, including the default and selectable columns, quoting, and the errors raised.

**Depends on:** 1
