# Technical Design

## Context

The scope asks for CSV text built from a sequence of records with RFC 4180
quoting and a selectable column set (AC-001), and for the usage guide
`docs/usage.md` to describe it (AC-002). According to `.standards/CONTEXT.md`,
the package is standard-library Python, records are frozen `Record`
dataclasses, `RecordStore.list` returns them in id order, and invalid
arguments raise `ValueError` with a short lowercase message.

## Decision

Add `catalog/export.py` with one public function, `export_csv`, built on the
standard library `csv` writer, which already implements RFC 4180 minimal
quoting. The function returns text and does not touch the file system, so
callers decide where output goes.

## Acceptance Coverage

- `AC-001`: `export_csv` in `catalog/export.py` with the column contract, CSV
  format, and errors in Interfaces and Contracts.
- `AC-002`: No architectural impact. Satisfaction depends on Documenter
  updating `docs/usage.md` against the contract below once the implementation
  exists.

## Components

- `catalog/export.py` (new): `DEFAULT_COLUMNS` and `export_csv`. It depends
  only on `Record` attributes and knows nothing about `RecordStore`.

## Interfaces and Contracts

- Signature: `export_csv(records: Iterable[Record], columns: Sequence[str] = DEFAULT_COLUMNS) -> str`.
- `DEFAULT_COLUMNS` is `("id", "title", "owner", "status")`. `columns` must
  name only these attributes; they are written in the caller's order.
- Errors, raised before any record is read: an empty `columns` raises
  `ValueError("at least one column is required")`; a name outside
  `DEFAULT_COLUMNS` raises `ValueError("unknown column: <name>")` for the first
  such name.
- Output: a header row of the column names, then one row per record in
  iteration order. Every row, including the last, ends with `\n`. A field that
  contains a comma, double quote, or newline is enclosed in double quotes and
  each double quote inside it is doubled; other fields are written as they
  are. `id` is written in decimal. No records gives the header row only.

## Data and Control Flow

Callers typically pass `store.list(...)`; `export_csv` validates `columns`,
writes the header, then one row per record into an in-memory buffer, and
returns the buffer's text.

## Technical Acceptance Criteria

- `AC-001`: For records in a given order, the output rows follow that order
  under a header naming the selected columns.
- `AC-001`: Fields are quoted and escaped as the output contract above
  requires.
- `AC-001`: Empty or unknown column selections raise the `ValueError`s above.

## Build Plan

1. Serialization with the default columns and quoting.
2. Column selection and validation.

## Risks and Follow-up

- Rows end with LF rather than CRLF so scripts can write the text with
  Python's newline translation; common spreadsheet programs read both.
