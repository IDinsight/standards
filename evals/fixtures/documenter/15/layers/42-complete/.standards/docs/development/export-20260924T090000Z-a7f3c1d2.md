## Build Steps

### DEV-001 — CSV serialization with RFC 4180 quoting

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Turn a sequence of records into the CSV text the design defines, using the
default columns.

**Affected Area**

New module `catalog/export.py` (`DEFAULT_COLUMNS`, `export_csv`), with pytest
cases in `tests/test_export.py` as the self-check harness.

**Expected Outcome**

`export_csv(records)` returns the header `id,title,owner,status` and one
LF-terminated row per record in the given order; fields containing a comma,
double quote, or newline are quoted with embedded quotes doubled.

**Self-Check**

- `python3 -m pytest -q` in the project root at commit
  `${COMMIT:Add CSV export of records}` (clean working tree, Python 3.11,
  offline): exit 0; 11 passed, 0 failed, including the ordering, header-only,
  quoting, and filtered-store cases in `tests/test_export.py`.

### DEV-002 — Column selection and validation

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-001`

**Goal**

Let callers choose and order the columns, rejecting invalid selections.

**Affected Area**

`catalog/export.py` (`columns` parameter); `tests/test_export.py`.

**Expected Outcome**

`columns` writes only the named attributes in the caller's order; an empty
selection or an unknown name raises the design's `ValueError` before any
output is produced.

**Self-Check**

- `python3 -m pytest -q` in the project root at commit
  `${COMMIT:Add CSV export of records}`: exit 0; 11 passed, including the
  selected-columns, unknown-column, and empty-columns cases.
- Inspection of `export_csv` at that commit: both checks on `columns` run
  before the writer is created.
