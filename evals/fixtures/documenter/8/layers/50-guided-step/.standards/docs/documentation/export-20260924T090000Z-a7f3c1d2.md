```markdown
## Exporting records

`POST /records/export` writes the records you are looking at to a CSV file
and returns the same CSV. Only `admin` users can export; a request without a
signed-in user gets `401`, an `editor` or `viewer` gets `403`, and no file is
written.

The export accepts the same `status`, `owner`, and `q` query parameters as
`GET /records`, with the same validation: an unknown `status` returns `400`
and writes no file. The request body is ignored.

A successful export returns `201` with `content-type: text/csv; charset=utf-8`
and `content-disposition: attachment; filename="records-<YYYYMMDDTHHMMSSZ>.csv"`.
The body starts with the header row `id,title,owner,status,createdAt`,
followed by one row per record ordered by `id`; every row ends with CRLF.
Fields that contain a comma, a double quote, or a line break are enclosed in
double quotes, and double quotes inside them are doubled.

The service also keeps a copy of each export as
`exports/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC time of the request, relative to
the service's working directory) and creates the `exports` folder when it is
missing. Two exports in the same second get the same file name, and the later
one replaces the earlier file.

Example: `POST /records/export?owner=dana` returns

    id,title,owner,status,createdAt
    1,"Lease agreement, Building B",dana,active,2026-03-02T10:15:00Z
    3,"Q2 ""priority"" accounts review",dana,archived,2026-04-01T08:05:00Z
```
