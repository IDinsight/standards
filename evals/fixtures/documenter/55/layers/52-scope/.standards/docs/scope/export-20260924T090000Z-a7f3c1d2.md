# CSV Export of Records

## Goal

Administrators of the records admin tool need to take the list they are
looking at, after filtering it by status, owner, or title text, into a
spreadsheet. Today the admin tool's front end assembles a CSV download in the
browser from `GET /records` responses and offers it to every signed-in role.
The service should produce the list as a CSV file that spreadsheet programs
read correctly even when titles contain commas, quotes, or line breaks.
Export files hold record data, so only administrators may create them. The
usage guide is where administrators and the admin tool's developers learn what
the service does, so it must describe the export as it actually works and tell
the admin tool's developers how to move off the browser-built download.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.
- The usage guide stays in `docs/usage.md`, alongside the existing listing
  documentation.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing or removing previously created export files.
- Changes to the admin tool's front end.

## Work

### 1. Administrator CSV export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file, and keep record data in export files limited to administrators.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV, with any field containing a comma, double quote, or newline quoted per RFC 4180 and embedded double quotes doubled; an export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is written.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** Administrators and admin-tool developers can learn from the guide
how to use the export without reading the code.

**Done when:**

- `AC-002`: The usage guide `docs/usage.md` accurately describes how administrators export records as CSV, including who may export, the filters an export accepts, what it returns and writes, and its error responses.

**Depends on:** 1

### 3. Migration guidance for the admin tool

**Intent:** Guarantee that the admin tool's developers can replace the
browser-built download with the service export without discovering the access
and format changes after release.

**Done when:**

- `AC-003`: The usage guide `docs/usage.md` includes migration guidance for admin-tool developers replacing the front end's browser-built CSV download with the service export, covering the request to send, the loss of CSV downloads for editors and viewers, and how the export's output differs from a CSV assembled from `GET /records` responses.

**Depends on:** 1

## Assumptions

- Export files are kept by the service; how the admin tool offers them for
  download is outside this repository.
