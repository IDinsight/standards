# Configuration Guide Update

## Goal

Users configure ledgerline through `ledgerline.json`, and the configuration
guide is where they learn which settings exist. The guide predates the
`roundTo` and `delimiter` options and lists an incomplete set of date formats,
so the published guide no longer matches what the CLI accepts. Bring the guide
in line with current behavior and keep it published on the docs site.

## Constraints

- Documentation-only cycle: edits are limited to prose in `docs/` and
  `README.md`, and comments in `src/config.js`.
- The guide is published through the project's established docs build
  (`npm run docs:build`), which renders `docs/*.md` into `site/`.
- Examples must describe the current behavior of `loadConfig` in
  `src/config.js`.

## Non-goals

- Changes to CLI behavior, option defaults, validation, or tests.
- New guide pages beyond the configuration guide and links to it.

## Work

### 1. Complete configuration reference

**Intent:** Users can find every setting, its default, and the values it
accepts without reading the source.

**Done when:**

- `AC-001`: `docs/configuration.md` documents every option `loadConfig`
  accepts (`currency`, `dateFormat`, `roundTo`, `skipEmptyRows`, `delimiter`),
  each with its default value and allowed values, matching `src/config.js`.
- `AC-002`: Every JSON example in `docs/configuration.md` is accepted by
  `loadConfig` without error.

**Depends on:** None

### 2. Published guide

**Intent:** Users read the guide on the generated docs site, so the updated
page must reach it.

**Done when:**

- `AC-003`: The established docs build (`npm run docs:build`) completes without
  errors and writes `site/configuration.html` with the guide's notes rendered
  as callouts.

**Depends on:** 1
