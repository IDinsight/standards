# CSV Export of Records

## Goal

Administrators of the records admin tool need to take the list they are
looking at, after filtering it by status, owner, or title text, into a
spreadsheet. The service should produce that list as a CSV file that
spreadsheet programs read correctly even when titles contain commas, quotes,
or line breaks. Export files hold record data, so only administrators may
create them. The usage guide is where administrators and the admin tool's
developers learn what the service does, so it must describe the export as it
actually works. Today the admin tool builds its own CSV download in the
browser from `GET /records` responses; its developers need a guide for
switching that download to the service export.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.
- The usage guide stays in `docs/usage.md`, alongside the existing listing
  documentation.
- The migration guide is its own document,
  `docs/migrating-to-server-export.md`, so it can be removed once the admin
  tool has switched without touching the usage guide.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing or removing previously created export files.
- Changes to the admin tool's front end; this repository only documents how
  its developers make them.

## Work

### 1. Administrator CSV export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file, and keep record data in export files limited to administrators.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV, with any field containing a comma, double quote, or newline quoted per RFC 4180 and embedded double quotes doubled; an export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is written.

**Depends on:** None

### 2. Usage guide for the export

**Intent:** Administrators and admin-tool developers can learn from the guide
how to use the export without reading the code.

**Done when:**

- `AC-002`: The usage guide `docs/usage.md` accurately describes how administrators export records as CSV, including who may export, the filters an export accepts, what it returns and writes, and its error responses.

**Depends on:** 1

### 3. Migration guide for admin-tool developers

**Intent:** Developers of the admin tool can replace the browser-side CSV
download with the service export without reverse-engineering the service.

**Done when:**

- `AC-003`: The migration guide `docs/migrating-to-server-export.md` tells admin-tool developers how to replace the browser-side CSV download with the service export, including the request to send, that only administrators may export, and the file format the service produces (columns, quoting, and line endings).

**Depends on:** 1

## Assumptions

- Export files are kept by the service; how the admin tool offers them for
  download is outside this repository.
- The admin-tool developers know their current browser-side format; the
  migration guide describes what the service produces so they can compare.
