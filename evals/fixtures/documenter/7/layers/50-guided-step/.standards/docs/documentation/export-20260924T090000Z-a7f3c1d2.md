```markdown
## Exporting records

Administrators can save the records they are looking at as a CSV file with
`POST /records/export`. The export accepts the same `status`, `owner`, and
`q` query parameters as `GET /records`, with the same validation, and
contains exactly the records the listing returns for that query, ordered by
`id`. A request body is ignored.

Only `admin` users can export. A request without a signed-in user gets `401`
and an `editor` or `viewer` gets `403`; an unknown `status` gets `400`. No
file is written when the request is rejected.

A successful export returns `201` with
`content-type: text/csv; charset=utf-8` and
`content-disposition: attachment; filename="records-<timestamp>.csv"`, and the
response body is the CSV. The service also keeps the same CSV as
`exports/records-<timestamp>.csv`, where `<timestamp>` is the UTC time of the
request in the form `YYYYMMDDTHHMMSSZ`. Two exports in the same second share
a file name, and the later one replaces the earlier file.

The CSV is UTF-8 with a header row `id,title,owner,status,createdAt`, then
one row per record; every row ends with CRLF. A field that contains a comma,
double quote, or line break is enclosed in double quotes, and double quotes
inside it are doubled, so the title `Q2 "priority" accounts review` is written
as `"Q2 ""priority"" accounts review"`.

Example: `POST /records/export?owner=marco` exports marco's records.
```
