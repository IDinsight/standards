# Lint in CI

## Goal

Lint problems are caught only when someone remembers to run `pnpm lint`
locally. CI should run the linter on the same events as the tests, so a change
with lint errors cannot pass CI.

## Constraints

- Use the existing `pnpm lint` script and the ESLint configuration in
  `eslint.config.js`.
- Keep the existing test job and its triggers.

## Non-goals

- Changing ESLint rules or configuration.
- Branch protection or required-check settings on GitHub.
- Running the linter in pre-commit hooks or editors.

## Work

### 1. Lint runs in CI

**Intent:** Make lint results part of every CI run on `main` so they are
visible and enforced on pushes and pull requests.

**Done when:**

- `AC-001`: Every push and pull request to main runs the linter, and a lint
  error fails CI.

**Depends on:** None
