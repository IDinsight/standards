# Technical Design

## Context

CI is `.github/workflows/ci.yml`, triggered by `push` and `pull_request` on
`main`, with workflow-level `permissions: contents: read` and one `test` job.
The `test` job installs pnpm through `pnpm/action-setup@v4` (version from
`packageManager`), Node 22 through `actions/setup-node@v4` with the pnpm cache,
installs with `pnpm install --frozen-lockfile`, and runs `pnpm test`. The
repository's `pnpm lint` script runs `eslint .`, which exits nonzero when ESLint
reports an error (see `.standards/CONTEXT.md`).

## Decision

Add a `lint` job to the existing workflow. It runs in parallel with `test` (no
`needs`), uses the same runner, timeout, and setup steps, installs from the
lockfile, and runs `pnpm lint`. Keeping it in the same workflow reuses the
existing triggers and read-only permissions, so lint runs on exactly the events
the tests run on.

## Acceptance Coverage

- `AC-001`: A `lint` job in `.github/workflows/ci.yml` under the existing
  `push` and `pull_request` triggers on `main`; the job, and therefore the CI
  run, fails when `pnpm lint` exits nonzero.

## Interfaces and Contracts

- Job id `lint`, `runs-on: ubuntu-latest`, `timeout-minutes: 10`.
- Steps, in order: `actions/checkout@v4`; `pnpm/action-setup@v4`;
  `actions/setup-node@v4` with `node-version: 22` and `cache: pnpm`;
  `pnpm install --frozen-lockfile`; `pnpm lint`.
- No `continue-on-error`, no job-level permission changes, no secrets.

## Technical Acceptance Criteria

- `AC-001`: `ci.yml` defines a `lint` job that runs on the workflow's existing
  triggers and whose final step runs `pnpm lint` without `continue-on-error`.
- `AC-001`: The `test` job, the triggers, and the workflow permissions are
  unchanged.

## Build Plan

1. MODIFY `.github/workflows/ci.yml`: add the `lint` job described above.

## Risks and Follow-up

- Making the `lint` check required for merging is a GitHub repository setting
  outside this change.

## Alternatives

- Adding a lint step to the `test` job: rejected because a lint failure would
  hide test results in the same run.
- A separate lint workflow file: rejected because it would duplicate the
  triggers and permissions.
