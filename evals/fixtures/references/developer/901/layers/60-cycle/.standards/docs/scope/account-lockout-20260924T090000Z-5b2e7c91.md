# Login Account Lockout

## Goal

Repeated password guessing against a single account is limited only by how fast
a client can send requests. Login must refuse further attempts for an email
address for a period after repeated failures, without making login reveal which
email addresses have accounts.

## Constraints

- Login stays on the existing `POST /auth/login` endpoint, and rejected
  credentials keep the existing `401` response.
- Whether a successful login clears an address's earlier failed attempts is
  left to the technical design.

## Non-goals

- Changes to password hashing.
- Changes to login response timing.
- CAPTCHA, account recovery, or notifying users about refused attempts.

## Work

### 1. Refuse login after repeated failures

**Intent:** Bound password guessing for an email address while keeping login
responses uninformative about which accounts exist.

**Done when:**

- `AC-001`: After 5 failed login attempts for an email address within 15
  minutes, further attempts for that address are refused for 15 minutes with
  status 429 and a `Retry-After` header.
- `AC-002`: Login does not reveal whether an account exists for an email
  address.

**Depends on:** None
