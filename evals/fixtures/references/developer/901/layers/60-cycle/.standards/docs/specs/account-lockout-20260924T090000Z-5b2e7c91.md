# Technical Design

## Context

- Login is `POST /auth/login` in `app/routers/auth.py`. It calls
  `authenticate_user` in `app/services/auth.py` and answers `401` with
  `Invalid email or password` when the result is `None`.
- The router already passes a `CounterStore` from
  `app/services/counter_store.py` as `store`: `RedisCounterStore` in production
  through `get_counter_store` in `app/dependencies.py`, and
  `InMemoryCounterStore` with an injected clock in unit tests.
  `authenticate_user` does not use it yet. Every store method raises
  `CounterStoreError` when the store fails.
- Modules under `app/services/` import only the standard library and other
  `app/services/` modules, so their unit tests run without FastAPI, redis, or
  SQLAlchemy (`.standards/CONTEXT.md`).

## Decision

- Add `AccountLockedError` to `app/services/auth.py`: an `Exception` subclass
  constructed as `AccountLockedError(retry_after)`, exposing `retry_after`, an
  `int` number of seconds until attempts for the address are accepted again.
  `authenticate_user` raises it while an email address is locked.
- Count failed attempts in the `CounterStore` that `authenticate_user` receives
  as `store`. How failed attempts are counted in the store, including whether a
  successful login resets an address's failed attempts, is an implementation
  detail for Developer.
- Add `login_lockout_threshold` (default `5`) and `login_lockout_seconds`
  (default `900`) to `Settings` in `app/config.py`, read from
  `LOGIN_LOCKOUT_THRESHOLD` and `LOGIN_LOCKOUT_SECONDS` like the existing
  settings.
- Add two keyword-only parameters to `authenticate_user`,
  `lockout_threshold: int = 5` and `lockout_seconds: int = 900`. The router
  passes `settings.login_lockout_threshold` and `settings.login_lockout_seconds`,
  so `app/services/` keeps importing only the standard library and
  `app/services/`.
- A `CounterStoreError` raised by the store propagates out of
  `authenticate_user`, so no login succeeds while the store fails. The router
  answers it with `503` and the detail `Login is temporarily unavailable`.
- The router maps `AccountLockedError` to `429` with a `Retry-After` header set
  from `retry_after`.

## Acceptance Coverage

- `AC-001`: `AccountLockedError`, failed-attempt counting in `store`, the two
  settings and keyword-only parameters, and the router's `429` mapping with
  `Retry-After`; the `503` mapping for `CounterStoreError`.
- `AC-002`: The router keeps its single existing `401` response for rejected
  credentials; the new `429` and `503` responses carry no account data.

## Interfaces and Contracts

- `authenticate_user(email, password, *, client_ip, users, store,
  lockout_threshold=5, lockout_seconds=900) -> User | None` returns the user for
  a correct password and `None` for rejected credentials, raises
  `AccountLockedError` while the email address is locked, and lets
  `CounterStoreError` from `store` propagate.
- `Settings.login_lockout_threshold: int` and `Settings.login_lockout_seconds:
  int` in `app/config.py`.
- `POST /auth/login`: `200` with the token and `401` with
  `Invalid email or password`, both unchanged; `429` with a `Retry-After`
  header for `AccountLockedError`; `503` with detail
  `Login is temporarily unavailable` for `CounterStoreError`.

## Technical Acceptance Criteria

- `AC-001`: After `lockout_threshold` failed attempts for an email address
  within `lockout_seconds`, `authenticate_user` raises `AccountLockedError` for
  further attempts for that address for `lockout_seconds`, and the router
  answers them with `429` and `Retry-After`.
- `AC-001`: When the store raises `CounterStoreError`, `authenticate_user`
  returns no user and the router answers `503` with
  `Login is temporarily unavailable`.
- `AC-002`: Rejected credentials keep the single existing `401` response.

## Build Plan

1. MODIFY `app/config.py`: add the two settings.
2. MODIFY `app/services/auth.py`: add `AccountLockedError`, the two
   keyword-only parameters, and failed-attempt counting in `store`.
3. MODIFY `app/routers/auth.py`: pass the two settings, map
   `AccountLockedError` to `429` and `CounterStoreError` to `503`.

## Risks and Follow-up

- The unit tests under `tests/unit/` import only `app/services/`; the router's
  new `429` and `503` mappings are not exercised by them.
