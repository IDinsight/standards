## Build Steps

### DEV-001 — Add account lockout to login

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Implement the technical design: `AccountLockedError(retry_after)` in
`app/services/auth.py`, failed-attempt counting in the `store` that
`authenticate_user` receives, the `lockout_threshold` and `lockout_seconds`
keyword-only parameters, the two lockout settings in `app/config.py`, and the
router's `429` and `503` responses.

**Affected Area**

`app/config.py`, `app/services/auth.py`, `app/routers/auth.py`.

**Expected Outcome**

After `lockout_threshold` failed attempts for an email address within
`lockout_seconds`, `authenticate_user` raises `AccountLockedError` for further
attempts for that address for `lockout_seconds`, and the router returns `429`
with `Retry-After`. A `CounterStoreError` from the store propagates out of
`authenticate_user`, and the router returns `503` with
`Login is temporarily unavailable`. The existing `401` response and the import
boundary of `app/services/` are unchanged.

**Self-Check**

Planned: `python3 -m pytest -q` from the project root, plus
`python3 -m py_compile app/config.py app/services/auth.py app/routers/auth.py`.
FastAPI is not installed in this environment, so the router change can be
checked only by compilation and inspection. Not yet run.
