# Technical Design

## Context

`app/utils/text.py` defines `slugify` and `truncate_words` using only the
standard library (`re`, `unicodedata`). Its only importers are
`app/reports/digest.py` and `scripts/export_digest.py` (see
`.standards/CONTEXT.md`). `app/core/` already holds `config.py`. The scope
requires the helpers to live in `app/core/text.py` with unchanged behavior.

## Decision

Move the module as is: create `app/core/text.py` with the current contents of
`app/utils/text.py`, change the two import statements to
`from app.core.text import ...`, and delete `app/utils/text.py`. No re-export is
kept at the old path, because nothing else in the repository imports it.
`app/utils/` keeps `__init__.py` and `dates.py`.

The change touches no route, request or response shape, schema, persistence,
or project setup.

## Acceptance Coverage

- `AC-001`: `app/core/text.py` holds the unchanged `slugify` and
  `truncate_words`; `app/reports/digest.py` and `scripts/export_digest.py`
  import them from `app.core.text`; `app/utils/text.py` is removed.

## Interfaces and Contracts

- `slugify(value: str) -> str` and
  `truncate_words(text: str, limit: int, suffix: str = "…") -> str` keep their
  signatures, defaults, and behavior.
- `build_digest` output and the export script's command line and output file
  names are unchanged.

## Technical Acceptance Criteria

- `AC-001`: `app.core.text` exposes both helpers with bodies identical to the
  current `app/utils/text.py`; no module in `app/`, `scripts/`, or `tests/`
  imports `app.utils.text`.

## Build Plan

1. `CREATE` `app/core/text.py` from `app/utils/text.py`; `MODIFY` the imports in
   `app/reports/digest.py` and `scripts/export_digest.py`; `DELETE`
   `app/utils/text.py`. Keep these in one step so the package always imports
   cleanly.

## Alternatives

- Keeping `app/utils/text.py` as a re-export of `app.core.text`: rejected;
  there are no other importers to protect.
