# Technical Design

## Context

apps/api is a uv-managed FastAPI service in the fieldwork monorepo, next to
apps/worker and packages/shared; it installs packages/shared through a uv path
source. The repository has no CI. The service's checks are the commands in
apps/api/README.md, recorded in .standards/CONTEXT.md. No project reference
applies.

## Decision

Add one GitHub Actions workflow for apps/api. The workflow is CI only: no
deployment, release, publishing, environments, or secrets. It runs the
service's existing uv commands with apps/api as the working directory and does
not change apps/api code, tests, dependencies, or tool configuration. Actions
are referenced by their major version tags, for example `actions/checkout@v4`,
not by commit SHA, so the team can read and update them at a glance.

A workflow dedicated to apps/api leaves apps/worker free to get its own CI later
without coupling the two.

## Acceptance Coverage

- `AC-001`: `.github/workflows/api-ci.yml` runs the lint, format, type-check,
  test, and build commands under **Interfaces and Contracts** in apps/api.
- `AC-002`: The test command under **Interfaces and Contracts** runs once for
  each of Python 3.11, 3.12, and 3.13; the `coverage.xml` each run writes is
  that run's coverage report.

## Components

- `.github/workflows/api-ci.yml`: the only new file.

## Interfaces and Contracts

Commands, each run in apps/api:

- Lint: `uv run ruff check .`
- Format: `uv run ruff format --check .`
- Type check: `uv run mypy app`
- Tests with coverage: `uv run pytest --cov=app --cov-report=xml`
- Build: `uv build`

Actions are referenced as `owner/action@vN` (major version tag), not by commit
SHA.

## Technical Acceptance Criteria

- `AC-001`: The workflow runs all five commands against apps/api, and a non-zero
  exit from any of them fails the run.
- `AC-002`: The test command runs under each of Python 3.11, 3.12, and 3.13, and
  each of those runs keeps its own `coverage.xml`.

## Build Plan

1. CREATE `.github/workflows/api-ci.yml`.

## Risks and Follow-up

- apps/worker and packages/shared still have no CI of their own; out of scope.

## Alternatives

- One workflow for every app in the repository: rejected for now; the scope
  covers apps/api only.
