# Survey API Continuous Integration

## Goal

Changes to apps/api reach main with no automated checks today; lint, typing,
test, and packaging problems surface only when someone runs the commands by
hand. Run the service's existing checks on GitHub for every change that can
affect it, so a broken change is visible on the push or pull request that
introduced it.

## Constraints

- Use the checks apps/api already defines (apps/api/README.md); do not add new
  tools or checks.
- apps/api supports Python 3.11 and later (requires-python in
  apps/api/pyproject.toml).
- apps/api depends on packages/shared from the same repository.

## Non-goals

- Deployment, release, or publishing of any package or image.
- CI for apps/worker or for packages/shared as products in their own right.
- Changes to apps/api code, tests, dependencies, or tool configuration.

## Work

### 1. Automated checks for apps/api

**Intent:** Give every change that can affect apps/api the same lint, type,
test, and build feedback as it reaches main, across the Python versions the
service supports.

**Done when:**

- `AC-001`: Every push and pull request to main that can affect apps/api runs
  lint, type checks, tests, and a build for apps/api.
- `AC-002`: The apps/api tests run on Python 3.11, 3.12, and 3.13, and each test
  run keeps its coverage report.

**Depends on:** None

## Assumptions

- The repository is hosted on GitHub with GitHub Actions enabled and
  GitHub-hosted runners available.
