# Import Jobs

## Goal

Today anyone can upload to `POST /imports`, a retried upload starts a second
import, and an unreadable file stays `running` forever. Uploads must be
authenticated and safe to retry, and partners must see imports that are
waiting or failed.

## Non-goals

- Retrying a failed import from the web page; deferred to a later cycle.
- Listing imports from other browser sessions.
- Changing how API tokens are issued.

## Work

### 1. Authenticated, retry-safe import submission

**Done when:**

- `AC-001`: POST /imports requires bearer authentication.
- `AC-002`: POST /imports accepts an optional Idempotency-Key header and
  returns 409 when the same key was already used with a different file.
- `AC-003`: POST /imports returns 202 with an ImportJob body, whose status is
  pending, running, failed, or done.

**Depends on:** None

### 2. Import status on the web page

**Done when:**

- `AC-004`: The web import page shows pending and failed imports.

**Depends on:** 1
