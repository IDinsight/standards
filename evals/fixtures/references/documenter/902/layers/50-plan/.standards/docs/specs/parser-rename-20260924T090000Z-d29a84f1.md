# Technical Design

## Context

`app/imports/parser.py` exposes `parse_csv(stream)`, which validates the header
and delegates row conversion to the module-private `_parse_rows(reader)`. A
repository search finds no caller of the helper outside the module. The parser
tests are in `tests/test_parser.py` and import only `parse_csv`, `ImportRow`,
and `ParseError`. Pytest is configured in `pyproject.toml` with
`testpaths = ["tests"]` and `pythonpath = ["."]`, so tests in subfolders are
collected without package files.

## Decision

Rename `_parse_rows` to `_read_rows` in place and update its single call site in
`parse_csv`; the body is unchanged. Move `tests/test_parser.py` to
`tests/imports/test_parser.py` unchanged with `git mv`. No `__init__.py` is
added, because the test file name stays unique under `tests/`. No public name,
signature, error message, route, setting, or command changes.

## Acceptance Coverage

- `AC-001`: Rename confined to `app/imports/parser.py`; `parse_csv` keeps its
  signature, return value, and `ParseError` messages, so callers in
  `app/imports/service.py` and the API are unaffected.
- `AC-002`: Test file moved to `tests/imports/` and collected by the existing
  pytest configuration.

## Technical Acceptance Criteria

- `AC-001`: `app/imports/parser.py` defines `_read_rows` and no longer defines
  `_parse_rows`; no module refers to the old name; the existing parser tests
  pass without edits.
- `AC-002`: `tests/imports/test_parser.py` exists, `tests/test_parser.py` does
  not, and the full test suite collects and passes the moved tests.

## Build Plan

1. MODIFY `app/imports/parser.py`: rename the helper and its call site.
2. Move the tests: DELETE `tests/test_parser.py` and CREATE
   `tests/imports/test_parser.py` with the same content (one `git mv`).

## Risks and Follow-up

- With no package files under `tests/`, a second `test_parser.py` elsewhere in
  `tests/` would collide on import; add package files if that ever happens.
