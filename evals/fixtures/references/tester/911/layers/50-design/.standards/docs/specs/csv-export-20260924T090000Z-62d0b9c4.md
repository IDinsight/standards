# Technical Design

## Context

The scope asks for a CSV export of tickets. Tickets are `Ticket` dataclasses in
`app/tickets/models.py`; `created_at` is a `datetime`. The project uses the
standard library only (`.standards/CONTEXT.md`). The export is independent of
the summaries feature.

## Decision

Add `app/exports/csv_export.py` with `export_tickets(tickets, stream)` built on
the standard `csv` module with its default `excel` dialect. The caller owns the
stream; the function does not open files. `csv.writer` is chosen over manual
joining because its quoting is what spreadsheet applications expect.

## Acceptance Coverage

- `AC-001`: `export_tickets` writes a header row and then one row per ticket in
  the fixed column order `id`, `title`, `status`, `created_at`.
- `AC-002`: `csv.writer` with the default `excel` dialect (`QUOTE_MINIMAL`)
  quotes any field containing a comma, double quote, carriage return, or line
  feed, and doubles embedded double quotes.

## Interfaces and Contracts

- `export_tickets(tickets, stream) -> None`: `tickets` is an iterable of
  `Ticket`; `stream` is a writable text stream. Callers writing to a file open
  it with `newline=""`.
- Columns and order: `id`, `title`, `status`, `created_at`. `id` is written as
  the csv module converts it with `str()`; `created_at` is written with
  `datetime.isoformat()`.
- Rows end with `\r\n`, the `excel` dialect default.

## Technical Acceptance Criteria

- `AC-001`: The first row is exactly `id,title,status,created_at`; each
  following row corresponds to one input ticket, in input order; an empty input
  produces only the header row.
- `AC-002`: Reading the output back with `csv.reader` returns every field value
  unchanged, including values that contain commas, double quotes, and line
  breaks.

## Build Plan

1. `CREATE app/exports/__init__.py` and `CREATE app/exports/csv_export.py` with
   `export_tickets`.

## Risks and Follow-up

- No HTTP route or output location is in scope; a later cycle can wire the
  export into a service.
