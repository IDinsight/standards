# Rates Client Caching Guide

## Goal

Integrators of rates-client need one place that explains how rates are cached
and how long a cached rate can be relied on, so they can choose `ttlSeconds`
and `maxEntries` for their workload without reading the source.

## Constraints

- Documentation-only cycle: permitted edits are a new guide at
  `docs/caching.md` and the README's Configuration section.
- Audience: application developers who call `RatesClient` from their own
  services.

## Non-goals

- Changing cache behavior, options, defaults, or tests.
- Documenting provider-specific `fetchRate` implementations.

## Work

### 1. Caching guide

**Intent:** Give integrators an accurate description of the cache so they can
configure it and know how fresh the rates they receive are.

**Done when:**

- `AC-001`: The guide explains what `RatesClient` caches, how the cache key is
  formed from the base and quote currencies, and how to configure `ttlSeconds`
  and `maxEntries`, including their defaults.
- `AC-002`: The guide states that a cached rate is guaranteed to expire
  `ttlSeconds` after it was fetched, so `getRate` never returns a rate older
  than `ttlSeconds`.
- `AC-003`: The guide explains how to clear the cache with `clearCache()` and
  when an integrator would do so.

**Depends on:** None

### 2. README link

**Intent:** Let readers of the README find the guide from the options list.

**Done when:**

- `AC-004`: The README Configuration section links to `docs/caching.md`.

**Depends on:** Work item 1.
