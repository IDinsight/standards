# Analyst Guide for tally

## Goal

Analysts on the operations team run `tally` against their CSV exports but have
only the README's single example and the command's help text to go on. Give
them a guide that explains how to use the existing command for everyday
summaries and how to recover when it reports an error.

## Constraints

- Documentation only: describe `tally` as it currently behaves. No changes to
  its source, tests, sample data, or packaging.
- The guide is a new Markdown file under `docs/`; `README.md` may gain a link to
  it. No other files change.
- Examples must use behavior the current command actually has.

## Non-goals

- New options, changed defaults, or reworded error messages.
- A contributor or developer guide.
- Publishing the guide outside the repository.

## Work

### 1. Accurate command reference

**Intent:** Analysts need a reference they can trust instead of trial and error.

**Done when:**

- `AC-001`: The guide documents every argument and option the current `tally`
  command accepts, with its default and allowed values, and every error message
  the command can print together with its exit status, all matching the current
  implementation.

**Depends on:** None

### 2. Guide written for analysts

**Intent:** The readers are analysts, not Python developers.

**Done when:**

- `AC-002`: The guide is written for analysts who run `tally` on their own CSV
  exports and know no Python: it explains how to run the command from a
  checkout, gives at least one worked example for each output format, and says
  how to read and recover from each error.

**Depends on:** Work item 1

## Assumptions

- Analysts have Python 3.10 or later available and run the command from a
  checkout of this repository.
