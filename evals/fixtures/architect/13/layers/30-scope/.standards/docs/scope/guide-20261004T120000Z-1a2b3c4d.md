# Authentication Error Guide

## Goal

Client developers building against the member portal API have no reference for
the authentication errors portal-auth returns, and work from trial and error.
Give them an accurate guide to the current error responses of sign-in and of
protected endpoints, so they can handle each case.

## Constraints

- Documentation cycle: describe existing behavior only. Source, tests, and
  configuration stay unchanged.
- Audience: client developers of the member portal; they see HTTP responses,
  not the source.
- Target: a new guide at `docs/auth-errors.md`.

## Non-goals

- Changing any status code, error code, or message.
- Documenting password hashing or token signing internals beyond what a client
  observes.
- Documenting the portal's other endpoints.

## Work

### 1. Authentication error guide

**Intent:** Let a client developer look up every authentication error response
and know what triggers it and what the response contains.

**Done when:**

- `AC-001`: The guide lists every error the sign-in endpoint returns, each with
  its HTTP status, error code, exact message text as currently implemented, and
  what triggers it.
- `AC-002`: The guide lists every error a protected endpoint returns for a
  missing, malformed, invalid, or expired bearer token, each with its HTTP
  status, error code, exact message text, and what triggers it.
- `AC-003`: The guide describes the error body shape and the retry information
  a locked account's response carries, as currently returned.

**Depends on:** None.
