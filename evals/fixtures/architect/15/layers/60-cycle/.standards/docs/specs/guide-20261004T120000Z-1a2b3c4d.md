# Technical Design

## Context

Documentation cycle for the existing `tally report` command
(`.standards/docs/scope/guide-20261004T120000Z-1a2b3c4d.md`). Facts below come
from `.standards/CONTEXT.md`, `tally/cli.py`, and `tally/ledger.py`. No
implementation, test, or example changes are permitted. No project references
apply.

## Decision

Document `tally report` as it behaves today. `docs/reports.md` is the single
guide for the command; the README usage section links to it rather than
repeating it.

## Acceptance Coverage

- `AC-001`: Command and error contracts under Interfaces and Contracts
  (`tally/cli.py` argument parsing and exit status, `tally/ledger.py`
  missing-file and invalid-amount errors).
- `AC-002`: Output contract under Interfaces and Contracts (`write_report` in
  `tally/report.py`).
- `AC-003`: No architectural impact — the README link is Documenter-owned
  prose.

## Interfaces and Contracts

- Command: `python3 -m tally report <ledger.csv> [--account NAME]`. The ledger
  is a CSV file with columns `date`, `account`, and `amount`. `--account`
  restricts the report to one account.
- Errors: a missing ledger file prints `tally: ledger file not found: <path>` to
  standard error and exits with status 2; an amount that cannot be read prints
  `tally: line N: invalid amount` and exits with status 2. Success exits 0.
- Output: one line per account, sorted by account name. Each line holds the
  account name and its total with two decimal places, separated by a tab. There
  is no header line.

## Technical Acceptance Criteria

- `AC-001`: The documented invocation, `--account` behavior, error messages,
  and exit statuses match `tally/cli.py` and `tally/ledger.py`.
- `AC-002`: The documented columns, separator, and ordering match
  `write_report` and `summarize` in `tally/report.py`.

## Risks and Follow-up

- `README.md` predates the guide; adding the link is Documenter's work.
