# Technical Design

## Context

`src/cli.js` exposes `run(argv, { stdout, stderr })`, which returns the exit
code; `src/export.js` holds `COLUMNS` and `toCsv`. Tests use `node:test` with
injected writers (see `.standards/CONTEXT.md`). No project references apply.

## Decision

Add `toJson(items)` beside `toCsv` in `src/export.js`, sharing `COLUMNS`, and a
`FORMATS` map from format name to formatter. `src/cli.js` parses
`--format <name>` and `--format=<name>` after `export`, defaults to `csv`, and
looks the name up in `FORMATS` before reading the input file. Keeping the
format table in the export module keeps the CLI free of per-format logic.

## Acceptance Coverage

- `AC-001`: `toJson` and `FORMATS` in `src/export.js`; `--format` parsing with
  default `csv` in `src/cli.js`.
- `AC-002`: No architectural impact — satisfaction depends on the
  Documenter-owned user guide `docs/export.md`.
- `AC-003`: Format lookup in `src/cli.js` before the input file is read; an
  unknown name writes a stderr message listing the `FORMATS` keys and returns
  exit code 2.

## Interfaces and Contracts

- `toJson(items) -> string`: `JSON.stringify` of objects whose keys are
  `COLUMNS` in order, two-space indent, trailing newline.
- `FORMATS`: own-property lookup only; `csv` and `json`.
- Exit codes: 0 on success; 2 for a usage error or an unsupported format (the
  existing usage code).

## Technical Acceptance Criteria

- `AC-001`: JSON output parses to an array whose objects have exactly the
  `COLUMNS` keys, with `quantity` a number.
- `AC-001`: With no `--format`, stdout is byte-identical to the previous CSV
  output.
- `AC-003`: For an unknown format nothing is written to stdout and the input
  file is not read.

## Build Plan

1. MODIFY `src/export.js`: add `toJson` and `FORMATS`.
2. MODIFY `src/cli.js`: parse `--format`, look up the formatter, update the
   usage text.
