# Technical Design

## Context

The scope adds semicolon-separated output (AC-001) and keeps the comma output
unchanged (AC-002). According to `.standards/CONTEXT.md`, `src/export.ts`
holds the pure functions `csvCell` and `toCsv`, which quote with a fixed comma
rule, and callers import them through `src/index.ts`.

## Decision

Add an optional delimiter to `toCsv` and `csvCell`, defaulting to comma. The
quoting rule depends on the selected delimiter, so a semicolon file does not
quote fields merely because they contain commas. Existing call signatures stay
valid.

## Acceptance Coverage

- `AC-001`: the `toCsv` option `delimiter: ';'`, the header and row joining
  rule, and delimiter-specific quoting in `csvCell` (Interfaces and
  Contracts).
- `AC-002`: comma default for both functions, with the pre-cycle quoting rule
  unchanged.

## Components

- `src/export.ts`: new `Delimiter` and `CsvOptions` types; `csvCell` and
  `toCsv` gain the delimiter. `exportFileName` is unchanged. No other module
  changes; `src/index.ts` already re-exports everything in `src/export.ts`.

## Interfaces and Contracts

- `type Delimiter = ',' | ';'`.
- `csvCell(value: string | number, delimiter: Delimiter = ','): string`. With
  `,`, a field containing `,`, `"`, CR, or LF is quoted (the pre-cycle rule).
  With `;`, a field containing `;`, `"`, CR, or LF is quoted; a comma alone
  does not cause quoting. Quoting encloses the field in double quotes and
  doubles each double quote inside it.
- `toCsv(records, options?: { delimiter?: Delimiter }): string`. The header row
  is `COLUMNS` joined with the delimiter; each record row is its fields in
  `COLUMNS` order, passed through `csvCell` with the same delimiter and joined
  with it; every row, including the last, ends with CRLF. Without `options` or
  `delimiter`, the delimiter is `,`.
- The delimiter is enforced by the type only; there is no runtime validation,
  because the only callers are TypeScript modules in the admin service.

## Technical Acceptance Criteria

- `AC-001`: `toCsv(records, { delimiter: ';' })` joins the header row and every
  record row with `;`, and every row ends with CRLF.
- `AC-001`: With `;`, a field containing `;`, `"`, CR, or LF is enclosed in
  double quotes with each embedded `"` doubled, and a field whose only special
  character is a comma is written unquoted.
- `AC-002`: `toCsv(records)` and `csvCell(value)` called without a delimiter
  return exactly what they returned before this cycle.

## Build Plan

1. Delimiter-aware quoting in `csvCell`.
2. `delimiter` option in `toCsv`.

## Risks and Follow-up

- A JavaScript caller passing another delimiter value is not rejected at
  runtime.
- The README's API section does not yet describe the option.
