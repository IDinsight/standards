### DEV-001 — Delimiter-aware field quoting

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002`

**Goal**

Quote a field according to the selected delimiter.

**Affected Area**

`src/export.ts` (`csvCell`, new `Delimiter` type).

**Expected Outcome**

`csvCell(value, delimiter = ',')` quotes a value containing the delimiter, a
double quote, CR, or LF and doubles embedded double quotes. Calls without a
delimiter behave exactly as before.

**Self-Check**

- `npm test` in the project root at commit
  `${COMMIT:Add semicolon delimiter to CSV export}` (clean working tree,
  Node 22, offline): exit 0; 12 tests passed, 0 failed.
- Manual calls in a Node 22 REPL at that commit: `csvCell('Rent; utilities', ';')`
  returned the value enclosed in double quotes, and
  `csvCell('Lease agreement, Building B', ';')` returned it unquoted.

### DEV-002 — Delimiter option for toCsv

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-001, AC-002`

**Goal**

Let `toCsv` produce semicolon-separated output on request.

**Affected Area**

`src/export.ts` (`toCsv`, new `CsvOptions` type).

**Expected Outcome**

`toCsv(records, { delimiter: ';' })` joins the header row and each record row
with `;` and passes the delimiter to `csvCell`; rows still end with CRLF.
`toCsv(records)` is unchanged.

**Self-Check**

- `npm test` in the project root at commit
  `${COMMIT:Add semicolon delimiter to CSV export}`: exit 0; 12 tests passed,
  0 failed.
- Manual call in a Node 22 REPL at that commit: `toCsv` with two records and
  `{ delimiter: ';' }` printed a semicolon-separated header and rows, each
  ending with CRLF.
