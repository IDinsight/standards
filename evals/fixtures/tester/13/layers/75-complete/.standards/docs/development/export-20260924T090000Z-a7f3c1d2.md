### DEV-002 — Streaming export through a cursor in one transaction

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-001, AC-002`

**Goal**

Replace the load-everything export with the design's batched, transactional
export.

**Affected Area**

`packages/export/src/export.js`; unit tests in
`packages/export/test/unit/export.test.js` and the integration test
`packages/export/test/integration/export.test.js` as self-check harnesses.

**Expected Outcome**

`exportRecords(db, filter, outputPath, { batchSize })` (default 500) rejects
an unknown status or an invalid batch size before sending any statement;
otherwise it begins a transaction, inserts the `export_jobs` row, declares
`export_cursor` over the listing query, writes the header and each
`FETCH FORWARD` batch to `<outputPath>.partial` with the existing `csv.js`
functions until a short batch, closes the cursor, sets `row_count` and
`finished_at`, renames the file into place, commits, and resolves with
`{ jobId, path, rowCount }`.

**Self-Check**

- `pnpm --filter export test` in the project root at commit
  `${COMMIT:Stream CSV exports through a cursor inside an export job transaction}`
  (clean working tree, Node 22): exit 0; 13 tests passed, 0 failed.
- The integration run recorded under DEV-001, including
  `test/integration/export.test.js` (owner filter, batch size 1, file
  contents, and the `export_jobs` row).

### DEV-003 — Rollback and file cleanup on failure

`Status`: `DONE` `Depends On`: `DEV-002` `Acceptance`: `AC-001`

**Goal**

Leave nothing behind when an export fails.

**Affected Area**

`packages/export/src/export.js` (error path).

**Expected Outcome**

Any error after `BEGIN` closes the open file, removes `<outputPath>.partial`
and, if it was already renamed, `outputPath`, issues `ROLLBACK`, and rethrows
the original error.

**Self-Check**

- The unit run recorded under DEV-002 at the same commit, including the
  failed-fetch and unwritable-output-path scenarios in
  `packages/export/test/unit/export.test.js`: both pass.
