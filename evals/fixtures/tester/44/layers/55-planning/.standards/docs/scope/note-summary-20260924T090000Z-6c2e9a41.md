# Note Summaries

## Goal

API clients want a short summary of a stored note without reading the whole
text. The service already has an LLM client; this change exposes a summary of
an existing note through the notes API.

## Constraints

- Summaries come from the existing LLM client in `app/llm/client.py`.

## Non-goals

- Storing, caching, or regenerating summaries.
- Changing the LLM client, its configuration, or its error types.
- Evaluating summary quality.

## Work

### 1. Summary endpoint

**Intent:** Give API clients a summary of an existing note, and a clear,
retryable response when the provider is too slow.

**Done when:**

- `AC-001`: A valid `POST /notes/{id}/summary` request for an existing note
  returns status 200 with the summary produced by the LLM client.
- `AC-002`: When the LLM provider times out, `POST /notes/{id}/summary`
  returns status 503 with a message telling the caller to retry.

**Depends on:** None
