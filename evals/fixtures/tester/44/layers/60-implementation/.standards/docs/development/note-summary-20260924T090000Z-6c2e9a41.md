### DEV-001 — Note summary route

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002`

**Goal**

Expose a summary of an existing note through the notes router, using the
injected LLM client and the error mapping in the design.

**Affected Area**

`app/notes/router.py` (MODIFY): new `summarize_note` handler; imports from
`app/llm/client.py`, which is unchanged.

**Expected Outcome**

`POST /notes/{note_id}/summary` returns 200 with `note_id` and the client's
summary; 404 for a missing note without calling the client; 503 with the retry
detail and `Retry-After: 5` on `LLMTimeoutError`; 502 for any other
`LLMError`.

**Self-Check**

`python3 -m pytest -q` in the project root on the working tree with the new
handler, before the commit that adds it: exit 0, 7 passed (existing notes and
client tests; none exercise the new route). Manual check in a Python shell:
called `summarize_note` with a stub client returning a string and with one
raising `LLMTimeoutError`; got the expected dictionary and an `HTTPException`
with status 503 and `Retry-After: 5`.
