# CSV Export of Records

## Goal

Administrators of the records admin tool need to take the list they are
looking at, after filtering it by status, owner, or title text, into a
spreadsheet. The service should produce that list as a CSV file that
spreadsheet programs read correctly even when titles contain commas, quotes,
or line breaks. The people who run the service also need to know what the
export leaves on the server: where the files go, what they are called, and
how long they stay.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Listing records keeps its current behavior.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing or removing previously created export files.
- Changes to the admin tool's front end.
- Deciding which roles may export. The user moved access rules for every
  route, export included, to separate access-policy work; the existing role
  check on the export route stays as it is.

## Work

### 1. Filtered CSV export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV; a field containing a comma, double quote, or newline is quoted per RFC 4180, with embedded double quotes doubled.

**Depends on:** None

### 2. Operations guide for export files

**Intent:** Give the people who run the service what they need to look after
the files the export leaves on the server.

**Done when:**

- `AC-004`: The repository contains an operations guide for export files that states where the service writes them and how to change that folder, how the files are named, that the service never removes them, and that two exports in the same second share a name, so the later file replaces the earlier one.

**Depends on:** 1

## Retired Acceptance Identifiers

- `AC-002`: An export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is created. Retired at the user's direction during final review: access rules for export moved to separate access-policy work.
- `AC-003`: The user guide (`docs/usage.md`) explains where export files are written. Retired before this revision was completed: the user asked for a separate operations guide instead, and AC-004 replaces it.

## Assumptions

- Export files are kept by the service; how the admin tool offers them for
  download is outside this repository.
