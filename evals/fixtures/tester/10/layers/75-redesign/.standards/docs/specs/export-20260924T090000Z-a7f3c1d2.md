# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) and an
operations guide for the files the export leaves on the server (AC-004). The
scope revision made during final review retired AC-002, the
administrator-only condition, and left the existing role check on the export
route as it is; its coverage and criterion are removed from this design.
According to `.standards/CONTEXT.md`, route handlers are synchronous functions
registered on `Router` and exercised in-process; `parseFilter` and
`RecordStore.list` already implement the listing filters; nothing wrote to
disk before this cycle. Seed titles contain a comma and double quotes.

## Decision

Add `POST /records/export`. The handler authorizes with `requireAdmin` before
anything else (as built), reuses `parseFilter` and `RecordStore.list` so an
export contains exactly what `GET /records` lists for the same query,
serializes with a quoting function, writes the CSV to a file in a
configurable export folder, and returns the same CSV as the response body.
POST is used because the request creates a file.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format and
  quoting rules, and the export file location (Interfaces and Contracts).
- `AC-004`: No architectural impact. The guide describes behavior this design
  already fixes: the export folder and the `exportDir` option, file naming,
  that files are never removed, and same-second replacement (Interfaces and
  Contracts; Risks and Follow-up). Documenter owns the guide.

## Components

- `src/export.ts`: `csvCell`, `toCsv`, `exportFileName`, and `writeExport`. It
  knows nothing about users or requests.
- `src/routes/export.ts`: `registerExportRoutes(router, store, { exportDir, now })`.
- `src/app.ts`: `createApp` options `exportDir` (default `exports`) and `now`
  (default: the current time), passed to `registerExportRoutes`.

## Interfaces and Contracts

- Route: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  request body is ignored.
- Authorization: the handler calls `requireAdmin` first, as built. No
  signed-in user gives 401 and an editor or viewer gives 403 (the existing
  `authorize` responses). This is existing behavior; after the scope revision
  it does not back a current acceptance condition of this cycle.
- Invalid `status`: 400 from `parseFilter`; no file is written.
- Success: status 201; headers `content-type: text/csv; charset=utf-8` and
  `content-disposition: attachment; filename="<file name>"`; the body is
  identical to the written file.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are.
- File location: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC
  time returned by `now()` for the request. `exportDir` is created when
  missing; a relative `exportDir` resolves against the process working
  directory. `exports/` is listed in `.gitignore`. The service never removes
  export files.

## Data and Control Flow

`Router.handle` calls the export handler: `requireAdmin(request.user)`, then
`parseFilter(request.query)`, `store.list(filter)`, `toCsv`, folder creation
and file write, and the 201 response. An `HttpError` thrown before the write
ends the request with its status and leaves the file system unchanged.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format above
  requires, and the response body equals the written file.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. File naming and writing.
3. Route, `createApp` options, and the `.gitignore` entry.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces
  the earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.

## Alternatives

- `GET /records/export` returning CSV without keeping a file: rejected because
  the scope keeps export files in the service for the admin tool to hand out.
