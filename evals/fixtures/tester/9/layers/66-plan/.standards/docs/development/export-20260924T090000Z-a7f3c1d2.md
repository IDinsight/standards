## Build Steps

### DEV-001 — CSV formatting

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Format records as the CSV the design defines.

**Affected Area**

New `app/export.py` (`write_csv`); unit tests in `tests/test_export.py` as
the self-check harness.

**Expected Outcome**

`write_csv(records, out)` writes the header `id,title,owner,status,created_at`
and one CRLF-terminated row per record in the given order, quoting fields
that contain a comma, double quote, CR, or LF and doubling embedded quotes,
and returns the number of records written.

**Self-Check**

`python -m pytest -m "not integration"` in the project root.

### DEV-002 — Snapshot export through the streaming cursor

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-001, AC-002`

**Goal**

Stream the matching records into `write_csv` from one transaction snapshot.

**Affected Area**

`app/export.py` (`export_csv`); `tests/integration/test_export_db.py` as the
self-check harness.

**Expected Outcome**

`export_csv(conn, record_filter, out, batch_size)` runs in one transaction
set to `REPEATABLE READ, READ ONLY` before the first read, passes the rows
from `iter_records` to `write_csv`, and returns the number of records
written.

**Self-Check**

`python -m pytest -m integration` against the compose database; inspect the
statement order inside the transaction.

### DEV-003 — Export command

`Status`: `PENDING` `Depends On`: `DEV-002` `Acceptance`: `AC-001`

**Goal**

Let operators run an export from the command line.

**Affected Area**

New `app/cli.py`.

**Expected Outcome**

`python -m app.cli export [--status S] [--owner O] [--q TEXT]` validates the
filter with `parse_filter`, exits with status 2 and its message when it is
invalid, and otherwise writes the CSV to standard output.

**Self-Check**

Run the command with an invalid status, and with a valid filter against the
compose database.
