# CSV Export of Records

## Goal

Staff who filter the records list need to take the result into a
spreadsheet. The service should write the matching records as CSV that
spreadsheet programs read correctly even when titles contain commas, quotes,
or line breaks. Exports can be large and records keep changing while one
runs, so an export must describe the records as they were at a single moment.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records.
- Listing records keeps its current behavior.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled
  exports.
- Offering exports for download in the admin tool.

## Work

### 1. Filtered CSV export

**Intent:** Let staff save exactly the records they filtered.

**Done when:**

- `AC-001`: An export writes every record matching the listing filters as CSV, with a header row and records in ascending id order; a field containing a comma, double quote, or line break is quoted per RFC 4180, with embedded double quotes doubled.

**Depends on:** None

### 2. Consistent exports

**Intent:** Keep an export trustworthy while other people edit records.

**Done when:**

- `AC-002`: An export reflects a single point in time: records added, changed, or removed by other sessions after the export starts reading do not change its contents.

**Depends on:** 1

## Assumptions

- Operators run exports from the command line; handing the file to the admin
  tool is outside this repository.
