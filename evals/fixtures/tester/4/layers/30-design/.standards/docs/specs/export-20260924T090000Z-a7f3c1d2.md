# Technical Design

## Context

Per `.standards/CONTEXT.md`, `src/csv.ts` already writes CSV for the
bulk-import rejection report but does not quote line breaks; `parseFilter`
and `RecordStore.list` implement the listing filters; `requireAdmin` is
unused.

## Decision

Add `POST /records/export`: `requireAdmin` first, then `parseFilter` and
`RecordStore.list`, so the export holds exactly what `GET /records` lists,
written with the existing `formatRow`. Extend the shared quoting rule in
`src/csv.ts` to CR and LF so every CSV the service writes follows RFC 4180,
instead of adding a second CSV writer.

## Acceptance Coverage

- `AC-001`: export route, CSV format, and extended quoting rule (Interfaces
  and Contracts).
- `AC-002`: `requireAdmin` as the handler's first step; the router maps its
  `HttpError` to 401 or 403 with a JSON error and no CSV.

## Components

- `src/csv.ts` (changed): the quoting rule also matches CR and LF.
- `src/export.ts` (new): `toCsv(records)`.
- `src/routes/export.ts` (new): `registerExportRoutes(router, store)`,
  registered in `src/app.ts`.

## Interfaces and Contracts

- `POST /records/export` with the `GET /records` query filters; body ignored.
  Admin only: 401 without a user, 403 for editor or viewer; 400 for an
  unknown status.
- Success: 200, `content-type: text/csv; charset=utf-8`, attachment
  `content-disposition` named `records.csv`, CSV body.
- CSV: header `id,title,owner,status,createdAt`, rows in ascending id, CRLF
  after every row. A field containing a comma, double quote, CR, or LF is
  enclosed in double quotes with inner quotes doubled.

## Technical Acceptance Criteria

- `AC-001`: Exported rows equal the `GET /records` rows for the same query,
  in order.
- `AC-001`: `parseCsv` reads every exported field back unchanged.
- `AC-002`: No user or a non-admin role gets 401 or 403 and no record data.

## Build Plan

1. Quoting rule in `src/csv.ts`.
2. `toCsv`.
3. Route and registration.

## Risks and Follow-up

- `escapeCell` also writes the import rejection report: a rejected cell with
  a line break is now quoted there too, which `parseCsv` already reads.
