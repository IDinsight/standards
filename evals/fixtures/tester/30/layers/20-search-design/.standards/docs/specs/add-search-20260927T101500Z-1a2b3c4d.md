# Technical Design

## Context

The library stores contacts in `Directory` (`src/directory.js`), whose `list()`
already returns contacts sorted by `name`. There is no search support.

## Decision

Add a module `src/search.js` with pure functions `matches(contact, query)` and
`search(contacts, query)`. `Directory` gains a `search(query)` method that
delegates to `search` over `list()`. Keeping matching pure lets it be reused
without a `Directory` instance.

## Acceptance Coverage

- `AC-001`: `matches` tests the trimmed, lowercased query as a substring of the
  lowercased `name`.
- `AC-002`: `matches` applies the same rule to `email`; a missing email is
  treated as an empty string.
- `AC-003`: `search` returns an empty array when the query is empty after
  trimming and sorts results by `name` with `localeCompare`.

## Interfaces and Contracts

- `matches(contact, query) -> boolean`.
- `search(contacts, query) -> Contact[]`: returns a new array and does not
  mutate its input.
- `Directory#search(query) -> Contact[]`: same results as `search(list(), query)`.

## Technical Acceptance Criteria

- `AC-001`, `AC-002`: Matching is substring-based after `trim()` and
  `toLowerCase()` of the query, applied to both name and email.
- `AC-003`: Result order equals `Directory#list()` order for the matched
  contacts.

## Build Plan

1. Matching helpers in `src/search.js`.
2. Ordering and blank-query handling in `search`.
3. `Directory#search` wiring.
