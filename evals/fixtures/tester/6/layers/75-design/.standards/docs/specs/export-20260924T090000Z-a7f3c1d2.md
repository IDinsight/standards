# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) that only
administrators may use, enforced by server-side authorization (AC-002), and
whose successful responses name the requesting administrator (AC-003, added
by the user's rework during final review). According to
`.standards/CONTEXT.md`, route handlers are synchronous functions registered
on `Router` and exercised in-process; `parseFilter` and `RecordStore.list`
already implement the listing filters; `requireAdmin` returns the user it
authorizes; nothing wrote to disk before this cycle. Seed titles contain a
comma and double quotes.

## Decision

Add `POST /records/export`. The handler authorizes with `requireAdmin` before
anything else and keeps the user it returns, reuses `parseFilter` and
`RecordStore.list` so an export contains exactly what `GET /records` lists for
the same query, serializes with a new quoting function, writes the CSV to a
file in a configurable export folder, and returns the same CSV as the response
body with a header naming that administrator. POST is used because the request
creates a file.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format and
  quoting rules, and the export file location (Interfaces and Contracts).
- `AC-002`: `requireAdmin` as the handler's first step; the router maps its
  `HttpError` to 401 or 403, and no folder is created and no file is written
  before it returns.
- `AC-003`: the `x-exported-by` response header, filled from the user that
  `requireAdmin` returns.

## Components

- `src/export.ts` (new): `csvCell`, `toCsv`, `exportFileName`, and
  `writeExport`. It knows nothing about users or requests.
- `src/routes/export.ts` (new): `registerExportRoutes(router, store, { exportDir, now })`,
  the only place the export's authorization and attribution happen.
- `src/app.ts`: new `createApp` options `exportDir` (default `exports`) and
  `now` (default: the current time), passed to `registerExportRoutes`.

## Interfaces and Contracts

- Route: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  request body is ignored.
- Authorization: administrators only, through `requireAdmin(request.user)`.
  No signed-in user gives 401 `{"error": "authentication required"}`; an
  editor or viewer gives 403 `{"error": "forbidden"}` (the existing
  `authorize` responses).
- Invalid `status`: 400 from `parseFilter`; no file is written.
- Success: status 201; headers `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="<file name>"`, and
  `x-exported-by: <name>`, where `<name>` is the `name` of the user returned by
  `requireAdmin`; the body is identical to the written file. The file name and
  file contents do not change for attribution.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are. `id` is written in
  decimal and `createdAt` as stored.
- File location: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC
  time returned by `now()` for the request. `exportDir` is created when
  missing; a relative `exportDir` resolves against the process working
  directory. `exports/` is listed in `.gitignore`.

## Data and Control Flow

`Router.handle` calls the export handler: `const admin = requireAdmin(request.user)`,
then `parseFilter(request.query)`, `store.list(filter)`, `toCsv`, folder
creation and file write, and the 201 response carrying `admin.name` in
`x-exported-by`. An `HttpError` thrown before the write ends the request with
its status and leaves the file system unchanged.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format above
  requires, and the response body equals the written file.
- `AC-002`: A request with no user or with a non-admin role receives 401 or
  403, and no export folder or file is created.
- `AC-003`: Every 201 export response carries `x-exported-by` equal to the
  `name` of the administrator returned by `requireAdmin`.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. File naming and writing.
3. Route, `createApp` options, and the `.gitignore` entry.
4. Attribution header on the export response, from the user `requireAdmin`
   returns.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces
  the earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.

## Alternatives

- `GET /records/export` returning CSV without keeping a file: rejected because
  the scope keeps export files in the service for the admin tool to hand out.
- Writing the administrator into the file name or the CSV: rejected; the file
  format stays as documented and the admin tool reads the response header.
