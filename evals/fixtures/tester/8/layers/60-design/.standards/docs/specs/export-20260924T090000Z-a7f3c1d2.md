# Technical Design

## Context

The scope adds a CSV export of the filtered records list that is stored in the
company document archive (AC-001), limited to administrators by server-side
authorization (AC-002), and answered within a configurable export time limit
(AC-003). According to `.standards/CONTEXT.md`, route handlers are synchronous
functions registered on `Router` and exercised in-process; `parseFilter` and
`RecordStore.list` already implement the listing filters; `requireAdmin`
exists but no route uses it; the service makes no outbound calls today and has
no archive client. Seed titles contain a comma and double quotes.

## Decision

Add `POST /records/export`. The handler authorizes with `requireAdmin` before
anything else, reuses `parseFilter` and `RecordStore.list` so an export
contains exactly what `GET /records` lists for the same query, serializes with
a new quoting function, uploads the CSV to the document archive through a new
archive client, and responds with the stored file's location. `Router` learns
to accept handlers that return a promise, so existing synchronous handlers are
unchanged. Archive uploads that fail with a network error or a 5xx response
are retried, so that brief archive unavailability does not fail an export.
POST is used because the request creates a file.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format and
  quoting rules, the archive upload, and the 201 response (Interfaces and
  Contracts).
- `AC-002`: `requireAdmin` as the handler's first step; the router maps its
  `HttpError` to 401 or 403, and no archive request is made before it returns.
- `AC-003`: the `exportTimeoutMs` export time limit (default 30000) applied to
  archive uploads, retry of transient upload failures, and the 504 response
  (Interfaces and Contracts: Archive client, Retry, Timeout).

## Components

- `src/export.ts` (new): `csvCell`, `toCsv`, and `exportFileName`. It knows
  nothing about users, requests, or the archive.
- `src/archive.ts` (new): `createArchiveClient(baseUrl, send?)` returning a
  client with `put(name, csv, timeoutMs)`. `send` defaults to the global
  `fetch`; tests supply their own.
- `src/routes/export.ts` (new): `registerExportRoutes(router, store, options)`,
  the only place the export's authorization, retry, and mapping of archive
  failures to responses happen.
- `src/http/router.ts`: a handler may return `Promise<AppResponse>`; a rejected
  promise is mapped to a response the same way as a thrown error.
- `src/app.ts`: new `createApp` options `archive`, `exportTimeoutMs`,
  `retryDelayMs`, and `now`, passed to `registerExportRoutes`.

## Interfaces and Contracts

- Route: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  request body is ignored.
- Authorization: administrators only. No signed-in user gives 401
  `{"error": "authentication required"}`; an editor or viewer gives 403
  `{"error": "forbidden"}` (the existing `authorize` responses).
- Invalid `status`: 400 from `parseFilter`; nothing is sent to the archive.
- Archive client: `put(name, csv, timeoutMs)` sends
  `PUT <ARCHIVE_URL>/files/<name>` with `content-type: text/csv; charset=utf-8`
  and the CSV as the body. The archive answers 201 with JSON
  `{"location": "<url>"}`. Any other status, or a request that fails without a
  response, is an archive error carrying the status (none for a network
  failure). `ARCHIVE_URL` comes from the environment (default
  `http://archive.internal`); `createApp` may be given a client instead.
- Retry: an archive error with a 5xx status or no status is retried after
  `retryDelayMs` (default 1000). Other archive errors are not retried and give
  502 `{"error": "archive rejected the export: <detail>"}`.
- Timeout: `exportTimeoutMs` is the export time limit in milliseconds (default
  30000). An archive upload that does not complete within the export time
  limit is abandoned and the request receives 504
  `{"error": "export did not complete"}`.
- Success: status 201, JSON `{"fileName": ..., "location": ..., "count": ...}`
  where `location` is the value the archive returned and `count` the number of
  exported records.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are.
- File name: `records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC time returned by
  `now()` for the request.

## Data and Control Flow

`Router.handle` calls the export handler: `requireAdmin(request.user)`, then
`parseFilter(request.query)`, `store.list(filter)`, `toCsv`, the archive upload
(retried on a transient archive error), and the 201 response. An `HttpError`
thrown before the upload ends the request with its status and nothing is sent
to the archive.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order,
  quoted and escaped as the CSV format above requires.
- `AC-001`: The PUT body is the CSV, and the response gives the location the
  archive returned.
- `AC-002`: A request with no user or with a non-admin role receives 401 or
  403, and no archive request is made.
- `AC-003`: An archive upload that exceeds the export time limit ends the
  request with 504 and `{"error": "export did not complete"}`.

## Build Plan

1. Serialization and file naming.
2. Archive client.
3. Promise support in `Router`, the export route, and the `createApp` options.

## Risks and Follow-up

- The archive is unavailable for short periods during its nightly
  maintenance; the retry covers these.
- Two exports in the same second share a file name; the archive keeps the
  later file. Accepted for this internal tool.

## Alternatives

- Writing export files to local disk for the admin tool to collect: rejected
  because the scope requires the file to be stored in the document archive.
