# CSV Export to the Document Archive

## Goal

Administrators of the records admin tool need to file the list they are
looking at, after filtering it by status, owner, or title text, in the company
document archive as a CSV file that spreadsheet programs read correctly even
when titles contain commas, quotes, or line breaks. An export must not leave
the admin tool waiting indefinitely when the archive is slow or unavailable:
it either finishes or fails within a known time. Export files hold record
data, so only administrators may create them.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.
- The export time limit is set per deployment and defaults to 30 seconds.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled
  exports.
- Listing, replacing, or deleting files already in the archive.
- Changes to the archive itself or to the admin tool's front end.

## Work

### 1. Filtered CSV export to the archive

**Intent:** Let administrators file exactly the records they filtered as a
CSV file in the document archive.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as a CSV file stored in the document archive; a field containing a comma, double quote, or newline is quoted per RFC 4180, with embedded double quotes doubled, and the response identifies the stored file.

**Depends on:** None

### 2. Administrator-only access

**Intent:** Keep record data in exported files limited to administrators.

**Done when:**

- `AC-002`: An export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before anything is sent to the archive.

**Depends on:** 1

### 3. Bounded export time

**Intent:** Keep the admin tool responsive when the archive is slow or
unavailable.

**Done when:**

- `AC-003`: Every export request receives a response within the configured export time limit; when the file has not been stored in the archive by then, the request fails with status 504 and an error saying the export did not complete.

**Depends on:** 1

## Assumptions

- The archive's address is supplied by each deployment.
