# Technical Design

## Context

Brownfield pnpm workspace. `packages/core` builds report rows from item
objects; `packages/cli` formats them. This cycle adds an optional `reorderAt`
integer to items.

## Decision

- Add `packages/core/src/lowStock.js` exporting `DEFAULT_REORDER_AT` (5),
  `reorderPoint(item)`, `isLowStock(item)`, and `lowStock(items)`, re-exported
  from `packages/core/src/index.js`.
- `reorderPoint` returns `item.reorderAt` when it is set (including 0) and
  `DEFAULT_REORDER_AT` when it is absent or null.
- An item is low stock when its quantity is less than or equal to
  `reorderPoint(item)`.
- `reportRows` adds a boolean `lowStock` to each row; existing fields and sku
  ordering are unchanged.
- The CLI `report` command accepts `--low-stock`, which prints only rows whose
  `lowStock` is true, sorted by quantity ascending with ties by sku. The summary
  line is unchanged.

## Acceptance Coverage

- `AC-001`: `isLowStock` comparison and the `lowStock` flag on report rows.
- `AC-002`: `reorderPoint` fallback to `DEFAULT_REORDER_AT`.
- `AC-003`: `--low-stock` option in `packages/cli/src/main.js`, using the row flag.

## Interfaces and Contracts

- `lowStock(items)` returns objects with `sku`, `quantity`, and the effective
  `reorderAt`, in input order.

## Technical Acceptance Criteria

- `AC-001`: `isLowStock` is true exactly when quantity is less than or equal to the effective threshold; `reportRows` sets `lowStock` from it.
- `AC-002`: An item without `reorderAt`, or with `reorderAt` null, is evaluated against 5.
- `AC-003`: `run(['report', file, '--low-stock'])` output contains only low-stock rows in ascending quantity order, then the unchanged summary line.
