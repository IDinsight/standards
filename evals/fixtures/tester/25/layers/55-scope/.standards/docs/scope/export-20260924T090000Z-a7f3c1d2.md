# Script-friendly Export CLI and CSV Download

## Goal

Operators run the export CLI from scheduled jobs and shell pipelines, which
need the CSV on standard output, diagnostics kept apart from the data, and
exit statuses they can act on; today the CLI insists on an output file,
prints its summary where data would go, and fails with tracebacks. People on
the records page cannot download the list they filtered, and a new control
must work for keyboard and screen reader users, including when an export
fails.

## Constraints

- The CSV content (columns, order, quoting) stays as it is.
- Writing to a file with `--output PATH` keeps working.
- The export is produced by the records service's existing export endpoint.

## Non-goals

- New columns or formats, progress reporting, and changes to the service.

## Work

### 1. Script-friendly CLI output

**Intent:** Let scripts pipe the CSV, see problems without corrupting data,
and branch on the result.

**Done when:**

- `AC-001`: Run without an output file, the export CLI writes the CSV to standard output and nothing else there, while diagnostics and error messages go to standard error; it exits 0 on success, 1 when the records dump cannot be used or the output cannot be written (with a one-line error message, no traceback, and no output file created), and 2 when the command line is invalid.

**Depends on:** None

### 2. Accessible download on the records page

**Intent:** Let people save the filtered list, including people who use only
the keyboard or a screen reader.

**Done when:**

- `AC-002`: The records page has a Download CSV button that exports the records matching the current filter and works with a mouse and with the keyboard; when an export fails, the reason is announced as an alert, keyboard focus moves to that message, and the button can be used again.

**Depends on:** None
