# CSV Export with Download Links

## Goal

Administrators of the records admin tool need the list they are looking at,
after filtering it by status, owner, or title text, as a CSV file they can
open in a spreadsheet. Each export is kept by the service and reachable
through its own download URL, so the file can be fetched again later without
repeating the export.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing, expiring, or removing previously created export files.
- Changes to the admin tool's front end.

## Work

### 1. Export access and download links

**Intent:** Keep export files under the service's control and make each one
retrievable through its download URL.

**Done when:**

- `AC-001`: Exports are private: only administrators can create an export or download an export file, and a request from any other role or with no signed-in user is denied by the service.
- `AC-002`: Anyone who has an export's download URL can download the file anonymously, without signing in.

**Depends on:** 2

### 2. Export contents

**Intent:** Give administrators exactly the records they filtered, in a form
spreadsheet programs read correctly.

**Done when:**

- `AC-003`: An export contains the records matching the listing filters as CSV, one row per record under a header row, with any field containing a comma, double quote, or newline quoted per RFC 4180 and embedded double quotes doubled.

**Depends on:** None

## Assumptions

- How the admin tool presents the download URL to its users is outside this
  repository.
