# Technical Design

## Context

The scope adds a CSV export of the filtered records list that the service
keeps as a file, plus a download URL for each export. According to
`.standards/CONTEXT.md`, route handlers are synchronous functions registered
on `Router` with exact path matching (no path parameters) and exercised
in-process; `parseFilter` and `RecordStore.list` already implement the listing
filters; `requireAdmin` exists but no route uses it; nothing writes to disk
today. Seed titles contain a comma and double quotes.

## Decision

Add two routes. `POST /records/export` authorizes with `requireAdmin` before
anything else, reuses `parseFilter` and `RecordStore.list` so an export holds
exactly what `GET /records` lists for the same query, writes the CSV to a file
in a configurable export folder, and returns the file name and its download
URL. `GET /exports/download` serves an existing export by the file name
carried in that URL. POST is used for creation because the request creates a
file; the file name travels in the query because the router has no path
parameters.

## Acceptance Coverage

- `AC-001`: `requireAdmin` as the first step of `POST /records/export`; the
  router maps its `HttpError` to 401 or 403, and no folder or file is created
  before it returns.
- `AC-002`: `GET /exports/download` serves an existing export by the file name
  in its download URL, with no authorization step; `POST /records/export`
  returns that URL.
- `AC-003`: the listing filters on `POST /records/export` and the CSV format
  and quoting rules (Interfaces and Contracts).

## Components

- `src/export.ts` (new): `csvCell`, `toCsv`, `exportFileName`,
  `isExportFileName`, `writeExport`, and `readExport`. It knows nothing about
  users or requests.
- `src/routes/export.ts` (new):
  `registerExportRoutes(router, store, { exportDir, now })` registers both
  routes; `downloadUrl(fileName)` builds the URL.
- `src/app.ts`: new `createApp` options `exportDir` (default `exports`) and
  `now` (default: the current time), passed to `registerExportRoutes`.

## Interfaces and Contracts

- Create: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  request body is ignored. Administrators only: no signed-in user gives 401
  `{"error": "authentication required"}`, an editor or viewer gives 403
  `{"error": "forbidden"}`. An invalid `status` gives 400 and writes no file.
  Success: status 201 with JSON
  `{"file": "<file name>", "count": <rows>, "url": "/exports/download?file=<file name>"}`.
- Download: `GET /exports/download?file=<file name>`. A name that is not of
  the form `records-<YYYYMMDDTHHMMSSZ>.csv` gives 400
  `{"error": "invalid export file name"}`; a well-formed name with no file
  gives 404 `{"error": "export not found"}`. Success: status 200, headers
  `content-type: text/csv; charset=utf-8` and
  `content-disposition: attachment; filename="<file name>"`, body equal to the
  file. No signed-in user is required.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are.
- File location: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC
  time returned by `now()` for the request. `exportDir` is created when
  missing; a relative `exportDir` resolves against the process working
  directory. `exports/` is listed in `.gitignore`. The strict file-name form
  keeps downloads inside `exportDir`.

## Data and Control Flow

Create: `requireAdmin(request.user)`, then `parseFilter(request.query)`,
`store.list(filter)`, `toCsv`, folder creation and file write, and the 201
response. An `HttpError` thrown before the write ends the request with its
status and leaves the file system unchanged. Download: validate the name, read
the file, and return it.

## Technical Acceptance Criteria

- `AC-001`: A `POST /records/export` request with no user or with a non-admin
  role receives 401 or 403, and no export folder or file is created.
- `AC-002`: `GET /exports/download?file=<name>` for an existing export returns
  200 with the file's CSV for any request, including one with no signed-in
  user.
- `AC-003`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same
  order, and every field is quoted and escaped as the CSV format requires.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. File naming, writing, and reading.
3. Creation route, `createApp` options, and the `.gitignore` entry.
4. Download route.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces
  the earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.
