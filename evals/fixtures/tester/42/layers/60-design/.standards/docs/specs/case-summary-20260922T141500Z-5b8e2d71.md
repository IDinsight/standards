# Technical Design

## Context

The provider client in `app/llm/client.py` and the `Summary` model
(`case_summaries`) already exist; no route uses them yet (see
`.standards/CONTEXT.md`). Case routes live in `app/cases/router.py`, where
`_owned_case` returns 404 for a missing or non-owned case.

## Decision

Add one async route to `app/cases/router.py`. It receives the client through
FastAPI's `Depends(get_llm_client)`, forces a `record_summary` tool call, parses
the tool arguments, and inserts a `Summary` only after a valid summary is
parsed. The client, models, and migrations do not change.

## Acceptance Coverage

- `AC-001`: Route, `record_summary` tool contract, argument parsing, and the
  201 response built from the stored row.
- `AC-002`: `RateLimitedError` mapped to 503 with `Retry-After`; nothing is
  inserted before parsing succeeds.
- `AC-003`: Argument parsing failure mapped to 502; nothing is inserted.

## Interfaces and Contracts

- `POST /cases/{case_id}/summary`, bearer auth through `CurrentUser`. A missing
  or non-owned case returns 404 `{"detail": "Case not found"}` from
  `_owned_case`.
- LLM boundary: `LLMClient.complete(messages=..., tools=[SUMMARY_TOOL],
  tool_choice=...)` returns `Completion`; `Completion.tool_calls` is a list of
  `ToolCall(name, arguments)`, where `arguments` is the provider's JSON string
  unchanged.
- Tool `record_summary`: object parameters with a required string `summary`.
- Success: 201 with `{"id", "case_id", "summary", "created_at"}`; `summary` is
  the parsed `summary` argument with surrounding whitespace removed and equals
  the stored `case_summaries.text`.
- Rate limit: the client raises `RateLimitedError`, whose `retry_after` is
  always an integer number of seconds. Response 503 with header
  `Retry-After: <retry_after>` and body
  `{"detail": "Summary service is busy; try again later."}`.
- Invalid tool output (no `record_summary` call, arguments that are not valid
  JSON, or no non-empty string `summary`): 502 with
  `{"detail": "Summary service returned an invalid summary."}`.
- Any other `LLMError`: 502 with `{"detail": "Summary service is unavailable."}`.
- Persistence: one insert and commit, only after parsing succeeds.

## Technical Acceptance Criteria

- `AC-001`: The response `summary` equals the stored row's `text`, and exactly
  one `case_summaries` row exists for the case afterwards.
- `AC-002`: `Retry-After` equals `RateLimitedError.retry_after`; no
  `case_summaries` row is written.
- `AC-003`: No `case_summaries` row is written.

## Build Plan

1. MODIFY `app/cases/router.py`: add the route, the `record_summary` tool
   definition, argument parsing, and the response model.

## Risks and Follow-up

- The client disables SDK retries (`max_retries=0`) and the route does not
  retry; callers retry after `Retry-After`.
