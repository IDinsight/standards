## Build Steps

### DEV-001 — Case summary endpoint

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002, AC-003`

**Goal**

Add `POST /cases/{case_id}/summary`: ask the model to call `record_summary`
for the owned case, store the parsed summary, and map provider failures to the
designed responses.

**Affected Area**

`app/cases/router.py` only. Reuses `get_llm_client`, `LLMClient`,
`RateLimitedError`, and `LLMError` from `app/llm/client.py`, the existing
`Summary` model, and `_owned_case`. No client, model, or migration changes.

**Expected Outcome**

The owner gets 201 with `{"id", "case_id", "summary", "created_at"}` and one
new `case_summaries` row. A `RateLimitedError` returns 503 with `Retry-After`
set to its `retry_after`; arguments that are not valid JSON, or a missing
`record_summary` call, return 502. Neither failure writes a row.

**Self-Check**

Live sanity check on the author's workstation, project root, with a personal
provider key in `.env`: `uv run uvicorn app.main:app`, then a `curl -X POST`
to `/cases/1/summary` with the owner's bearer token for a seeded case. Result:
HTTP 201 with a two-sentence summary, and the row was present in
`case_summaries`; one request to the live provider API. Assessed content: the
`app/cases/router.py` committed with this plan. Limitation: the rate-limit and
invalid-arguments branches were not exercised; no automated tests were added
or run.

**Implementation Notes**

`tool_choice` forces `record_summary`. The client runs with SDK retries
disabled, so a provider 429 reaches the route once as `RateLimitedError`.
