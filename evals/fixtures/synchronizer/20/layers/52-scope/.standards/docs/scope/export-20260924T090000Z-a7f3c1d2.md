# Partner Export: Accounts Feed Source

## Goal

The billing system's nightly TSV dump is being retired in favor of the
accounts service's new feed, a JSON Lines file. The weekly partner export must
take its accounts from the feed while partners keep receiving the same file.
When the feed cannot be read, the export must fail visibly instead of leaving
a partial partner file. Operators learn how the export runs from the
operations guide, so the guide must describe the new source as it actually
works.

## Constraints

- The partner file layout (header, columns, active accounts only, order by
  account id, ISO dates) does not change.
- The operations guide stays in `docs/operations.md`.

## Non-goals

- Changes to the partner file layout or to its delivery to partners.
- Reading both sources, or falling back to the dump.
- Validating account content beyond what building the file needs.

## Work

### 1. Read accounts from the feed

**Intent:** Move the export off the retiring dump without partners noticing.

**Done when:**

- `AC-001`: The export builds the partner file from the accounts feed `data/feed/accounts.jsonl` and no longer reads the billing system's dump; for the same accounts, the partner file has the same header, rows, order, and date values as before.

**Depends on:** None

### 2. Fail without a partial file

**Intent:** Never hand operations a partner file built from part of the feed.

**Done when:**

- `AC-002`: When the feed is missing or a line of it cannot be read, the export stops with an error that names the feed file (and the line number for an unreadable line), exits with a non-zero status, and leaves no output file.

**Depends on:** 1

### 3. Operations guide

**Intent:** Operators can run and troubleshoot the export from the guide.

**Done when:**

- `AC-003`: The operations guide `docs/operations.md` accurately describes the feed as the export's source, including its location, the fields the export uses, and what happens when the feed cannot be read.

**Depends on:** 1, 2

## Assumptions

- The accounts service publishes the feed as a file that production mounts at
  `data/feed/accounts.jsonl`, as the billing drop is mounted today.
