# Technical Design

## Context

The scope moves the partner export from the billing system's TSV dump to the
accounts feed without changing the partner file (AC-001), requires a failed
feed read to stop the export without leaving an output file (AC-002), and
requires the operations guide to describe the feed (AC-003). According to
`.standards/CONTEXT.md`, the source is chosen only in `make_source()` in
`partner_export/settings.py`, sources yield `Account` values that
`partner_export/export.py` turns into the partner file, and the project uses
the Python standard library only. The current `write_export` opens the output
file before it reads any account.

## Decision

Replace `TsvDumpSource` with `JsonlFeedSource`, a source with the same
`accounts()` interface that reads the feed with the `json` module, and point
`make_source()` at it. Remove the dump source, its test, and the sample dump,
so nothing reads the dump by accident. Make `write_export` read every account
before it opens the output file, and have the command line turn a feed error
into an error message and exit status 1.

## Acceptance Coverage

- `AC-001`: `JsonlFeedSource`, `FEED_PATH` and `make_source()`, removal of the dump source, and the unchanged partner file contract (Interfaces and Contracts).
- `AC-002`: `FeedError`, reading before writing in `write_export`, and the command-line error contract.
- `AC-003`: No architectural impact. Satisfaction depends on Documenter updating `docs/operations.md` from the contract below once the implementation exists.

## Components

- `partner_export/sources.py`: `JsonlFeedSource` and `FeedError` replace
  `TsvDumpSource`.
- `partner_export/settings.py`: `FEED_PATH` (`<project root>/data/feed/accounts.jsonl`)
  replaces `DUMP_PATH`; `make_source()` returns `JsonlFeedSource(FEED_PATH)`.
- `partner_export/export.py`: `write_export` builds every row first.
- `partner_export/__main__.py`: error handling.
- `data/feed/accounts.jsonl` (new sample data) replaces
  `data/legacy/accounts.tsv`.

## Interfaces and Contracts

- Feed format: UTF-8, one JSON object per line; lines containing only
  whitespace are skipped. Required fields `id` (integer), `name`, `country`,
  `status`, and `updated_at` (ISO 8601 timestamp with a UTC offset; `Z` is
  allowed). Other fields are ignored.
- Mapping to `Account`: `account_id` is `int(id)`; `name` is stripped;
  `country` is upper-cased; `status` is lower-cased; `updated_on` is the UTC
  calendar day of `updated_at`. The dump's `updated` was already a UTC day, so
  `updated_on` keeps its meaning.
- `FeedError(path, line, reason)`: raised for a line that is not valid JSON,
  is not an object, lacks a required field, or has an invalid `id` or
  `updated_at` (including one without an offset). Its message is
  `<path>:<line>: <reason>`, with `line` counted from 1.
- Partner file: unchanged. Header `account_id,name,country,updated_on`; active
  accounts only; ascending `account_id`; `updated_on` as YYYY-MM-DD; `csv`
  module quoting and CRLF rows.
- `write_export(accounts, out_path)`: consumes `accounts` completely before
  opening `out_path`; an exception from the source propagates and no file is
  created.
- Command line: `python3 -m partner_export OUTPUT.csv`. On `FeedError` or
  `OSError` (including a missing feed file) it prints `error: <message>` to
  standard error and returns 1; a usage error keeps exit 2; success prints
  `wrote <path>` and returns 0.

## Data and Control Flow

`main` calls `make_source()` and passes `source.accounts()` to
`write_export`. `export_rows` reads the feed line by line until it ends; only
then is the output file opened and written. An error at any line ends the run
before the output file exists.

## Technical Acceptance Criteria

- `AC-001`: `make_source()` returns `JsonlFeedSource(FEED_PATH)`, and no module, test, or data file for the dump remains.
- `AC-001`: For accounts with the same values, the partner file is byte for byte what the dump produced: header, active accounts in id order, and `updated_on` as the UTC day.
- `AC-002`: A missing feed or an unreadable line makes the command print an error naming the feed file (and the 1-based line for a line error), return 1, and create no output file.

## Build Plan

1. Feed source and error type.
2. Point settings at the feed; remove the dump source, its test, and the
   sample dump; add the sample feed.
3. Read before write in `write_export`, and command-line error handling.

## Risks and Follow-up

- The whole feed is read before writing; current volumes are a few thousand
  accounts, so memory use is not a concern.
- Production must mount the accounts service drop at `data/feed/` before the
  first run; that is an operations step outside this repository.

## Alternatives

- Keeping `TsvDumpSource` as a fallback: rejected; the scope excludes reading
  both sources.
- Writing to a temporary file and renaming it: rejected as more moving parts
  than reading first at these volumes.
