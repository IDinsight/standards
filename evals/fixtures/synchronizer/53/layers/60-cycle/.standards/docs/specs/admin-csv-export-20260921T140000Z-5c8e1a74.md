# Technical Design

## Context

Brownfield records API (see `.standards/CONTEXT.md`): handlers are functions
that take a request object and return `{ status, headers, body }`, and
`src/csv.js` already implements RFC 4180 quoting. The session layer sets
`req.user` to the authenticated account `{ id, roles }` or `null`; service
tokens are accounts with no `roles` array.

## Decision

Add `exportHandler(store)` in a new `src/export.js` and a reusable
`isAdmin(user)` predicate in a new `src/auth.js`. The handler decides
authorization before reading the store, so a refused request never touches
record data.

## Acceptance Coverage

- `AC-001`: `exportHandler` serializes `store.list()` with `toCsv` using the
  fixed column list `id`, `title`, `owner`, `updatedAt`, with content type
  `text/csv; charset=utf-8`.
- `AC-002`: an `isAdmin(req.user)` gate in `exportHandler`, evaluated before
  `store.list()`; the refusal is a fixed JSON error body.

## Interfaces and Contracts

- `isAdmin(user)` returns a boolean: true only when `user.roles` is an array
  containing `admin`. It never throws; a `null` user or an account without
  `roles` is not an administrator.
- `exportHandler(store)(req)` returns 200 with the CSV body and
  `content-disposition: attachment; filename="records.csv"`, or 403 with an
  `application/json` body whose `error` is `forbidden`.

## Technical Acceptance Criteria

- `AC-001`: The CSV body equals
  `toCsv(store.list(), ['id', 'title', 'owner', 'updatedAt'])`.
- `AC-002`: For every request whose user is not an administrator, including a
  missing user or an account without roles, the handler returns 403 without
  calling `store.list()` and without throwing.

## Build Plan

1. CREATE `src/auth.js` with `isAdmin`.
2. CREATE `src/export.js` with `exportHandler`, using `isAdmin` and `toCsv`.
