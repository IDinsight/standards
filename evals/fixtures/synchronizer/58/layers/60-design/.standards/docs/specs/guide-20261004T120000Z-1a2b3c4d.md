# Technical Design

## Context

Documentation cycle for the existing `ledgerline` CLI (see
`.standards/CONTEXT.md`). This design records the existing contracts the guide
must describe; it proposes no implementation change.

## Decision

The guide describes `bin/ledgerline.js`, `src/parse.js`, and `src/summary.js`
as committed in `${COMMIT:Add ledgerline import and summary commands}`. Where
the README and the code differ in detail, the code is authoritative.

## Acceptance Coverage

- `AC-001`: statement-file and `import` contracts below (`src/parse.js`, the
  `import` branch of `bin/ledgerline.js`).
- `AC-002`: `summary` contract below (`src/summary.js`, the `summary` branch of
  `bin/ledgerline.js`).
- `AC-003`: exit-code contract below (`bin/ledgerline.js`).

## Interfaces and Contracts

- Statement file: UTF-8 CSV; the first non-blank line must be
  `date,description,amount` (case-insensitive, spaces around names ignored);
  dates are `YYYY-MM-DD`; amounts are decimal, negative for spending; every line
  is split on every comma and must have exactly three fields; blank lines are
  ignored.
- `import <file.csv>`: parses the whole file and prints
  `Read <n> entries from <file>`. It stores nothing.
- `summary <file.csv> --month YYYY-MM`: prints `<month>: <n> entries`, then
  income (sum of amounts of zero or more), spending (sum of negative amounts as
  a positive number), and net (income minus spending), each with two decimals.
- Exit codes: `0` success; `1` usage error (unknown command or missing file
  argument, which print the usage line, or `summary` without a `--month`
  value); `2` `--month` is not a valid `YYYY-MM` month; `3` the file cannot be
  read, the header is wrong, or an entry cannot be read.

## Technical Acceptance Criteria

- `AC-001`: the guide's format rules and `import` example agree with
  `parseStatement` and the `import` branch.
- `AC-002`: the guide's `summary` example agrees with the output of
  `monthSummary` and `formatCents` for `examples/statement.csv`, month `2026-08`.
- `AC-003`: the guide's exit-code list matches the four codes above and their
  conditions.

## Risks and Follow-up

- `import` only validates and counts; readers may expect it to save data. The
  guide must say that it does not.
