# Technical Design

## Context

Per `.standards/CONTEXT.md`, `run()` in `src/cli.js` parses options with
`node:util` `parseArgs` in strict mode, so an option missing from its table is
rejected through the existing error path (exit 2, message on standard error).
The scope replaces `--json` with `--format` (AC-001), requires the removed flag
and unknown formats to fail with exit 2 and no output (AC-002), and requires
the usage guide to document the option (AC-003).

## Decision

Add a string option `format` with default `csv`, validate it against a
`FORMATS` list, and pick the serializer from a map keyed by format. Remove
`json` from the option table, so strict parsing rejects `--json` like any
unknown option. Validation happens before records are filtered or any output
is produced.

## Acceptance Coverage

- `AC-001`: `--format` option with default `csv` and the serializer map
  (Interfaces and Contracts).
- `AC-002`: `json` removed from the option table; format validation before any
  write.
- `AC-003`: No architectural impact. Satisfaction depends on Documenter
  updating `docs/usage.md` once the implementation exists.

## Components

- `src/cli.js`: option table, `FORMATS`, serializer map, validation order, and
  usage text. `src/csv.js` and `src/records.js` do not change.

## Interfaces and Contracts

- `--format <csv|json>`: optional, default `csv`. `csv` output is
  `toCsv(records)`, unchanged. `json` output is
  `JSON.stringify(records, null, 2)` followed by a newline, the same content
  `--json` produced.
- `--json`: removed. `parseArgs` reports it as an unknown option; `run()` writes
  the parser's message and the usage summary to standard error and returns 2.
- Any other `--format` value: `unknown format: <value>` and the usage summary
  on standard error; `run()` returns 2.
- In every failure case nothing is written to standard output and no `--out`
  file is created.
- The usage summary lists `--format <csv|json>` and not `--json`.

## Technical Acceptance Criteria

- `AC-001`: For the same filters, `--format csv` output equals the default
  output, and `--format json` output equals what `--json` produced before.
- `AC-002`: `--json` or an unknown format returns 2 before any serializer runs
  or any file is opened.

## Build Plan

1. Add `--format` and the serializer map.
2. Remove `--json`, add format validation, and update the usage text.

## Risks and Follow-up

- Scripts that pass `--json` stop working; the scope accepts this without a
  deprecation period.
