# Technical Design

## Context

`toCsv(rows)` in `src/csv.js` derives columns from the keys of the first row
and quotes fields through the private `cell` helper (`.standards/CONTEXT.md`).
No project references apply.

## Decision

Add an optional second parameter `options` with a `columns` array. When
`columns` is present it fully determines the header and the field order; each
value is looked up by key, and a missing key yields `undefined`, which `cell`
already writes as an empty field. When `columns` is absent, keep the current
derivation unchanged. Unknown column names are not validated.

## Acceptance Coverage

- `AC-001`: `options.columns` determines header and row field order in `toCsv`.
- `AC-002`: the per-key lookup yields `undefined` for a missing key, and `cell`
  writes it as an empty field.
- `AC-003`: the default path is untouched when `options.columns` is undefined.

## Interfaces and Contracts

- `toCsv(rows, options = {})` returns a string. `options.columns` is an optional
  array of column names. With columns and no rows, the result is the header line
  only. Without columns and no rows, the result is an empty string.

## Technical Acceptance Criteria

- `AC-001`: the header is the quoted `columns` joined by commas, and each row
  has exactly `columns.length` fields in that order.
- `AC-002`: a missing key produces an empty field and the row keeps its field
  count.
- `AC-003`: `toCsv(rows)` output is identical to the previous behavior,
  including an empty string for empty input.
