# Technical Design

## Context

Documentation cycle for the `rates` CLI. Existing behavior is recorded in
`.standards/CONTEXT.md`; no implementation changes are in scope.

## Decision

Document the CLI contract from `bin/rates.js` and the pricing rule from
`src/rates.js` as they stand at ${COMMIT:Initial rates CLI}, in a single guide
at `docs/guide.md`.

## Acceptance Coverage

- `AC-001`: CLI contract in `bin/rates.js`: positional `<weight-kg> [zone]`,
  default zone `domestic`, output `quote(...).toFixed(2)` on stdout with no
  currency symbol.
- `AC-002`: `ZONES` table in `src/rates.js` (base 4.50 / per kg 1.20 domestic,
  7.00 / 2.10 regional, 15.00 / 4.75 international) and billable weight
  `Math.ceil(weightKg * 2) / 2`, price rounded to cents.
- `AC-003`: Missing weight prints the usage line on stderr and exits 2;
  `quote()` errors (`unknown zone: <zone>`, `weight must be positive`) print on
  stderr and exit 1. A non-numeric weight becomes `NaN` and reports
  `weight must be positive`.

## Interfaces and Contracts

- Evidence sources: `src/rates.js`, `bin/rates.js`, and
  `test/rates.test.js`; examples in the guide must be reproducible with
  `node bin/rates.js`.

## Risks and Follow-up

- Prices carry no currency; the guide must not invent one.
