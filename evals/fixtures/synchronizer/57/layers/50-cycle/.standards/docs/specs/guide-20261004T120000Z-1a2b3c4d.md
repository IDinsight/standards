# Technical Design

## Context

Documentation cycle for the existing `tally` CLI (see `.standards/CONTEXT.md`).
No implementation changes. Behavior evidence: `tally/__main__.py`,
`tally/ledger.py`, `data/expenses.csv`, and the existing tests in `tests/`.

## Decision

Document the CLI contracts below as they exist today. The guide stays a single
file, `docs/usage.md`, with commands run from the repository root using
`python3`.

## Acceptance Coverage

- `AC-001`: Input contract below (`REQUIRED_COLUMNS` and `load_rows` in
  `tally/ledger.py`).
- `AC-002`: `summary` contract below.
- `AC-003`: `check` and exit-status contract below.

## Interfaces and Contracts

- Input contract: the header must contain `date`, `category`, and `amount`;
  other columns are ignored. Amounts are parsed as `Decimal`; category
  whitespace is stripped. Dates are not parsed: month grouping takes the first
  seven characters, so `YYYY-MM-DD` is the expected form.
- `summary PATH [--by category|month]`: default grouping `category`; prints the
  key and total separated by a tab, one line per key, sorted by key; exit 0.
- `check PATH [--strict]`: prints `ok: <N> rows` and exits 0. With `--strict`,
  rows with a blank category produce `error: blank category on line(s) ...` on
  standard error and exit 1.
- Read failures (missing file, missing column, non-numeric amount) print
  `error: <reason>` on standard error and exit 2; argparse usage errors also
  exit 2.

## Technical Acceptance Criteria

- `AC-002`: Example output in the guide is exactly what the commands print for
  `data/expenses.csv`, apart from how the tab renders.
- `AC-003`: Documented exit statuses agree with `main` in `tally/__main__.py`.

## Risks and Follow-up

- `check --strict` and its exit status 1 are existing behavior that the scope
  does not require the guide to cover.
