# Technical Design

## Context

The scope adds an administrator-only CSV export of the filtered records list
(AC-001, AC-002); guide changes are a non-goal. Per `.standards/CONTEXT.md`,
handlers are synchronous `Router` functions, `parseFilter` and
`RecordStore.list` implement the filters, and `requireAdmin` exists unused.

## Decision

Add `POST /records/export`: `requireAdmin` first, then `parseFilter` and
`store.list`, serialize to CSV, write the file to a configurable export
folder, and return the same CSV. POST because the request creates a file.

## Acceptance Coverage

- `AC-001`: the route, CSV format, quoting rules, and file location below.
- `AC-002`: `requireAdmin` as the handler's first step; 401 or 403 before any
  folder or file is created.

## Interfaces and Contracts

- `src/export.ts`: `csvCell`, `toCsv`, `exportFileName`, `writeExport`.
  `src/routes/export.ts`: `registerExportRoutes`. `createApp` gains
  `exportDir` (default `exports`) and `now`.
- Query parameters and validation are those of `GET /records`.
- No user: 401 `authentication required`; editor or viewer: 403 `forbidden`;
  invalid `status`: 400; no file in any of these cases.
- Success: 201, `content-type: text/csv; charset=utf-8`, an attachment
  `content-disposition` naming the file, body identical to the file.
- CSV: header `id,title,owner,status,createdAt`, rows in ascending `id`, CRLF
  after every row. A field containing a comma, a double quote, CR, or LF is
  enclosed in double quotes with inner double quotes doubled (RFC 4180).
- File: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv` in UTC; folder created
  when missing; `exports/` is gitignored.

## Technical Acceptance Criteria

- `AC-001`: exported rows equal what `GET /records` returns for the same
  query, in the same order.
- `AC-001`: every field is quoted as required above, and the body equals the
  written file.
- `AC-002`: no user or a non-admin role receives 401 or 403, and no export
  folder or file is created.

## Risks and Follow-up

- Two exports in the same second share a file name; accepted.
