# Technical Design

## Context

The scope requires a filtered CSV export (AC-001) restricted to
administrators, with other requests rejected before any file is written
(AC-002). Per `.standards/CONTEXT.md`, handlers are synchronous `Router`
functions; `parseFilter` and `RecordStore.list` implement the listing filters;
`requireAdmin` exists unused. The expedited phase added `csvCell`/`toCsv` and
a `format=csv` branch on `GET /records`, both non-baseline.

## Decision

Add `POST /records/export`: `requireAdmin` first, then `parseFilter` and
`RecordStore.list`, serialization with the existing `csvCell`/`toCsv`, a file
written to a configurable export folder, and the same CSV as the response
body. This is the export's only entry point: the expedited `format=csv`
branch is removed and `GET /records` returns JSON only, as before the cycle.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format,
  and the file location (Interfaces and Contracts).
- `AC-002`: `requireAdmin` as the export handler's first step and no other
  route returning export data; no folder or file is created before it passes.

## Components

- `src/export.ts`: `csvCell`, `toCsv` (kept); new `exportFileName`,
  `writeExport`.
- `src/routes/export.ts` (new): `registerExportRoutes(router, store, { exportDir, now })`.
- `src/routes/records.ts`: back to the pre-cycle handler; `format=csv` branch
  removed.
- `src/app.ts`: `createApp` options `exportDir` (default `exports`) and `now`.

## Interfaces and Contracts

- `POST /records/export` with the `GET /records` filters and validation.
- No user: 401 `authentication required`; editor or viewer: 403 `forbidden`;
  invalid `status`: 400, no file.
- Success: 201, `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="<file name>"`, body equal to
  the file.
- CSV: header `id,title,owner,status,createdAt`, rows in ascending `id`, CRLF
  after every row; a field with a comma, double quote, CR, or LF is quoted and
  its quotes doubled (RFC 4180).
- File: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC of `now()`), folder
  created when missing, `exports/` gitignored.
- `GET /records`: JSON only.

## Technical Acceptance Criteria

- `AC-001`: Exported rows equal what `GET /records` returns for the same
  query, in the same order.
- `AC-001`: Fields are quoted as above and the body equals the written file.
- `AC-002`: No user or a non-admin role gets 401 or 403 and no export folder
  or file is created. No other route returns records as CSV.

## Build Plan

1. Keep `csvCell`/`toCsv`; add tests for double quotes and line breaks.
2. File naming and writing.
3. Route, `createApp` options, `.gitignore`, and removal of the `format=csv`
   branch.

## Risks and Follow-up

- Two exports in the same second share a file name; accepted.

## Alternatives

- Keeping `GET /records?format=csv`: rejected; it shares the listing's
  every-role authorization and keeps no file.
