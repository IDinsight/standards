# Export Authorization Regression Tests

## Goal

Export files contain record data, and only administrators may create them.
The service enforces this today, but no automated test fails if a later change
lets a signed-out user, a viewer, or an editor export, or lets a refused
request leave an export file behind. This change adds regression tests that
pin that behavior, so the project's regular test run catches such a change.

## Constraints

- The export code and its behavior stay as they are; this change adds tests
  only.
- The tests run offline with the project's existing test command and leave no
  files in the repository.

## Non-goals

- Changes to the export route, roles, or the documented export behavior.
- New tests for successful administrator exports beyond the existing ones.

## Work

### 1. Refused export requests are pinned by tests

**Intent:** A change that weakens who may export, or that writes files for a
refused request, is caught before it ships.

**Done when:**

- `AC-001`: The test suite fails if an export request from no signed-in user is not rejected with 401, or an export request from a viewer or an editor is not rejected with 403, each with its documented error body.
- `AC-002`: The test suite fails if a refused export request creates the export folder or writes an export file.

**Depends on:** None

### 2. Part of the regular test run

**Intent:** The new tests protect the behavior only if they run whenever the
project's tests run.

**Done when:**

- `AC-003`: The new tests run as part of `npm test`, and the change modifies no source file, configuration, or existing test.

**Depends on:** 1
