# Technical Design

## Context

The scope asks for regression tests that pin who may export (AC-001), that a
refused export writes nothing (AC-002), and that the tests run in the existing
test command with no change to the export code (AC-003). Per
`.standards/CONTEXT.md`, the export handler calls `requireAdmin` before
`parseFilter`, `store.list`, and `writeExport`; only `writeExport` creates the
export folder; and `createApp` accepts `exportDir` and `now`, so a test can
point each request at its own temporary folder.

## Decision

Add one end-to-end regression suite next to the existing export flow tests,
driving `createApp` in-process. No production code, configuration, or
existing test changes: the current seams already make refused requests
observable through the response and the export folder.

## Acceptance Coverage

- `AC-001`: refused-request cases in the regression suite for no user, a
  viewer, and an editor, asserting the status and error body defined below.
- `AC-002`: every refused case uses its own temporary export folder and
  asserts that the folder still does not exist after the request; one case
  combines a viewer with an invalid `status`, so the role check is shown to
  come before filter validation and before any write.
- `AC-003`: the suite lives at `test/integration/export-access.test.js`, which
  the existing `test/integration/*.test.js` pattern in `npm test` already
  runs.

## Interfaces and Contracts

- Behavior under test (unchanged): `POST /records/export`. No user gives 401
  `{"error": "authentication required"}`; `editor` or `viewer` gives 403
  `{"error": "forbidden"}`; a refused request creates neither the export
  folder nor a file. A viewer request with `status=deleted` gives 403, not
  400.
- Test boundary: `createApp({ exportDir, now })` with each `exportDir` under a
  folder created in `os.tmpdir()` and removed when the suite finishes; nothing
  is written inside the repository.

## Technical Acceptance Criteria

- `AC-001`: each refused case asserts both the status code and the JSON error
  body.
- `AC-002`: each refused case asserts the absence of its export folder after
  the request, so a change that creates the folder or writes a file before or
  despite the role check fails the suite.
- `AC-003`: apart from workflow records, the change touches only
  `test/integration/export-access.test.js`, and `npm test` runs it.

## Build Plan

1. Developer confirms the existing seams; no production change is planned.
2. Tester adds and runs the regression suite.

## Risks and Follow-up

- The suite depends on the `exportDir` option of `createApp`; a later change
  to that option must update the suite.
