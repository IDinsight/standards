# CSV Export of Records

## Goal

Administrators need to take the records list they filtered into a
spreadsheet. The service should produce it as a CSV file that spreadsheet
programs read correctly even when titles contain commas, quotes, or line
breaks. Export files hold record data, so only administrators may create them,
and the usage guide must describe the export as it actually works.

## Constraints

- An export applies the same filters, with the same validation, as
  `GET /records`.
- Access is decided by the service, not by the admin tool's interface.
- The usage guide stays in `docs/usage.md`.

## Non-goals

- Other formats, column selection, scheduled exports, and managing earlier
  export files.

## Work

### 1. Filtered CSV export

**Intent:** Let administrators save exactly the records they filtered.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV; a field containing a comma, double quote, or newline is quoted per RFC 4180, with embedded double quotes doubled.

**Depends on:** None

### 2. Administrator-only access

**Intent:** Keep record data in export files limited to administrators.

**Done when:**

- `AC-002`: An export request from a user who is not an administrator, or from no signed-in user, is rejected by server-side authorization before any export file is written.

**Depends on:** 1

### 3. Usage guide for the export

**Intent:** Readers can learn how to use the export without reading the code.

**Done when:**

- `AC-003`: The usage guide `docs/usage.md` accurately describes how administrators export records as CSV, including who may export, the filters an export accepts, what it returns and writes, and its error responses.

**Depends on:** 1, 2
