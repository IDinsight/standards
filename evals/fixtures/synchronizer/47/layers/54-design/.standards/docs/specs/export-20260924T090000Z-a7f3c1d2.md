# Technical Design

## Context

The scope adds an administrator-only CSV export of the filtered records list
(AC-001, AC-002) and requires the usage guide to describe it (AC-003).
`parseFilter` and `RecordStore.list` implement the listing filters;
`requireAdmin` exists but no route uses it (`.standards/CONTEXT.md`).

## Decision

Add `POST /records/export`. The handler calls `requireAdmin` first, reuses
`parseFilter` and `RecordStore.list`, writes the CSV to a file in a
configurable folder, and returns the same CSV. POST because it creates a file.

## Acceptance Coverage

- `AC-001`: route, CSV format, and file location (Interfaces and Contracts).
- `AC-002`: `requireAdmin` as the handler's first step; 401 or 403 before any
  folder or file is created.
- `AC-003`: No architectural impact; Documenter updates `docs/usage.md`.

## Interfaces and Contracts

- `POST /records/export` takes the `GET /records` query filters with the same
  validation (400 for an invalid `status`, no file written).
- No user: 401 `{"error": "authentication required"}`; editor or viewer: 403
  `{"error": "forbidden"}`.
- Success: 201, `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="<file name>"`, body equal to the
  written file.
- CSV: header `id,title,owner,status,createdAt`, one row per record in id
  order, CRLF after every row; a field containing a comma, double quote, CR, or
  LF is quoted with inner double quotes doubled (RFC 4180).
- File: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC time from `now()`);
  `exportDir` defaults to `exports`, is created when missing, and is ignored by
  git.

## Technical Acceptance Criteria

- `AC-001`: exported rows equal what `GET /records` returns for the same query,
  in the same order.
- `AC-001`: every field is quoted as above, and the response body equals the
  written file.
- `AC-002`: a request with no user or a non-admin role gets 401 or 403, and no
  export folder or file is created.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces the
  earlier file. Export files are never removed.
