# Technical Design

## Context

Documentation cycle for the existing `rowtool convert` command. Current behavior
is recorded in `.standards/CONTEXT.md`; the contracts below are read from
`bin/rowtool.js`, `src/convert.js`, and `src/csv.js`, with
`test/convert.test.js` as supporting evidence. No implementation changes.

## Decision

Document the existing contracts as they stand in a single new guide,
`docs/guides/convert.md`. Where behavior is a limitation (no quoted fields), the
guide states it rather than implying support.

## Acceptance Coverage

- `AC-001`: CLI contract below, from `USAGE` and `parseArgs` in
  `bin/rowtool.js`; the `,` default comes from the `convert` and `parseCsv`
  signatures.
- `AC-002`: Output contract below, from `main` in `bin/rowtool.js`.
- `AC-003`: Row-mapping contract below, from `src/convert.js` and `src/csv.js`.

## Interfaces and Contracts

- Invocation: `rowtool convert <file.csv> [--delimiter <char>] [--out <file.json>]`.
  Each option takes the next argument as its value. Unknown options or a missing
  value print the problem and usage to standard error and exit 2.
- Output: JSON array, two-space indent, trailing newline. Written to standard
  output unless `--out` is given; with `--out`, written to that path
  (overwritten) and nothing is printed. Exit 0 on success.
- Row mapping: the first line is the header; each later line becomes one object
  keyed by header name; cells are trimmed; values are always strings; missing
  trailing fields become `""`; extra fields are dropped. The delimiter is split
  literally, so quoted fields are not supported.

## Risks and Follow-up

- There are no CLI-level tests, so output destination and exit codes rest on
  source inspection; confirm them with a command run while documenting.
