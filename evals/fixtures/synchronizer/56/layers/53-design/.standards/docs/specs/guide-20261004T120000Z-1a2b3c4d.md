# Technical Design

## Context

Documentation cycle for the existing `ledger import` command. Behavior is
established from `bin/ledger.js`, `src/import.js`, `src/parse.js`, and the tests
in `test/`, as recorded in `.standards/CONTEXT.md`. No implementation change is
planned. No project references apply.

## Decision

Document the command-line contract exactly as implemented. The guide shows the
command as `node bin/ledger.js import`, notes the `ledger` bin entry for
installed use, and states the input limitations (comma splitting, shape-only
date check, empty amount read as 0) instead of implying stricter validation.

## Interfaces and Contracts

- Invocation: `ledger import <file.csv> [--out <file.json>] [--dry-run]`. The
  first non-option argument is the file; options may appear before or after it.
  Any further non-option argument is a usage error. `--out` replaces an existing
  file.
- Input: the first non-blank line is the header; names are trimmed and compared
  in lower case. `date`, `description`, and `amount` are required; `category` is
  optional and an empty or missing value becomes `uncategorized`. Every comma
  separates columns; quoting is not supported. Values are trimmed and blank
  lines skipped. Dates must match `YYYY-MM-DD` (shape only). Amounts are parsed
  with `Number()`, so an empty amount is 0, and stored as `amountCents`, rounded
  to the nearest cent.
- Output: a summary line `<n> transactions, net <total>` with the total to two
  decimals, then a JSON array (two-space indented) of objects with `date`,
  `description`, `amountCents`, and `category`, on standard output or in the
  `--out` file. `--dry-run` prints only the summary line.
- Failures: exit 1 with `import failed: <message>` on standard error when the
  file cannot be read or a row is invalid (`missing column: <name>`,
  `line <n>: invalid date "<value>"`, `line <n>: invalid amount "<value>"`);
  line numbers count non-blank lines with the header as line 1. Exit 2 for usage
  problems: the usage line for a missing file argument or an unknown command,
  `unexpected argument: <arg>` for an extra argument. Exit 0 on success.

## Risks and Follow-up

- Invalid dates, unreadable files, and extra arguments have no existing tests;
  documentation of them rests on source inspection and manual runs.
