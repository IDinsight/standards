# Technical Design

## Context

`Catalog` caches `get(sku)` under `product:<sku>` and `list()` under
`list:all` in a `TtlCache` (see `.standards/CONTEXT.md`). `upsert` removes only
the product key.

## Decision

Add prefix invalidation to `TtlCache` and have `Catalog.upsert` invalidate every
`list:` key in addition to the product key. This keeps the cache generic and
covers future filtered lists stored under the same prefix.

## Acceptance Coverage

- `AC-001`: `TtlCache.invalidatePrefix('list:')` called from `Catalog.upsert`.
- `AC-002`: the existing `product:<sku>` delete in `Catalog.upsert`, kept
  unchanged.

## Interfaces and Contracts

- `TtlCache.invalidatePrefix(prefix)` deletes every entry whose key starts with
  `prefix` and returns the number removed.

## Technical Acceptance Criteria

- `AC-001`: no `list:` key survives a `Catalog.upsert` call.

## Build Plan

1. Add `invalidatePrefix` to `TtlCache`.
2. Call it from `Catalog.upsert`.
