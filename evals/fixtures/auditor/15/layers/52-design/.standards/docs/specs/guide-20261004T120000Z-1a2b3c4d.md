# Technical Design

## Context

Documentation cycle for the user guide `docs/usage.md`, under the scope in
`.standards/docs/scope/guide-20261004T120000Z-1a2b3c4d.md` and the project
context in `.standards/CONTEXT.md`. The contracts below are read from the
current implementation: `bin/csvsum.js`, `src/parse.js`, and
`src/summarize.js`. No project references apply.

## Decision

Document csvsum as implemented; this cycle changes no behavior. The guide's
examples read the sample files in `docs/examples/` and run from the repository
root.

## Acceptance Coverage

- `AC-001`: Option contract in `bin/csvsum.js` (`parseArgs`, strict mode):
  positional `<file>`; `--column` with short form `-c`, required;
  `--delimiter`, default `,`; `--format`, `text` (default) or `json`. Unknown
  options and missing arguments exit with status 2 and a usage line.
- `AC-002`: Output contract in `formatSummary` (`src/summarize.js`): text is
  three lines, `count N`, `sum X.XX`, and `mean X.XX` (`toFixed(2)`); json is
  `JSON.stringify` of `count`, `sum`, and `mean` without rounding. The CLI
  writes either followed by one newline.
- `AC-003`: Error contract: `summarize` skips empty cells and throws for
  non-numeric values; `bin/csvsum.js` prints `csvsum: <message>` and exits with
  status 1, including `no column named <name>` when the header lacks the
  column.

## Interfaces and Contracts

- `parseCsv(text, delimiter)` in `src/parse.js`: the first non-blank line is
  the header; blank lines are skipped; cells are split on the delimiter and
  trimmed. Quoted fields are not supported.

## Technical Acceptance Criteria

- `AC-001`: Each option name, short form, and default in the guide matches the
  `parseArgs` option table in `bin/csvsum.js`.
- `AC-002`: Each example's shown output equals the standard output of
  `node bin/csvsum.js` with the same arguments, run from the repository root.
- `AC-003`: The guide's messages and exit statuses for empty cells,
  non-numeric values, and an unknown column match `bin/csvsum.js` and
  `src/summarize.js`.

## Risks and Follow-up

- The parser does not handle quoted fields; the guide must not imply that it
  does.
