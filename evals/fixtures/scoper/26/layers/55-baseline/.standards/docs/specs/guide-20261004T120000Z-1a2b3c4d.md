# Technical Design

## Context

Documentation cycle for the support guide. Baseline: `.standards/CONTEXT.md`.
Behavior sources: `acctreport/cli.py`, `acctreport/report.py`, and
`data/ledger.csv`; `tests/test_report.py` is supporting evidence only. No
project references apply.

## Decision

The guide documents the `export` subcommand exactly as implemented and uses
`data/ledger.csv` for its example so readers can reproduce it. No behavior
changes are proposed.

## Acceptance Coverage

- `AC-001`: Invocation `python3 -m acctreport export <ledger>`; CSV is the
  default format (`acctreport/cli.py`). CSV output from `to_csv`
  (`acctreport/report.py`): header `account_id,name,balance`, one row per
  account sorted by `account_id`, balance summed from the ledger and formatted
  with two decimals, name from the account's last ledger row. For
  `data/ledger.csv` the command prints four lines: the header and three
  accounts.
- `AC-002`: No architectural impact — the audience is set by the scope; the
  only technical prerequisite is the README's Python 3 requirement and running
  from the repository root, which the AC-001 invocation already assumes.

## Interfaces and Contracts

- Command line: `export <ledger> [--format csv|json]`; output goes to standard
  output; an unknown format exits with status 2.
- Ledger input: CSV header `account_id,name,amount`; negative amounts are
  allowed and reduce the balance.
- The `--format json` output (`to_json`) is also part of the existing
  interface: an object with `count` and an `accounts` array of `account_id`,
  `name`, `balance` objects. The current scope does not ask the guide to
  document it.

## Technical Acceptance Criteria

- `AC-001`: The guide's example output is identical to the output of
  `python3 -m acctreport export data/ledger.csv` run from the repository root.

## Risks and Follow-up

- If `data/ledger.csv` changes, the guide example must be refreshed.
