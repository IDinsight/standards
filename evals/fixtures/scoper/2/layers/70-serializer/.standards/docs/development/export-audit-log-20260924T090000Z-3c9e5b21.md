## Build Steps

### DEV-001 — CSV serializer for audit entries

`Status`: `DONE` `Depends On`: `NONE`
`Acceptance`: `AC-001`

**Goal**

Serialize audit entries to the RFC 4180 CSV document the design defines.

**Affected Area**

New module `src/export/csv.js`.

**Expected Outcome**

`toCsv(entries)` returns the `timestamp,actor,action,target` header and one row
per entry in order, quoting fields that contain a comma, double quote, CR, or
LF and doubling embedded quotes, with CRLF after every line.

**Self-Check**

Ran in the project root on the working tree before commit: `node -e` importing
`src/export/csv.js` and printing `toCsv` for three sample entries, one with an
actor containing a comma and one with a target containing a double quote.
Output had the `timestamp,actor,action,target` header, CRLF line endings, and
both values quoted with the embedded quote doubled; exit 0. `npm test`: exit 0,
6 passes (no export coverage exists yet). This is a Developer sanity check, not
Tester verification.

### DEV-002 — Audit log export handler

`Status`: `PENDING` `Depends On`: `DEV-001`
`Acceptance`: `AC-001, AC-002`

**Goal**

Expose the filtered audit log as a CSV download under the view's permission.

**Affected Area**

New module `src/routes/auditExport.js`, using `src/auditLog.js` and
`src/permissions.js` unchanged.

**Expected Outcome**

`handleAuditExport(user, query, log)` returns the view's 403 response to users
who cannot view the audit log, and otherwise status 200 with the CSV headers
from the design and a body holding exactly the entries the view returns for the
same query.

**Self-Check**

Planned: `npm test`, plus an inline call of `handleAuditExport` as a member and
as an administrator with an actor filter, comparing the rows with
`handleAuditView` for the same query.
