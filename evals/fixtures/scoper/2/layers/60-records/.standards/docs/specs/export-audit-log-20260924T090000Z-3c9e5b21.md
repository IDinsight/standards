# Technical Design

## Context

The audit console backend already serves a filtered audit log view through
`handleAuditView` in `src/routes/auditView.js`: `parseFilters` and
`filterEntries` in `src/auditLog.js` implement the actor, action, and
date-range filters, and `canViewAuditLog` in `src/permissions.js` restricts the
view to administrators. Handlers return `{ status, headers, body }`. The scope
asks for a CSV download of the same filtered entries under the same permission.

## Decision

Add a separate export handler next to the view handler that reuses the view's
filter parsing, filtering, and permission check unchanged, and serializes the
result with a new CSV serializer. The export is a fixed CSV document; there is
no format parameter. Reusing the view's functions rather than copying them keeps
the export and the view from drifting apart.

## Acceptance Coverage

- `AC-001`: `toCsv` in `src/export/csv.js` and the `handleAuditExport` response
  contract below.
- `AC-002`: `handleAuditExport` calls `canViewAuditLog`, `parseFilters`, and
  `filterEntries` exactly as `handleAuditView` does.

## Components

- `src/export/csv.js` — `toCsv(entries)`: serializes audit entries; no I/O.
- `src/routes/auditExport.js` — `handleAuditExport(user, query, log)`:
  permission check, filtering, serialization.

## Interfaces and Contracts

- `handleAuditExport(user, query, log)` accepts the same `query` keys as the
  view (`actor`, `action`, `from`, `to`) and returns `{ status, headers, body }`.
- Denied: `{ status: 403, headers: {}, body: { error: 'forbidden' } }`,
  identical to the view.
- Allowed: status 200, `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="audit-log.csv"`, body from
  `toCsv`.
- CSV format: RFC 4180. Header row `timestamp,actor,action,target`; one row per
  entry in log order; fields containing a comma, double quote, CR, or LF are
  quoted with embedded quotes doubled; every line, including the last, ends
  with CRLF.
- The endpoint produces CSV only; any other query key is ignored.

## Data and Control Flow

Request query -> `canViewAuditLog` (403 on failure) -> `parseFilters` ->
`filterEntries(log.all(), filters)` -> `toCsv` -> response.

## Technical Acceptance Criteria

- `AC-001`: For any entry list, the `toCsv` output parses back under RFC 4180
  to the header row plus the same field values in the same order.
- `AC-002`: For any user and query, the export returns 403 exactly when the
  view returns 403, and otherwise contains exactly the entries the view returns
  for the same query.

## Build Plan

1. Add the CSV serializer.
2. Add the export handler wired to the existing filter and permission
   functions.

## Risks and Follow-up

- Large logs are serialized in memory, as the view already loads them;
  streaming is not required by the scope.
