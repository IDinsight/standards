# Technical Design

## Context

Search currently matches titles only and is case-sensitive (`src/search.js`).
The scope is `docs/product/search.md`. Existing callers pass only
`(records, query)`.

## Decision

Keep the `search(records, query)` signature. Normalize the query once (trim,
lower case), scan records in catalog order, and collect title hits and
summary-only hits in two lists that are concatenated. Reject an empty
normalized query by throwing a new exported `SearchError` before scanning.

## Acceptance Coverage

- `AC-001`: Case-insensitive substring match of the trimmed query against
  `title` and `summary`.
- `AC-002`: Two-group collection in catalog order; the title group comes first.
- `AC-003`: `SearchError` thrown before scanning when the trimmed query is
  empty.

## Interfaces and Contracts

- `search(records, query)` returns an array of the matching record objects.
- `SearchError` extends `Error` with `name` `SearchError`; it is exported from
  `src/search.js`.

## Technical Acceptance Criteria

- `AC-002`: A record that matches in both title and summary appears once, in
  the title group.

## Build Plan

1. Normalized matching and two-group ordering.
2. Empty-query rejection.
