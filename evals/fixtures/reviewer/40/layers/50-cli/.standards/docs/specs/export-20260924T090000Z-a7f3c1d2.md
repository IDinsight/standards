# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) that only
administrators may use through the service, enforced by server-side
authorization (AC-002), and the same export run from a shell on the service
host (AC-003). According to `.standards/CONTEXT.md`, route handlers are
synchronous functions registered on `Router` and exercised in-process;
`parseFilter` and `RecordStore.list` already implement the listing filters;
`requireAdmin` exists but no route uses it; nothing writes to disk today.
Records live in memory, seeded from `@records/seed`, and no route changes
them. Seed titles contain a comma and double quotes.

## Decision

Add `POST /records/export`. The handler authorizes with `requireAdmin` before
anything else, reuses `parseFilter` and `RecordStore.list` so an export
contains exactly what `GET /records` lists for the same query, serializes with
a new quoting function, writes the CSV to a file in a configurable export
folder, and returns the same CSV as the response body. POST is used because
the request creates a file.

For AC-003, add a command, `src/cli/export-records.ts`, run with `node`. It
uses the same `parseFilter`, `RecordStore.list` over the seed records, and
`writeExport`, so its file matches a service export with the same filters at
the same time. It does not go through the router or `requireAdmin`; shell
access to the host decides who may run it.

## Acceptance Coverage

- `AC-001`: `POST /records/export` with the listing filters, the CSV format and
  quoting rules, and the export file location (Interfaces and Contracts).
- `AC-002`: `requireAdmin` as the handler's first step; the router maps its
  `HttpError` to 401 or 403, and no folder is created and no file is written
  before it returns.
- `AC-003`: `src/cli/export-records.ts` with the listing filters and an output
  folder option, reusing the CSV format and file naming.

## Components

- `src/export.ts` (new): `csvCell`, `toCsv`, `exportFileName`, and
  `writeExport`. It knows nothing about users or requests.
- `src/routes/export.ts` (new): `registerExportRoutes(router, store, { exportDir, now })`,
  the only place the export's authorization happens.
- `src/app.ts`: new `createApp` options `exportDir` (default `exports`) and
  `now` (default: the current time), passed to `registerExportRoutes`.
- `src/cli/export-records.ts` (new): `runExportRecords(args, { records, now })`
  returning `{ code, output }`, plus an entry point used when the file is run
  directly.

## Interfaces and Contracts

- Route: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  request body is ignored.
- Authorization: administrators only. No signed-in user gives 401
  `{"error": "authentication required"}`; an editor or viewer gives 403
  `{"error": "forbidden"}` (the existing `authorize` responses).
- Invalid `status`: 400 from `parseFilter`; no file is written.
- Success: status 201; headers `content-type: text/csv; charset=utf-8` and
  `content-disposition: attachment; filename="<file name>"`; the body is
  identical to the written file.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are.
- File location: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`, using the UTC
  time returned by `now()` for the request. `exportDir` is created when
  missing and resolves against the working directory. `exports/` is listed in
  `.gitignore`.
- Command: `node src/cli/export-records.ts` with `--status`, `--owner`, and
  `--q` options (the listing filters, same `parseFilter` validation) and one
  option naming the output folder, default `exports`, created when missing.
  File name and content follow the file location and CSV format above. On
  success it prints `Wrote <n> records to <path>` (`record` when n is 1) and
  exits 0. An unknown option, a missing option value, a positional argument,
  or an invalid `status` prints the error and a usage line to standard error,
  exits 2, and creates no folder or file.

## Data and Control Flow

`Router.handle` calls the export handler: `requireAdmin(request.user)`, then
`parseFilter(request.query)`, `store.list(filter)`, `toCsv`, folder creation
and file write, and the 201 response. An `HttpError` thrown before the write
ends the request with its status and leaves the file system unchanged. The
command parses arguments with `parseArgs` from `node:util` in strict mode,
then runs the same filter, list, and write steps; any argument or filter
error returns before the write.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records `GET /records` returns for that query, in the same order.
- `AC-001`: Every field is quoted and escaped as the CSV format above
  requires, and the response body equals the written file.
- `AC-002`: A request with no user or with a non-admin role receives 401 or
  403, and no export folder or file is created.
- `AC-003`: For the same filters and time, the command writes the file name
  and content that `POST /records/export` writes.
- `AC-003`: An invalid argument or filter exits with code 2 and leaves the
  file system unchanged.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. File naming and writing.
3. Route, `createApp` options, and the `.gitignore` entry.
4. Command-line export on top of steps 1 and 2.

## Risks and Follow-up

- Two exports in the same second share a file name; the later one replaces
  the earlier file. Accepted for this internal tool.
- Export files are never removed; retention is outside this cycle.
- The command reads the seed records, not a running process's store; they
  hold the same data because no route changes records.

## Alternatives

- `GET /records/export` returning CSV without keeping a file: rejected because
  the scope keeps export files in the service for the admin tool to hand out.
