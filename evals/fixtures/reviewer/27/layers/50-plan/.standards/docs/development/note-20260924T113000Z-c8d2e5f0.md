## Build Steps

### DEV-001 — Optional internal note on tickets

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `EXPEDITED_REQUEST`

**Goal**

Tickets carry an optional `note` that staff can set when creating or updating a
ticket, using the same `optionalText` rules already applied to `assignee`.

**Affected Area**

- `src/tickets.js`: `newTicket`, `updateTicket`, `internalView`.
- `src/api.js`, `src/service.js`, `src/fields.js`: no change expected. Create
  and update are already staff-only and respond with `internalView`; customers
  read through `publicView`.

**Expected Outcome**

- `note` is trimmed; missing, `null`, or blank becomes `null`; a non-string or
  more than 500 characters is rejected with `ValidationError`, which the
  existing routes return as status 400 without storing anything.
- `updateTicket` changes `note` only when the update body contains the key;
  `null` or a blank string clears it.
- `internalView` includes `note`; `publicView` is unchanged and never includes
  it.

**Self-Check**

Planned: `npm test` in the project root for regressions, then a targeted
`node --input-type=module` run of the create, read, and update routes covering
a trimmed note, the public view, keeping and clearing the note on update, a
non-string note, and the 500-character limit.
