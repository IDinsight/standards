# Hourly Records Export to the Document Archive

## Goal

Operations keeps a copy of the records list in the company's document
archive, and today someone copies it there by hand. The service should produce
the records list as a CSV file and upload it to the archive by itself when
operations runs it on a schedule. Nobody watches the scheduled runs, so a run
that cannot store the file must end and report the failure instead of carrying
on, so that the next hourly run starts cleanly and the failure shows up in the
scheduler's alerts.

## Constraints

- Operations runs the export every hour from its scheduler with
  `pnpm --filter export archive-export`, providing `ARCHIVE_URL` and
  `ARCHIVE_TOKEN` in the environment. A non-zero exit status raises an alert.
- The archive accepts uploads as `PUT {ARCHIVE_URL}/exports/{file name}` with
  the header `authorization: Bearer {ARCHIVE_TOKEN}`. It answers 2xx when the
  file is stored, 429 when it is throttling clients, and 5xx during outages;
  any other 4xx response means it refused the request itself.
- Listing records (`GET /records`) keeps its current behavior.

## Non-goals

- Filtering the export, other file formats, and choosing columns.
- Scheduling inside the service; operations owns the schedule.
- Listing or removing files already in the archive.

## Work

### 1. Upload the records list

**Intent:** Put a current copy of every record into the archive on each run.

**Done when:**

- `AC-001`: Each run uploads one CSV file containing every record, named `records-<UTC timestamp>.csv` for the time the run started, with the header row `id,title,owner,status,createdAt` and RFC 4180 quoting of any field that contains a comma, double quote, or newline.

**Depends on:** None

### 2. Handle archive failures

**Intent:** Keep unattended runs reliable without leaving them hanging when
the archive is down or refuses the upload.

**Done when:**

- `AC-002`: When an upload attempt fails transiently (the archive cannot be reached, or answers 429 or 5xx), the run retries it; retrying is bounded, so if the archive keeps failing the run stops retrying, reports the failure, and exits with a non-zero status instead of retrying indefinitely.
- `AC-003`: When the archive refuses an upload with any other non-2xx status, the run does not retry; it reports the archive's status and exits with a non-zero status.

**Depends on:** 1

## Assumptions

- The archive replaces a file that is uploaded again under the same name.
