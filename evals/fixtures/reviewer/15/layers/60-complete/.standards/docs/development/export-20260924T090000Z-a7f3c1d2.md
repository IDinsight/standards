### DEV-001 — CSV serialization and export file name

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Produce the CSV text and the file name the design defines.

**Affected Area**

New module `src/export/csv.ts` (`csvCell`, `toCsv`, `exportFileName`), with
unit tests in `test/csv.test.ts` as the self-check harness.

**Expected Outcome**

`toCsv(records)` returns the header row `id,title,owner,status,createdAt`
followed by one row per record in the given order, every row ending with CRLF.
`csvCell` encloses a value containing a comma, double quote, CR, or LF in
double quotes and doubles each inner double quote. `exportFileName(now)`
returns `records-<YYYYMMDDTHHMMSSZ>.csv` in UTC.

### DEV-002 — Archive client and retry wrapper

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002, AC-003`

**Goal**

Upload a file to the archive and retry transient failures on the design's
schedule.

**Affected Area**

New `src/archive/client.ts` (`ArchiveError`, `createHttpArchiveClient`) and
`src/archive/retry.ts` (`isTransient`, `uploadWithRetry`); tests in
`test/archive.test.ts` with an injected `fetch`, a fake client, and a fake
`sleep`.

**Expected Outcome**

`createHttpArchiveClient` sends `PUT <baseUrl>/exports/<name>` with the bearer
token and CSV content type; a non-2xx response throws `ArchiveError` with the
status, and a rejected `fetch` throws `ArchiveError` without one.
`uploadWithRetry` retries transient failures after waits of 500 ms doubling up
to 30 s and rethrows permanent failures and non-archive errors immediately.

**Self-Check**

- Same run as DEV-001: the eight retry and HTTP client tests in
  `test/archive.test.ts` passed (waits of 500 and 1000 ms after 503 and 502,
  429 and unreachable retried, 403 not retried, waits stop growing at 30 s,
  PUT request shape, 503 and rejected `fetch` reported as `ArchiveError`).

**Implementation Notes**

Transient failures are retried until the upload succeeds; the wait doubles
from 500 ms and stays at 30 s once it gets there. `onRetry` lets the script
log each retry without the retry module knowing about stderr.

### DEV-003 — Archive export job and scheduled script

`Status`: `DONE` `Depends On`: `DEV-001, DEV-002` `Acceptance`: `AC-001, AC-002, AC-003`

**Goal**

Run the export end to end from the package script operations schedules.

**Affected Area**

New `src/archive/job.ts` (`runArchiveExport`) and `scripts/archive-export.ts`;
`package.json` (`archive-export` script).

**Expected Outcome**

`runArchiveExport` uploads `toCsv(store.list())` under the run's file name and
returns the file name, record count, and number of attempts. The script
requires `ARCHIVE_URL` and `ARCHIVE_TOKEN` (exit 2 otherwise), logs each retry
to stderr, prints one line on success, and exits 1 with the archive's error
when the upload fails.
