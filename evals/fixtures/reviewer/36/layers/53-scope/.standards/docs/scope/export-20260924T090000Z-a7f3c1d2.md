# CSV Export of Records

## Goal

Tenant administrators need to take the list they are looking at, after
filtering it by status, owner, or title text, into a spreadsheet. The service
should produce that list as a CSV file that spreadsheet programs read
correctly even when titles contain commas, quotes, or line breaks. Export
files hold customer record data, so an export must contain only the
requesting administrator's own tenant's records, and only administrators may
create one.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Tenant separation is an established rule of the service: a user sees only
  their own tenant's records, and the tenant comes from the signed-in user.
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing, downloading again, or removing previously created export files.
- Exports across tenants for support staff, and changes to the admin tool's
  front end.

## Work

### 1. Filtered CSV export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file.

**Done when:**

- `AC-001`: Administrators can export the records they currently see in the list, with the same filters applied, as CSV; a field containing a comma, double quote, or newline is quoted per RFC 4180, with embedded double quotes doubled.

**Depends on:** None

### 2. Exports stay within the tenant

**Intent:** Keep each customer organization's records out of other
organizations' export files.

**Done when:**

- `AC-002`: An export contains only records that belong to the requesting administrator's tenant, with or without filters.

**Depends on:** 1

### 3. Administrator-only access

**Intent:** Keep record data in export files limited to administrators.

**Done when:**

- `AC-003`: An export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is created.

**Depends on:** 1

## Assumptions

- Export files are kept by the service; how the admin tool offers them for
  download is outside this repository.
