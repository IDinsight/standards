# Technical Design

## Context

Documentation cycle for README.md. The relevant existing contracts are the
configuration loader in `src/config.js` and the retention rule in
`src/prune.js`, described in `.standards/CONTEXT.md`. No implementation change
is part of this cycle.

## Decision

Document the options and defaults exactly as `DEFAULTS` and `loadConfig`
define them, and the retention rule as `selectExpired` applies it. The source
is the authority for every stated value; `test/fixtures/defaults.json` and
`test/config.test.js` are supporting evidence.

## Acceptance Coverage

- `AC-001`: `loadConfig(overrides)` in `src/config.js` merges overrides over
  `DEFAULTS`. Options: `archiveDir` (non-empty string, else `TypeError`),
  `retentionDays` (positive integer number of days, else `RangeError`),
  `compress` (any value, converted to a boolean).
- `AC-002`: the default retention is `DEFAULTS.retentionDays` in
  `src/config.js`; `selectExpired` in `src/prune.js` treats an entry as
  expired when `createdAt` is earlier than `now` minus `retentionDays` × 24
  hours.

## Interfaces and Contracts

- `loadConfig(overrides = {})` returns a new object; it never mutates
  `DEFAULTS`.
- `selectExpired(entries, now, config)` takes `{ name, createdAt }` entries
  with `Date` values and returns an array of names.

## Technical Acceptance Criteria

- `AC-001`: each documented default equals the corresponding `DEFAULTS` value
  in `src/config.js`.
- `AC-002`: the documented retention equals `DEFAULTS.retentionDays` and
  describes the cutoff as `selectExpired` computes it.

## Risks and Follow-up

- Defaults are duplicated in `test/fixtures/defaults.json`; the guide should
  cite the source, not the fixture.
