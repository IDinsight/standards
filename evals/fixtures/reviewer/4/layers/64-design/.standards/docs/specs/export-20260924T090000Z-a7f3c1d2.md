# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) whose
quoting lets the existing CSV import read the file back unchanged (AC-002).
According to `.standards/CONTEXT.md`, `src/csv.js` holds `parseCsv`, an
RFC 4180 reader used only by `importRecords` in `src/import.js`;
`RecordStore.list(filter)` already applies the `status` and `owner` filters;
and `test/fixtures/records.csv` is a sample import file with a comma, double
quotes, and a line break inside quoted titles.

## Decision

Put the writer beside the reader in `src/csv.js`, so both directions of the
format live in one module and are tested against the same sample file, and add
`src/export.js` with `exportRecords(store, filter)`. `parseCsv` and
`src/import.js` do not change: the import side of the round trip is the
existing, established reader.

## Acceptance Coverage

- `AC-001`: `exportRecords` lists with `RecordStore.list(filter)` and writes the
  header and columns defined under Interfaces and Contracts.
- `AC-002`: `csvField` quoting and `formatCsv` row endings, read back by the
  unchanged `parseCsv` and `importRecords`.

## Components

- `src/csv.js`: adds `csvField(value)` and `formatCsv(rows)`; keeps
  `parseCsv(text)` as it is.
- `src/export.js` (new): `exportRecords(store, filter = {})` and
  `EXPORT_COLUMNS`.

## Interfaces and Contracts

- `exportRecords(store, filter = {})` returns the CSV text as a string; the
  caller decides where it goes. `filter` is `{ status?, owner? }`, passed to
  `RecordStore.list` unchanged.
- CSV text: no byte order mark. Header row `id,title,owner,status` (the import
  header), then one row per record in `list` order (ascending `id`). Every row,
  including the last, ends with CRLF. A field containing a comma, double quote,
  CR, or LF is enclosed in double quotes with each inner double quote doubled
  (RFC 4180); other fields are written as they are. `id` is written in decimal.
- Reader: `parseCsv` already accepts quoted fields containing commas, doubled
  quotes, and line breaks, with CRLF or LF row endings. `importRecords` keeps
  its header, validation, and error messages.

## Data and Control Flow

`exportRecords` calls `store.list(filter)`, maps each record to the four
columns, and passes the header and rows to `formatCsv`, which applies
`csvField` to every value.

## Technical Acceptance Criteria

- `AC-001`: For any filter, the exported rows are exactly the records
  `store.list(filter)` returns, in the same order, under the header row.
- `AC-002`: Fields are quoted and escaped as the CSV text contract requires,
  and every row ends with CRLF.
- `AC-002`: For records the store holds, `importRecords` on the output of
  `exportRecords` recreates them with identical field values, including titles
  that contain commas, double quotes, or line breaks.

## Build Plan

1. `csvField` and `formatCsv` in `src/csv.js`.
2. `exportRecords` in `src/export.js`, with tests against the sample file.

## Alternatives

- A separate writer module: rejected so the reader and writer of one format
  stay together and share the sample file.
