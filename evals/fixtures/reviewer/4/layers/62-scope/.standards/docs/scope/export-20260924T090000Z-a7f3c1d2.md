# CSV Export of Records

## Goal

Staff load record lists into the records tool from spreadsheet files through
the CSV import. They also need to take a filtered list back out as a CSV file,
edit it in a spreadsheet, and import it again. The export must be readable by
spreadsheet programs and by the tool's own import, even when titles contain
commas, double quotes, or line breaks.

## Constraints

- The export uses the same `status` and `owner` filters as listing records.
- The existing CSV import keeps its file format and behavior.

## Non-goals

- HTTP routes, file storage, or downloads; callers decide where the CSV goes.
- Choosing or reordering columns, and formats other than CSV.
- Merging or updating existing records on import.

## Work

### 1. Filtered export

**Intent:** Let staff take exactly the records they filtered out of the tool.

**Done when:**

- `AC-001`: An export contains exactly the records matching the given status and owner filters, ordered by id, under the header row `id,title,owner,status`.

**Depends on:** None

### 2. Files that read back correctly

**Intent:** Keep exported files usable in spreadsheets and by the tool's own
import.

**Done when:**

- `AC-002`: A field containing a comma, double quote, or line break is quoted per RFC 4180 with embedded double quotes doubled, so an exported file imports back through the existing CSV import with every field unchanged.

**Depends on:** 1

## Assumptions

- Exported files are imported into an empty store or one without the same
  ids; duplicate-id handling stays as the import defines it.
