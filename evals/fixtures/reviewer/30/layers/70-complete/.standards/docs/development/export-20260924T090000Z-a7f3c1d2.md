### DEV-003 — Transactional export run

`Status`: `DONE` `Depends On`: `DEV-001, DEV-002` `Acceptance`: `AC-001, AC-002`

**Goal**

Run an export as one database transaction.

**Affected Area**

New `src/exports/repository.js` (`pendingInvoices`, `insertRun`,
`markExported`, `ExportConflictError`) and `src/exports/service.js`
(`runExport`).

**Expected Outcome**

`runExport(db, { now })` selects the pending invoices, inserts the run, marks
each invoice with the run's id, and returns `{ runId, invoiceCount, csv }`, or
`null` when nothing is pending, all inside `db.transaction()`. Any failure,
including an invoice already marked by another run, rolls the transaction back
and is rethrown.

**Self-Check**

- `npm test` in the project root at commit `${COMMIT:Add invoice export runs}`:
  exit 0; 9 tests passed, 0 failed. No unit test drives `runExport` yet.
- Inspection of `src/exports/service.js` and `src/exports/repository.js` at
  that commit: every statement of a run goes through the `tx` handle passed
  by `db.transaction`, and the conflict check throws inside the callback.
- `npm run test:db` was not run, for the reason recorded under DEV-001.
