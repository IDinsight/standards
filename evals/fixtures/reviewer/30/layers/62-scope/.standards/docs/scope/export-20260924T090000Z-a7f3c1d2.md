# Invoice Export Runs

## Goal

Finance imports invoices into the accounting system from CSV files. The ledger
needs an export run that takes every invoice not yet exported, produces the
CSV for them, and records that they were exported, so each invoice reaches
accounting exactly once. A run that fails part-way must not leave invoices
marked as exported without a recorded run, or a recorded run without its
invoices.

## Constraints

- Invoices stay in the existing libSQL database, and the service keeps having
  no npm dependencies.
- Recording and listing invoices keep their current behavior.

## Non-goals

- Scheduling runs, delivering the CSV to the accounting system, or
  re-exporting a past run.
- Changes to invoice validation.

## Work

### 1. Export run

**Intent:** Give finance one CSV per run containing exactly the invoices that
have not reached accounting yet.

**Done when:**

- `AC-001`: An export run produces a CSV with a header row and one row per invoice that had not been exported before the run, and records those invoices as exported by that run, so a later run does not include them again.

**Depends on:** None

### 2. All-or-nothing runs

**Intent:** Keep the ledger consistent when a run fails part-way.

**Done when:**

- `AC-002`: If any step of an export run fails, the run leaves the database as it was before the run: no export run is recorded and no invoice is marked as exported.

**Depends on:** 1

## Assumptions

- Runs are started by a scheduled job outside this repository; two runs may
  occasionally overlap.
