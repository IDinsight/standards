# Streamed CSV Export

## Goal

Administrators now export record sets of more than 100,000 records. The
current export builds the whole file in memory before returning it, so the
memory it needs grows with the size of the export. The export should stay
within a fixed memory budget however many records it contains.

## Constraints

- The bound applies on the project's supported runtime, Node 22.

## Non-goals

- Changes to the CSV columns, quoting, or row order.
- Compression, paged downloads, or new export formats.
- Limits on memory used outside the export itself, such as loading records
  into a source.

## Work

### 1. Bounded-memory export

**Intent:** Keep large exports from exhausting the backend's memory.

**Done when:**

- `AC-001`: Exporting 200,000 records keeps the exporting process's peak heap growth at or below 32 MB, measured from immediately before the export starts until it finishes.

**Depends on:** None

## Assumptions

- The admin backend can consume the export as a stream of chunks.
