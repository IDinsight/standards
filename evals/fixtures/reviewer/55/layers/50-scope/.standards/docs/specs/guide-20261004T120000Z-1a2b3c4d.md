# Technical Design

## Context

Documentation cycle for the existing byte-size helpers. Project context is in
`.standards/CONTEXT.md`; no implementation change is planned.

## Decision

Document the public API of `src/bytes.js` as it stands. The module itself is
the authority for output strings and error behavior; the guide quotes what it
returns rather than restating unit rules.

## Acceptance Coverage

- `AC-001`: `formatBytes(bytes, { digits = 1 } = {})` in `src/bytes.js` is the
  source of every output string; `test/bytes.test.js` exercises representative
  values.
- `AC-002`: No architectural impact — link resolution is checked with the
  existing `npm run check:links` script (`scripts/check-links.mjs`).
- `AC-003`: Input validation in `src/bytes.js`: `formatBytes` throws
  `RangeError` for negative or non-finite numbers; `parseBytes` throws
  `SyntaxError` for unparseable text and unknown units.

## Interfaces and Contracts

- `formatBytes` and `parseBytes` are named exports of the ES module
  `src/bytes.js`.

## Technical Acceptance Criteria

- `AC-001`: Each example output shown in the guide equals the return value of
  the current `formatBytes` for the shown arguments.
- `AC-003`: The error types named in the guide are the ones the current
  functions throw.
