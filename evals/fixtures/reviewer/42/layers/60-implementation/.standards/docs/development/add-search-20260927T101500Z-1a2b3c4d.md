## Build Steps

### DEV-001 — Match records by name or email

`Status`: `DONE` `Depends On`: `NONE` `Acceptance`: `AC-001, AC-002, AC-003`

**Goal**

Filter the store's records by a case-insensitive substring of name or email,
and reject a missing or blank query.

**Affected Area**

`src/search.js` (new).

**Expected Outcome**

`searchRecords(store, params)` returns status 400 with `{ error }` when `q` is
missing or blank, and otherwise the records whose name or email contains `q`,
ignoring case, in store order.

**Self-Check**

In the project root, ran a `node --input-type=module` script over the three
records in `data/records.json` on the working tree saved for this plan:
`q=LOVE` returned Ada Lovelace only, `q=navy` returned Grace Hopper only, and
both a missing `q` and `q=%20` returned 400. Developer feedback only, not
formal verification.

### DEV-002 — Page search results

`Status`: `DONE` `Depends On`: `DEV-001` `Acceptance`: `AC-004`

**Goal**

Apply `page` and `pageSize` to the matched records and report paging fields.

**Affected Area**

`src/search.js`.

**Expected Outcome**

The 200 body is `{ items, page, pageSize, total }`; `total` counts all
matches and `items` holds the requested page.

**Self-Check**

In the project root, the same script over 30 generated records named
`Member N`: `q=member` returned 20 items with `pageSize` 20 and `total` 30;
`q=member&page=2` returned the remaining 10 items starting at id 21.
