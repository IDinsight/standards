# Record Search

## Goal

Let admin-tool clients find records by name or email without paging through
the full record list.

## Constraints

- Search results follow the paging rules documented in docs/api.md
  ("Paging"), the same rules `GET /records` already follows.
- Existing `GET /records` behavior stays unchanged.

## Non-goals

- Fuzzy matching, ranking, or matching on fields other than name and email.
- Changes to how records are stored or loaded.

## Work

### 1. Search endpoint

**Intent:** Admin tools need to locate a person quickly by part of their name
or email address.

**Done when:**

- `AC-001`: `GET /records/search?q=<text>` returns the records whose name
  contains the text, ignoring case.
- `AC-002`: The same request returns the records whose email contains the
  text, ignoring case.
- `AC-003`: A missing or blank `q` returns status 400 with an error message.
- `AC-004`: Search results are paged with `page` and `pageSize` under the
  documented paging rules: page size 20 by default, at most 50 results per
  page, and the response reports `page`, `pageSize`, and `total`.

**Depends on:** None
