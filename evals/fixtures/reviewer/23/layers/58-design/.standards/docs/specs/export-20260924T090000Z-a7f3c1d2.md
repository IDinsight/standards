# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001), restricted
to administrators by server-side authorization (AC-002). Since the correction
raised in final review, an export must also never replace an earlier export
file (AC-003). Route handlers are synchronous functions on `Router`;
`parseFilter` and `RecordStore.list` implement the listing filters. The admin
tool resends an export request when the response is slow.

## Decision

Add `POST /records/export`. The handler authorizes with `requireAdmin` before
anything else. It reuses `parseFilter` and `RecordStore.list`, serializes with
a quoting function, writes the CSV to a file in a configurable export folder,
and returns the same CSV.

Each export file is created exclusively, under a name that is free at that
moment, so an existing file is never overwritten. Because the admin tool
resends slow requests, a repeat of an export with the same filters within the
same second gets the response already produced instead of a near-identical
second file. Like every other step of the handler, that repeat lookup comes
after authorization and filter validation.

## Acceptance Coverage

- `AC-001`: the route with the listing filters, the CSV format and quoting,
  and the file location (Interfaces and Contracts).
- `AC-002`: `requireAdmin` as the handler's first step. The router maps its
  `HttpError` to 401 or 403; nothing is written and no record data is returned
  before then.
- `AC-003`: exclusive creation under the first free name for the second, and
  the same-second repeat rule.

## Components

- `src/export.ts`: `csvCell`, `toCsv`, `exportStamp`, `exportFileName`,
  `writeExport`.
- `src/routes/export.ts`: `registerExportRoutes(router, store, { exportDir, now })`,
  the only place export authorization happens. It also holds the current
  second's exports for the repeat rule.
- `src/app.ts`: the `exportDir` (default `exports`) and `now` options.

## Interfaces and Contracts

- Route: `POST /records/export`, taking the `GET /records` filters with
  `parseFilter` validation.
- Authorization: administrators only. No user gives 401
  `{"error": "authentication required"}`; an editor or viewer gives 403
  `{"error": "forbidden"}`.
- Invalid `status`: 400, and no file is written.
- Success: 201 with `content-type: text/csv; charset=utf-8` and
  `content-disposition: attachment; filename="<file name>"`; the body equals
  the file.
- CSV: header row `id,title,owner,status,createdAt`, then rows in ascending
  `id`, every row ending with CRLF. Fields containing a comma, double quote,
  CR, or LF are quoted, with inner quotes doubled.
- File location: the first export in a UTC second goes to
  `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv`; later ones in that second go
  to `-2`, `-3`, and so on. Files are created exclusively, so an existing name
  is skipped and never overwritten. `exportDir` is created when missing.
- Repeat: for an authorized administrator whose validated filters equal those
  of an export this process wrote in the same second, return that export's
  response again (201, same file name and body) and write nothing.

## Data and Control Flow

The handler runs these steps in order: `requireAdmin(request.user)`,
`parseFilter(request.query)`, the repeat lookup keyed by the second and the
parsed filter, `store.list`, `toCsv`, the exclusive write, recording the
export for repeats, and the 201 response. An `HttpError` thrown before the
write leaves the file system unchanged.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly its records, in the same order.
- `AC-001`: Every field is quoted as the CSV format requires, and the body
  equals the written file.
- `AC-002`: A request with no user or with a non-admin role gets 401 or 403
  and no record data, and no export folder or file is created.
- `AC-003`: No export modifies an existing file. Exports with different
  filters in one second produce distinct files, and a same-second repeat
  writes nothing.

## Risks and Follow-up

- The repeat lookup is held in memory per process; after a restart, a repeat
  gets the next free name.
- Export files are never removed.
