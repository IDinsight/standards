# Technical Design

## Context

The scope adds a CSV export of the filtered records list (AC-001) that only
administrators may use, enforced by server-side authorization (AC-002).
Per `.standards/CONTEXT.md`, handlers are registered on `Router` and run
in-process; `parseFilter` and `RecordStore.list` implement the listing
filters; `requireAdmin` exists.

Revision during implementation review: the user reported that production
export folders sit on a network volume that can stall, and required export
files to be written through a stream with a time limit so a stalled volume
cannot hold a request open. The CSV format, file location, and authorization
are unchanged.

## Decision

`POST /records/export` authorizes with `requireAdmin` first, reuses
`parseFilter` and `RecordStore.list`, writes the CSV to a file in the export
folder through a write stream bounded by a time limit, and returns the same
CSV as the body. `Router.handle` becomes asynchronous so a handler may return
a promise.

## Acceptance Coverage

- `AC-001`: the route with the listing filters, the CSV format and quoting,
  the file location, and the streamed write with its time limit.
- `AC-002`: `requireAdmin` as the handler's first step; 401 or 403 before any
  folder or file is created.

## Components

- `src/export.ts`: `csvCell`, `csvRows`, `toCsv`, `exportFileName`, and the
  asynchronous `writeExport`.
- `src/routes/export.ts`: `registerExportRoutes(router, store, options)`.
- `src/http/router.ts`: `handle` returns a promise and awaits the handler;
  error mapping is unchanged.
- `src/app.ts`: options `exportDir` (default `exports`), `now`,
  `exportTimeoutMs` (default 15000), and `openExportStream` (default
  `fs.createWriteStream`; tests use it to stand in for a stalled volume).

## Interfaces and Contracts

- Route: `POST /records/export` with the `GET /records` filters and the same
  `parseFilter` validation (400 for an invalid status, no file written).
- Authorization: no user gives 401 `authentication required`; editor or
  viewer gives 403 `forbidden`.
- Success: 201, `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="<file name>"`, body identical
  to the written file.
- CSV format: header `id,title,owner,status,createdAt`, rows in ascending
  `id`, every row ending with CRLF; a field containing a comma, double quote,
  CR, or LF is quoted with embedded quotes doubled (RFC 4180).
- File location: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC of
  `now()`); `exportDir` is created when missing and is gitignored.
- Export write: `writeExport(dir, records, now, { timeoutMs, open })` opens
  one stream with `open`, writes the header and rows respecting backpressure,
  ends it, and resolves with `timedOut: false` once it has finished. If the
  stream has not finished within `timeoutMs`, `writeExport` destroys the
  stream, which closes its file handle, and resolves with `timedOut: true`. If
  the stream fails, it destroys the stream and rejects. Whatever the outcome,
  the stream is finished or destroyed and no timer is left pending when
  `writeExport` settles.
- Time limit response: on `timedOut`, the handler removes any partial file
  and responds 503 `{"error": "export timed out"}`.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records it returns, in the same order.
- `AC-001`: Every field is quoted as the CSV format requires, and the body
  equals the written file.
- `AC-001`: An export whose stream does not finish within the time limit gets
  503 and leaves no export file, and its write stream is destroyed; after any
  export outcome no write stream stays open and no timer stays pending.
- `AC-002`: A request with no user or a non-admin role receives 401 or 403,
  and no export folder or file is created.

## Risks and Follow-up

- Two exports in the same second share a file name; accepted.
- A large export on a slow but working volume can hit the limit and must be
  retried.

## Alternatives

- Keeping `writeFileSync`: rejected after the user's report; a synchronous
  write cannot be bounded in time.
