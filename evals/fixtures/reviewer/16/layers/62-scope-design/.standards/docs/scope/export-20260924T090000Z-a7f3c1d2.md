# CSV Export of Records

## Goal

Administrators need to take the filtered records list into a spreadsheet as a
CSV file that reads correctly even when titles contain commas, quotes, or line
breaks. Only administrators may create export files. Administrators often
click export twice or retry after a slow response; those repeats should not
fill the export folder with duplicate files.

## Constraints

- An export applies the same filters, with the same validation, as
  `GET /records`.
- Access is decided by the service. Listing records keeps its behavior.

## Non-goals

- Other formats, column choice, scheduled exports, and removing old exports.

## Work

### 1. Filtered CSV export

**Intent:** Let administrators save exactly the records they filtered.

**Done when:**

- `AC-001`: Administrators can export the currently filtered records as CSV; a field containing a comma, double quote, or newline is quoted per RFC 4180, with embedded double quotes doubled.

**Depends on:** None

### 2. Administrator-only access

**Intent:** Keep record data in export files limited to administrators.

**Done when:**

- `AC-002`: An export request from a user who is not an administrator, or from no signed-in user, is denied by server-side authorization before any export file is created.

**Depends on:** 1

### 3. No duplicate files for repeated exports

**Intent:** Keep a double click or quick retry from producing a second copy.

**Done when:**

- `AC-003`: When the same administrator repeats an export with the same filters within 60 seconds of the first, the service returns the file the first request created and does not create another export file.

**Depends on:** 1
