# Technical Design

## Context

The scope adds a filtered CSV export (AC-001) restricted to administrators by
server-side authorization (AC-002). An export implementation from the former
expedited path is present but is active-cycle work (`.standards/CONTEXT.md`);
this design defines the contract it must meet.

## Decision

`POST /records/export` authorizes before anything else, reuses `parseFilter`
and `RecordStore.list` so an export holds exactly what `GET /records` lists
for the same query, writes the CSV to a file in a configurable folder, and
returns the same CSV.

## Acceptance Coverage

- `AC-001`: the route, CSV format, quoting rules, and file location below.
- `AC-002`: administrator-only authorization as the handler's first step;
  refused requests end with 401 or 403 before any folder or file is created.

## Interfaces and Contracts

- Route: `POST /records/export`; query parameters are the `GET /records`
  filters with the same `parseFilter` validation.
- Authorization: administrators only, decided before any other step. No
  signed-in user: 401 `{"error": "authentication required"}`; editor or
  viewer: 403 `{"error": "forbidden"}` (the existing `authorize` responses).
- Invalid `status`: 400 from `parseFilter`; no file is written.
- Success: 201, `content-type: text/csv; charset=utf-8`, a
  `content-disposition` attachment header with the file name, and a body
  identical to the written file.
- CSV: header `id,title,owner,status,createdAt`, rows in ascending `id`, CRLF
  after every row; a field containing a comma, double quote, CR, or LF is
  enclosed in double quotes with inner double quotes doubled.
- File: `<exportDir>/records-<YYYYMMDDTHHMMSSZ>.csv` (UTC); `exportDir`
  defaults to `exports` and is created when missing; `exports/` is gitignored.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the exported rows are
  exactly the records it returns, in the same order.
- `AC-001`: Every field is quoted as above, and the body equals the file.
- `AC-002`: A request with no user or with a non-admin role receives 401 or
  403, and no export folder or file is created.

## Risks and Follow-up

- Two exports in the same second share a file name; accepted for this
  internal tool.
