# Technical Design

## Context

Documentation cycle for the existing `tally` CLI. Scope:
`.standards/docs/scope/guide-20261004T120000Z-1a2b3c4d.md`. Project context:
`.standards/CONTEXT.md`. No project references apply.

## Decision

Document the CLI contract as implemented in `src/cli.js`, `src/parse.js`, and
`src/summary.js` at ${COMMIT:Add CLI tests and sample data}. One guide,
`docs/guide.md`, with sections for running tally, the input file, and options.
Examples come from real runs against a small input shown in the guide. No
behavior changes.

## Acceptance Coverage

- `AC-001`: Invocation `node bin/tally.js <file.csv> [options]` (`bin/tally.js`,
  `main` in `src/cli.js`); output format from `formatSummary` in
  `src/summary.js`; missing-file handling in `main`.
- `AC-002`: Header and row rules from `parseEntries` in `src/parse.js`; error
  reporting and exit status from `main` in `src/cli.js`.
- `AC-003`: Option parsing, accepted values, and defaults from `parseArgs` in
  `src/cli.js`; filter semantics from `filterByDate` and grouping from
  `summarize` in `src/summary.js`.

## Interfaces and Contracts

- Command line: one input file path plus options in any position. Unknown
  options, a second file argument, or a missing option value are usage errors.
- `--by`: `project` (default) or `day`. `--from`, `--to`: `YYYY-MM-DD`,
  compared as strings, both inclusive; unset means no bound.
- Input: header must name `date`, `project`, `hours` (case-insensitive, any
  order); extra columns ignored; blank lines skipped; fields split on commas
  with no quoting. Row errors report the line number in the file.
- Output: one row per key sorted ascending, key padded to the longest key (at
  least 5 characters), two spaces, hours with two decimals right-aligned in 7
  characters; final `TOTAL` row.
- Errors: `tally: <message>` plus the usage line on stderr, exit 2; a missing
  input file prints `tally: cannot read <path>`, exit 1.

## Technical Acceptance Criteria

- `AC-001`: The guide's example output is byte-identical to `node bin/tally.js`
  on the guide's example input.
- `AC-002`: Column, date, hours, and error descriptions agree with
  `parseEntries` and `main`.
- `AC-003`: Each option's values and unset behavior agree with `parseArgs` and
  `filterByDate`, including that `--from` and `--to` are inclusive.

## Risks and Follow-up

- Quoted CSV fields are not supported; the guide must say values cannot contain
  commas rather than implying general CSV support.
