# Technical Design

## Context

The scope bounds exports with a timeout (AC-001) without changing successful
output (AC-002) or imports (AC-003). Per `.standards/CONTEXT.md`, import and
export both move data through `transfer(source, destination)` in
`src/io/transfer.js`, a wrapper over `pipeline` whose error path destroys both
streams.

## Decision

Add an optional `timeoutMs` to the shared `transfer` helper. `exportRecords`
passes its own timeout, 30 000 ms unless the caller gives one;
`importRecords` keeps calling `transfer` without one. Keeping the timeout in
`transfer` puts timeout teardown next to the existing pipeline error handling.

## Acceptance Coverage

- `AC-001`: `transfer(source, destination, { timeoutMs })` and
  `TransferTimeoutError`; `exportRecords` `timeoutMs` option with
  `DEFAULT_EXPORT_TIMEOUT_MS`.
- `AC-002`: CSV serialization in `src/csv.js` and the export line generator
  are unchanged; the timeout only bounds the transfer.
- `AC-003`: `importRecords` is unchanged and calls `transfer` without
  `timeoutMs`; the no-timeout path of `transfer` remains a plain `pipeline`.

## Components

- `src/io/transfer.js`: timeout option and `TransferTimeoutError`.
- `src/export.js`: `timeoutMs` option, `DEFAULT_EXPORT_TIMEOUT_MS`, and a
  re-export of `TransferTimeoutError`.

## Interfaces and Contracts

- `transfer(source, destination, { timeoutMs = 0 } = {})`: with
  `timeoutMs > 0`, if the pipeline has not finished within `timeoutMs`, reject
  with `TransferTimeoutError` (`name` `TransferTimeoutError`, `code`
  `ETRANSFERTIMEOUT`, `timeoutMs`) and destroy both streams, as the existing
  error path does, so no file handle or source iterator stays open and no data
  is written after the rejection. Clear the timer as soon as the transfer
  settles. Without a positive `timeoutMs`, behave exactly as today.
- `exportRecords(store, destination, { timeoutMs = DEFAULT_EXPORT_TIMEOUT_MS } = {})`:
  resolves with the record count as today; rejects with
  `TransferTimeoutError` on timeout. `DEFAULT_EXPORT_TIMEOUT_MS` is `30000`.
- `importRecords(source, store)`: signature and behavior unchanged.

## Data and Control Flow

`exportRecords` builds the CSV line source, opens the destination, and awaits
`transfer` with its timeout. A timeout ends the transfer, tears down both
streams, and surfaces `TransferTimeoutError` to the caller.

## Technical Acceptance Criteria

- `AC-001`: An export to a destination that stops acknowledging writes rejects
  with `TransferTimeoutError` carrying the timeout, at roughly the timeout.
- `AC-001`: When the timeout fires, both the source and the destination
  stream are destroyed; when a transfer settles in time, its timer is cleared
  so it does not keep the process alive.
- `AC-002`: A successful export, with or without an explicit timeout, writes
  CSV identical to the pre-change output.
- `AC-003`: `importRecords` results and errors are unchanged, with no time
  limit.

## Build Plan

1. Timeout option and error in `transfer`.
2. Export option and default.

## Risks and Follow-up

- A timed-out export to a file path can leave a partial file; removing it is
  a scope non-goal.

## Alternatives

- A timeout only inside `exportRecords`: rejected because stream teardown
  belongs with the pipeline handling in `transfer`.
