# Technical Design

## Context

The scope adds a filtered CSV export that administrators create (AC-001) and
that can be downloaded through a URL (AC-002). According to
`.standards/CONTEXT.md`, route handlers are synchronous functions registered
on `Router`, which matches exact paths only; `parseFilter` and
`RecordStore.list` already implement the listing filters; `requireAdmin`
exists but no route uses it; nothing writes to disk today. Seed titles contain
a comma and double quotes.

## Decision

Add two routes. `POST /records/export` authorizes with `requireAdmin` before
anything else, reuses `parseFilter` and `RecordStore.list` so an export holds
exactly what `GET /records` lists for the same query, writes the CSV to a file
named by a random token, and returns the download URL.
`GET /exports/download?token=<token>` returns the stored file. The token is a
query parameter because `Router` has no path parameters.

## Acceptance Coverage

- `AC-001`: `requireAdmin` as the creation handler's first step (401 or 403,
  no folder or file written); export files are kept only in the export folder,
  no route lists them, and each is addressed by an unguessable 128-bit token
  that is returned only in the creating administrator's response. CSV format
  and filters as in Interfaces and Contracts.
- `AC-002`: `GET /exports/download` returns the stored CSV for a valid token
  and does not require a signed-in user.

## Components

- `src/export.ts` (new): `csvCell`, `toCsv`, `newExportToken`,
  `isExportToken`, `writeExport`, and `readExport`. It knows nothing about
  users or requests.
- `src/routes/export.ts` (new):
  `registerExportRoutes(router, store, { exportDir, newToken })` registering
  both routes.
- `src/app.ts`: new `createApp` options `exportDir` (default `exports`) and
  `newToken` (default `newExportToken`), passed to `registerExportRoutes`.

## Interfaces and Contracts

- Create: `POST /records/export`. Query parameters are the `GET /records`
  filters (`status`, `owner`, `q`) with the same `parseFilter` validation; any
  body is ignored. Administrators only: no signed-in user gives 401
  `{"error": "authentication required"}`; an editor or viewer gives 403
  `{"error": "forbidden"}`. Invalid `status` gives 400; no file is written.
  Success: 201 JSON `{"count": <rows>, "url": "/exports/download?token=<token>"}`.
- Download: `GET /exports/download?token=<token>`. No signed-in user is
  required. A token that is not 32 lowercase hex characters, or that names no
  stored export, gives 404 `{"error": "export not found"}`. Success: 200 with
  `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment; filename="records.csv"`, and the stored
  file as the body.
- CSV format: UTF-8 without a byte order mark. Header row
  `id,title,owner,status,createdAt`, then one row per record in
  `RecordStore.list` order (ascending `id`). Every row, including the last,
  ends with CRLF. A field that contains a comma, a double quote, CR, or LF is
  enclosed in double quotes and each double quote inside it is doubled
  (RFC 4180); other fields are written as they are.
- Token and storage: 16 bytes from `node:crypto` `randomBytes`, hex encoded.
  The file is `<exportDir>/<token>.csv`; `exportDir` is created when missing
  and resolves against the working directory when relative. `exports/` is
  listed in `.gitignore`.

## Data and Control Flow

Create: `requireAdmin(request.user)`, `parseFilter(request.query)`,
`store.list(filter)`, `newToken()`, `writeExport`, 201 response. An
`HttpError` thrown before the write leaves the file system unchanged.
Download: validate the token, read `<exportDir>/<token>.csv`, return it or
404.

## Technical Acceptance Criteria

- `AC-001`: For any query `GET /records` accepts, the export's rows are
  exactly the records `GET /records` returns for that query, in the same
  order, quoted and escaped as the CSV format requires.
- `AC-001`: A creation request with no user or a non-admin role receives 401
  or 403, and no export folder or file is created.
- `AC-001`: Tokens are 128-bit random values; no route lists exports or
  returns a token other than the creation response.
- `AC-002`: A download request with a valid token returns 200 and the stored
  CSV whether or not a user is signed in; a malformed or unknown token gets
  404.

## Build Plan

1. Serialization: `csvCell` and `toCsv`.
2. Tokens and file storage.
3. Routes, `createApp` options, and the `.gitignore` entry.

## Risks and Follow-up

- Download URLs do not expire and export files are never removed; both are
  non-goals for this cycle.

## Alternatives

- Signed, expiring URLs: rejected because expiring exports is a non-goal and
  would need a secret-management decision this project has not made.
