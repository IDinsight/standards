## Build Steps

### DEV-001 — CSV serialization with RFC 4180 quoting

`Status`: `PENDING` `Depends On`: `NONE` `Acceptance`: `AC-001`

**Goal**

Turn a list of records into the CSV text the design defines.

**Affected Area**

New module `src/export.ts` (`csvCell`, `toCsv`), with unit tests in
`test/export.test.ts` as the self-check harness.

**Expected Outcome**

`toCsv(records)` returns the header row `id,title,owner,status,createdAt`
followed by one row per record in the given order, every row ending with CRLF.
`csvCell` encloses a value that contains a comma, double quote, CR, or LF in
double quotes and doubles each double quote inside it.

**Self-Check**

`pnpm --filter export test` in the project root.

### DEV-002 — Export tokens and file storage

`Status`: `PENDING` `Depends On`: `DEV-001` `Acceptance`: `AC-001, AC-002`

**Goal**

Store each export under a random token and read it back by token.

**Affected Area**

`src/export.ts` (`newExportToken`, `isExportToken`, `writeExport`,
`readExport`); `.gitignore`.

**Expected Outcome**

`newExportToken()` returns 32 lowercase hex characters from 16 random bytes.
`writeExport(dir, records, token)` creates `dir` when missing and writes
`<token>.csv`. `readExport(dir, token)` returns the stored CSV, or null for a
malformed or unknown token. `exports/` is ignored by git.

**Self-Check**

`pnpm --filter export test` in the project root.

### DEV-003 — Export creation and download routes

`Status`: `PENDING` `Depends On`: `DEV-002` `Acceptance`: `AC-001, AC-002`

**Goal**

Expose export creation and download through the app as designed.

**Affected Area**

New `src/routes/export.ts` (`registerExportRoutes`); `src/app.ts`
(`exportDir` and `newToken` options, route registration);
`test/export-routes.test.ts` as the self-check harness.

**Expected Outcome**

`POST /records/export` calls `requireAdmin` first, applies `parseFilter`,
writes the export, and returns 201 JSON with `count` and the download `url`.
`GET /exports/download?token=<token>` returns the stored CSV with the design's
headers, without requiring a signed-in user, and 404 for a malformed or
unknown token. `GET /records` is unchanged.

**Self-Check**

`pnpm --filter export test`; inspect the creation handler's statement order.
