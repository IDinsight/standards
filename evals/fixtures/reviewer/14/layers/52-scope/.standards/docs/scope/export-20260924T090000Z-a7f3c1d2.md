# CSV Export of Records

## Goal

Administrators of the records admin tool need to take the list they are
looking at, after filtering it by status, owner, or title text, into a
spreadsheet, and to hand the resulting file on to the people who need it. The
service should produce the filtered list as a CSV file that spreadsheet
programs read correctly and keep it available for download after it is
created.

## Constraints

- An export applies the same filters, with the same validation, as listing
  records (`GET /records`).
- Access is decided by the service, not by the admin tool's user interface.
- Listing records keeps its current behavior.

## Non-goals

- Formats other than CSV, choosing or reordering columns, and scheduled or
  emailed exports.
- Listing, expiring, or removing previously created exports.
- Changes to the admin tool's front end.

## Work

### 1. Private filtered export

**Intent:** Let administrators save exactly the records they filtered as a
CSV file without exposing record data outside the admin tool.

**Done when:**

- `AC-001`: An administrator can export the currently filtered records as a CSV file, and the export stays private: no one other than a signed-in administrator can create it or download its contents.

**Depends on:** None

### 2. Download link

**Intent:** Let an export be handed on by sharing a link instead of passing
files around.

**Done when:**

- `AC-002`: Each export has a public download URL, and anyone who has that URL can download the CSV file without signing in.

**Depends on:** 1

## Assumptions

- How the admin tool presents the download URL to the administrator is
  outside this repository.
