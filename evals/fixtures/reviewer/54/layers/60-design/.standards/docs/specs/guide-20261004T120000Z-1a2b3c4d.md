# Technical Design

## Context

Documentation cycle for the existing summarize command. Baseline from
`.standards/CONTEXT.md`; behavior below was read from `bin/summarize.js`,
`src/csv.js`, and `src/summarize.js` at commit
`${COMMIT:Add summarize CLI for CSV columns}`. No project references apply.
No implementation changes are planned.

## Decision

One page, `docs/guide.md`, ordered: running the command, input format, what
gets counted, reading the output, examples, exit codes. The contracts below are
the facts the guide must state; anything not listed here is not promised.

## Acceptance Coverage

- `AC-001`: Command line contract under Interfaces and Contracts, from
  `parseArgs` in `bin/summarize.js`.
- `AC-002`: Input contract, from `parseCsv` in `src/csv.js`.
- `AC-003`: Summary contract, from `summarize` in `src/summarize.js`.
- `AC-004`: Output contract, from the output branch of `bin/summarize.js`.
- `AC-005`: Exit contract, from the `process.exit` calls in `bin/summarize.js`
  and Node's handling of the uncaught `readFileSync` error.
- `AC-006`: `examples/sales.csv`; the expected outputs follow from the input and
  summary contracts and are asserted for `amount` (text) and `units` (JSON) in
  `test/cli.test.js`.
- `AC-007`: No architectural impact — a README prose link owned by Documenter.

## Interfaces and Contracts

- Command line: `node bin/summarize.js <file> --column <name> [--format text|json]`.
  The first argument that is not an option value is the file. `--column` and
  the file are required; `--format` defaults to `text`. Arguments may come in
  any order. A second positional argument, a missing option value, or a format
  other than `text`/`json` is a usage error.
- Input: lines that are empty or whitespace-only are dropped; the first
  remaining line is the header. Every line is split on every comma (no quote
  handling) and each cell is trimmed. Missing trailing cells become empty
  strings; cells past the header are ignored. The column name must equal a
  trimmed header cell exactly (case-sensitive).
- Summary: a cell counts when `Number(cell)` is finite; empty and non-numeric
  cells increment `skipped`. Fields in order: `count`, `skipped`, `sum`, `min`,
  `max`, `mean`. `sum` and `mean` are rounded with `Math.round(n * 100) / 100`;
  `min` and `max` are not rounded. With no numeric cells: `count` 0, `sum` 0,
  and `min`, `max`, `mean` null.
- Output: text prints `field: value` per line in field order with null shown as
  `-`; JSON prints `JSON.stringify(result)` on one line.
- Exit: 0 on success; 1 with the usage line
  `Usage: summarize <file.csv> --column <name> [--format text|json]` on
  standard error; 2 with `Column not found: <name>` when the column is not in
  the header; an unreadable file is not caught, so Node prints the error (for
  example `ENOENT`) and the process exits 1.

## Technical Acceptance Criteria

- `AC-001`: The guide names the file argument, `--column`, and `--format` with
  default `text`, and states which combinations are usage errors.
- `AC-002`: Each input limit stated in the guide matches the input contract,
  including the absence of quoted-field support.
- `AC-003`: Rounding is stated for `sum` and `mean` only.
- `AC-004`: The no-values case is described as `-` in text and `null` in JSON.
- `AC-005`: Exit codes 0, 1 (usage error and unreadable file), and 2 are listed
  with their messages.
- `AC-006`: Every example output block equals the command's actual output.

## Risks and Follow-up

- The guide must not imply that quoted fields or file errors are handled
  gracefully; both are existing behavior, not documentation work to fix.
